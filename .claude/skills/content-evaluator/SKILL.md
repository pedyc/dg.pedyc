description: 评估笔记在知识库中的健康度和地位，提供 status 流转建议，识别孤立/过时笔记
argument-hint: <笔记路径或 "all"（评估全库）>
allowed-tools: Glob,Read,Grep
---

## 概述

content-evaluator 评估笔记在知识库中的健康度，基于以下核心维度：

| 维度 | 评估内容 | 权重 |
|:---|:---|:---|
| 新鲜度 | date-modified 距今时间 | 20% |
| 连接度 | 入链数、出链数、孤立风险 | 40% |
| 活跃度 | 引用频率、编辑频率 | 20% |
| 完整性 | 模板章节是否齐全 | 20% |

**与 content-verifier 的关系**：
- content-verifier：单篇笔记内容质量（对不对、完不完整）
- content-evaluator：笔记在知识库中的地位（值不值维护、应该什么状态）

---

## 使用示例

```
/content-evaluator content/40-RESOURCES/Temporal API.md
/content-evaluator content/40-RESOURCES/
/content-evaluator all
```

## 评估维度详解

### D1: 新鲜度（Freshness）

**评分标准**（满分 10）：

| date-modified 距今 | 得分 | 说明 |
|:---|:---:|:---|
| < 1 个月 | 10 | 🟢 最新 |
| 1-3 个月 | 8 | 🟢 良好 |
| 3-6 个月 | 6 | 🟡 可更新 |
| 6-12 个月 | 4 | 🟠 建议检查 |
| > 1 年 | 2 | 🔴 考虑归档 |

**版本时效性检查**（针对 roadmap/concept）：
- 笔记提及的版本是否已过时
- 如「ES2026 是最新版本」但当前已是 ES2027 → ⚠️ 过时

---

### D2: 连接度（Connectivity）

**评分标准**（满分 10）：

| 入链数 | 出链数 | 得分 | 说明 |
|:---:|:---:|:---:|:---|
| > 5 | > 3 | 10 | 🟢 核心节点 |
| 3-5 | 2-3 | 7 | 🟢 正常 |
| 1-2 | 1-2 | 5 | 🟡 边缘 |
| 1 | 0 | 3 | 🟠 孤立风险 |
| 0 | 0 | 1 | 🔴 孤立笔记 |

**孤立风险判定**：
- 入链 = 0 且 非 atomic → 孤立
- 入链 = 0 且 是 atomic → 检查内容是否有价值

---

### D3: 活跃度（Activity）

**评分标准**（满分 10）：

基于近 30 天的编辑频率和引用频率综合评估。

| 活跃指标 | 得分 | 说明 |
|:---|:---:|:---|
| 近 30 天有编辑 或 被引用 > 3 | 10 | 🟢 活跃 |
| 近 90 天有编辑 或 被引用 1-3 | 6 | 🟡 一般 |
| > 6 个月无编辑 且 被引用 = 0 | 2 | 🔴 不活跃 |

---

### D4: 完整性（Completeness）

**基础模板检查**（满分 10）：

检查必要章节是否齐全（详见 content-verifier 的 L1 检查）。

| 缺失章节数 | 扣分 | 得分 |
|:---:|:---:|:---|
| 0 | 0 | 10 |
| 1 | 2 | 8 |
| 2 | 4 | 6 |
| 3 | 6 | 4 |
| > 3 | 8 | 2 |

---

## 综合评分

```
新鲜度: X/10  (20%)
连接度: X/10  (40%)
活跃度: X/10  (20%)
完整性: X/10  (20%)
--------------------
总分: XX/100
```

**评级阈值**：

| 总分 | 评级 | 说明 |
|:---:|:---:|:---|
| 80-100 | 🟢 A | 优秀，知识库核心资产 |
| 60-79 | 🟡 B | 良好，维持现状 |
| 40-59 | 🟠 C | 一般，建议优化 |
| 20-39 | 🔴 D | 较差，考虑归档 |
| 0-19 | ⚫ F | 严重问题，需要处理 |

## Status 流转建议

基于本库指南的归档决策树：

### 决策流程

```
评估总分 + 孤立风险 + 新鲜度
         │
         ▼
    ┌─────────────────────────────────────────┐
    │ 1. atomic 类型？                         │
    │    └── 是 → 永不归档，仅标记 status        │
    └─────────────────────────────────────────┘
         │ 否
         ▼
    ┌─────────────────────────────────────────┐
    │ 2. 入链 = 0？                           │
    │    └── 是 → 检查是否有保留价值             │
    │         └── 无 → 移入 50-ARCHIVE/        │
    │         └── 有 → status: archived        │
    └─────────────────────────────────────────┘
         │ 否
         ▼
    ┌─────────────────────────────────────────┐
    │ 3. 版本已更新但笔记未更新？               │
    │    └── 是 → status: archived             │
    │    └── 否 → 维持当前 status               │
    └─────────────────────────────────────────┘
```

### 建议优先级

| 当前 Status | 触发条件 | 建议 |
|:---|:---|:---|
| fleeting | 长期未加工（>3个月） | → 删除或归档 |
| cultivating | 入链>3 + 持续更新 | → active |
| cultivating | 长期无进展（>6个月） | → archived |
| active | 被替代/版本过时 | → completed/archived |
| 任意 | atomic 类型 | → 不归档 |

## 注意事项

1. **atomic 永不归档**：洞察是资产，无论连接度高低都保留
2. **孤立 ≠ 删除**：孤立笔记移入 50-ARCHIVE/，不删除
3. **与 content-verifier 互补**：先评估（决定是否维护），再核查（保证内容质量）
4. **判断主观性**：评估结果仅供参考，最终决策由用户决定
5. **批量评估较慢**：全库评估可能需要较长时间，按目录评估更快
