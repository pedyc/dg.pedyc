## 使用示例

```
/content-verifier content/40-RESOURCES/XSS.md
/content-verifier content/20-AREAS/A-前端/Vue.md
```

---

## 核查维度

统一核查以下4个维度：

| 维度 | 检查内容 |
|:---|:---|
| 模板完整 | 是否包含该类型的所有必要章节 |
| 关键领域覆盖 | 核心概念是否覆盖（动态检查） |
| 知识覆盖 | 已移除（检查模板完整即可） |
| 事实核查 | 待核实标记、不确定表述、理论正确性 |

---

## 核查流程

### Step 1: 确定笔记类型

根据 `content-type` 属性确定检查重点：

| content-type | 知识网络章节 | 检查重点 |
|:---|:---|:---|
| area | 关键领域 | 核心概念覆盖 |
| concept | 知识图谱 | 核心命题→关联概念 |
| term | 知识网络 | 术语定义 |
| atomic | 关联 | 观点→论据 |
| comparison | 关联 | 维度完整性 |
| question | 关联 | 探索路径 |
| sop | 关联 | 步骤完整性 |

### Step 2: 模板完整性检查

根据笔记类型，检查是否包含必要章节：

| content-type | 必要章节 |
|:---|:---|
| area | 领域定义、长期目标、关键领域、知识网络、FAQ、领域健康度 |
| concept | 核心命题、运行机制、应用场景、知识图谱、参考延伸 |
| term | 定义、核心特点、应用、相关概念 |
| moc | 分类链接列表（灵活结构，不强制章节） |
| atomic | 定义、论据/示例 |
| comparison | 维度列表、对比表格、总结 |
| question | 问题描述、探索路径、相关概念 |
| sop | 步骤列表、适用场景、注意事项 |
| record | 时间线、背景、影响、引申 |
| article | 引言、主体、总结、相关阅读 |

### Step 3: 关键领域检查（仅 area）

**核心逻辑**：
1. 读取 area 笔记，提取笔记标题和"关键领域"章节中已链接的概念
2. **WebSearch 搜索**：搜索 "{领域} 核心知识" 或 "{领域} 必须掌握的概念"，收集搜索结果中的关键概念
3. 本地搜索：Glob 搜索知识库中已存在的相关笔记
4. **对比分析**：
   - 已链接 + 本地存在 = ✓ 已覆盖
   - 已链接 + 本地不存在 = 该知识尚未掌握（正常现象）
   - 搜索到 + 本地存在 + 未链接 = ○ 遗漏的关键领域
   - 搜索到 + 本地不存在 = 待创建的新领域

### Step 4: 事实核查

事实核查检查笔记中的**事实错误**和**逻辑错误**：

**1. 客观事实错误**
- 数值错误（如"地球人口60亿"应为80亿+）
- 概念定义错误（如"JavaScript是编译型语言"错误）
- 常识错误（如"光速是30万km/s"正确，但其他数值错误）

**2. 逻辑/因果错误**
- 错误因果（如"因为A，所以B"但实际无因果关系）
- 错误类比（如"A像B，所以A=B"）
- 错误推断（如"数据显示X增长，结论是Y导致"但缺乏证据）

**3. 技术事实错误**
- API/方法参数错误
- 版本特性错误
- 原理描述错误

**注意**：
- 不检查"可能、大概"等不确定表述（写作风格问题）
- 不检查"待核实"标记（用户自行判断）
- 重点关注客观可验证的错误

## 注意事项

1. **不检查 WikiLink 断链**：断链说明知识点尚未掌握，是有意义的知识缺口，不代表该知识没用
2. **重点关注不确定内容**：不是逐字检查，对不确定内容标记 `{{待核实}}`
3. **事实核查为主**：主要确保内容正确性，而非链接数量
