## 目标

不学会怎样：`lint-staged` 配了规则但 hook 没装，`npm test` 在 CI 里跑但没设成必过——两种「有配置、无门」，出了事才发现拦不住。另一种是门都装好了，但一次改动和三个人的提交缠在一起，想撤它得连别人一起撤。

本段装 ①（切改动）与 ③（过门）两环。**提交门不依赖产物**：它挂在源码上，所以可以和构建并行，甚至更早。把它安排成「等构建好了再加」，会一直没加——这是排序上最容易犯的错。

读物清单在 [[前端工程学习专项#读什么]]，本页不重复。

## 自测

答不出就是没学：

1. ESLint 与 `tsc` 各查什么，交集在哪，为什么两个都要？
2. 钩子为什么挂 `pre-commit` 而不是 `pre-push`？
3. 提交前那道门为什么不跑 E2E？
4. 现在把你这次改动单独 revert，会连带撤掉谁的提交？怎么改才能只撤自己这份？
5. `--no-verify` 绕过一次，留下痕迹了吗？在哪看？

## 要留下的东西

- [ ] 按 [[通过husky+lint-staged进行代码质量防护]] 装提交前门，故意提交一个 lint 错，留下被拒的那段输出
- [ ] 用 `--no-verify` 绕过一次，然后在 `git log` / 流水线记录里指出「绕过这件事在哪一步能看见」——看不见就是没有记录
- [ ] 补最小样本：[[单元测试]] 一条用 Vitest，[[Playwright]] 一条 E2E
- [ ] 流水线串 `build` + `test` 并设为必过检查——只跑不设，等于没门

## 外部真值

[Conventional Commits](https://www.conventionalcommits.org/) 提交语义 · [Git: reset vs revert](https://git-scm.com/docs/git-revert) 撤销的两种语义：改写历史与追加一次反向提交
