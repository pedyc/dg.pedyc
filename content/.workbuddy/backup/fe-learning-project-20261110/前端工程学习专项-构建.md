## 目标

不学会怎样：把「配了 Vite」当成「懂构建」——产物名里的哈希、什么能 tree-shake、dev 与 build 差在哪，三条全靠背。

这一段不是链上的某道门，是**产物那一环的前置**：没有产物，后面的质量门与「回滚 = 切指针」都无从谈起。所以顺序上它排第一，但理由不是「最重要」，而是「后面两步都得踩在它上面」。

## 读什么

[[前端构建与打包]] → [[模块化与组件化开发]] → [[Vite]] → [[Webpack]] → [[前端构建工具对比]] → [[Tree Shaking]]

**入场券**：建空仓库，跑通 `vite dev` 与 `vite build` 各一次，两条命令的输出贴进当天的 memory。没走这步，后面全是读，没有落点。先读 [[模块化与组件化开发]] 再写那条 atomic「dev 与 build 在哪分岔」；读之前写，只会把结论背下来。

> [[前端构建工具对比]] 是旧写法：`para` / `related` / `zettel` 三个已废除字段、正文四个死链。读它跳过死链，改它不属于本专项——它是这条链上唯一的负面样本，顺手改掉就看不见「旧写法长什么样」了。

## 自测

答不出就是没学：

1. 同一句 `import`，在 CJS 下为什么 tree-shake 不掉？
2. dev 下浏览器为这一个组件发几个请求，build 之后发几个，中间差的那一步是谁做的？
3. 产物名里的 `a1b2c3` 是谁算的，为什么回滚要靠它？

## 决定项

| 决定项 | 取值 | 为什么是这个 |
|:--|:--|:--|
| 包管理器 | pnpm，`packageManager` 锁版本 | `pnpm-lock.yaml` 是「同一 commit 两处构建一致」的证据，不是偏好 |
| Node | LTS，`.nvmrc` 固定 | 版本漂移是「本地能跑 CI 不能跑」的第一成因 |
| 构建器 | Vite 跑主链路，Webpack 只作对照 | 两套都配会把「讲得出」降级成配置练习 |

三项换成别的工具都不影响判据，只有「锁得住」与「只有一套主链路」这两点不能换。
