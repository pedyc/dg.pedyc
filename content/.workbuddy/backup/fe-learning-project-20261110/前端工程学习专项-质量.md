## 目标

不学会怎样：`lint-staged` 配了规则但 hook 没装，`npm test` 在 CI 里跑但没设成必过——两种「有配置、无门」，出了事才发现拦不住。

这一段装的是链上最便宜的两道门。**提交门不依赖产物**：它挂在源码上，所以可以和构建并行，甚至更早。

## 读什么

[[前端工程化工具]] 的代码质量节 → [[ESLint]] → [[Prettier]] → [[Git Hooks]] → [[Husky]] → [[通过husky+lint-staged进行代码质量防护]] → [[单元测试]] → [[Vitest]] → [[Playwright]]

> 「没有产物就没有质量门」只对合并门和产物那一环成立。把它当通则，提交门就会被安排成「等构建好了再加」，然后一直没加——这是排序上最容易犯的错。

## 自测

答不出就是没学：

1. ESLint 与 `tsc` 各查什么，交集在哪，为什么两个都要？
2. 钩子为什么挂 `pre-commit` 而不是 `pre-push`？
3. 提交前那道门为什么不跑 E2E？

## 要留下的东西

- [ ] 按 [[通过husky+lint-staged进行代码质量防护]] 装提交前门，故意提交一个 lint 错，留下被拒的那段输出
- [ ] 补最小样本：[[单元测试]] 一条用 Vitest，[[Playwright]] 一条 E2E
- [ ] 流水线串 `build` + `test` 并设为必过检查——只跑不设，等于没门
