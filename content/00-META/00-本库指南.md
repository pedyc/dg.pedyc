> [!hint]
> 本库设计原则：Less is more.
> 本库方法论：PARA 笔记法 + 卡片盒笔记法
> 本库工作流：捕获 → 加工 → 内化 → 行动

---

## 核心理念

本库是一个**个人数字花园**，基于以下原则构建：

1. **PARA 行动导向**：项目（Project）→ 领域（Area）→ 资源（Resource）→ 归档（Archive）
2. **卡片盒内化**：闪念 → 文献 → 永久笔记
3. **物理位置解耦**：目录只管存放位置，元数据决定模板和筛选

---

## 目录结构

```
content/
├── 00-META/           # 系统元数据（本目录）
├── 10-PROJECTS/       # 项目（有明确目标/截止日期）
├── 20-AREAS/          # 领域（需持续关注的范围）
├── 30-ZETTELCASTEN/   # 原创笔记（已内化的知识）
├── 40-RESOURCES/       # 外部资源（剪藏网页等）
├── 50-ARCHIVE/        # 归档（已完成/过时的内容）
├── 90-DIARY/          # 日记（时间序列记录）
└── 99-ASSETS/         # 额外资源（插件配置、附件等）
```

| 目录 | 存放内容 | 说明 |
|------|----------|------|
| 00-META | 系统元数据 | 规范、架构、索引 |
| 10-PROJECTS | 项目笔记 | 有明确目标和截止日期 |
| 20-AREAS | 领域笔记 + MOC | 需要持续关注的范围 |
| 30-ZETTELCASTEN | 原创笔记 | atomic, concept, term, comparison, sop, moc |
| 40-RESOURCES | 外部资源 | 剪藏网页等，无需 content-type |
| 50-ARCHIVE | 归档内容 | 已完成的项目、过时的资源 |
| 90-DIARY | 日记 | 时间序列记录，无需 content-type |
| 99-ASSETS | 额外资源 | 插件配置、图片等 |

## 元数据规范

### 通用字段

| 字段 | 用途 | 可选值 | 备注 |
|------|------|--------|------|
| uid | 唯一标识 | 时间戳 | 自动生成 |
| title | 笔记标题 | - | - |
| aliases | 别名 | - | 方便搜索 |
| description | 描述 | - | - |
| tags | 标签 | `#父/子` 格式 | 横向分类 |
| status | 笔记状态 | 见下方 | 生命周期 |
| content-type | 内容分类 | 见下方 | 决定使用模板 |
| category | 横向分类 | learning / work / life / hobby | - |
| up | 父级链接 | [[MOC/概念]] | 知识网络 |
| date-created | 创建时间 | 日期 | 工具自动 |
| date-modified | 修改时间 | 日期 | 工具自动 |

### status：笔记状态

> 流转方向：**单项不可逆**

| 状态 | 含义 | 行动 |
|------|------|------|
| fleeting | 闪念/草稿 | 需要加工或删除 |
| cultivating | 培育中 | 持续补充内容/链接 |
| active | 活跃 | 作为主力引用 |
| completed | 已完成 | 项目完结/笔记闭环 |
| archived | 已归档 | 仅存档，不再维护 |

### content-type：内容分类

> **特定型**（由物理位置决定）：project, area
> **通用型**（由内容决定）：

| 类型 | 定义 | 示例 |
|------|------|------|
| term | 术语解释（来自文献/外部） | HTTP 协议、多巴胺 |
| atomic | 永久笔记（自己的观点、陈述） | "遗忘是记忆的默认属性" |
| concept | 概念集合，解释"为什么"或"如何运作" | 双重编码理论、熵增 |
| comparison | 对比分析，跨越多个概念 | A vs B、选型建议 |
| sop | 标准流程，明确步骤的操作指南 | 部署流程、SOP |
| moc | 内容地图，索引多个相关笔记 | 导航页、知识地图 |

### 项目专属字段

| 字段 | 用途 | 可选值 |
|------|------|--------|
| consequence | 重要程度 | 1~10 |
| urgency | 紧急程度 | 1~10 |
| energy-type | 精力类型 | 💡 创意 / ⚡ 能量 / 🔄 常规 / 🏃 运动 |
| quadrant | 四象限位置 | - |
| expire | 截止日期 | 日期 |

## 命名规范

### 文件前缀

| 前缀 | 用途 | 示例 |
|------|------|------|
| P- | 项目笔记 | P-求职、Docker项目 |
| A- | 领域笔记 | A-人工智能、A-个人成长 |
| Q- | 问题笔记 | Q-如何学习编程 |
| MOC- | 内容地图 | MOC-前端知识地图 |
| SOP- | 标准流程 | SOP-周回顾部署流程 |
| T- | 术语笔记 | T-HTTP |
| C- | 概念笔记 | C-双重编码理论 |

### 目录前缀

数字前缀用于排序：

```
00-META      → 系统元数据
10-PROJECTS  → 项目
20-AREAS     → 领域
30-ZETTELCASTEN → 原创笔记
40-RESOURCES → 外部资源
50-ARCHIVE   → 归档
90-DIARY     → 日记
99-ASSETS    → 额外资源
```

### 命名原则

- 采用中文 + 内容描述
- 避免拼音、缩写和无意义编号
- 禁止特殊字符（? * < > | \ / : "）

## 标签规范

### 格式

```
#父标签/子标签
```

### 示例

```
#学习/前端      → 话题标签
#工具/Obsidian  → 工具标签
#工作/项目A     → 工作相关
#生活/爱好      → 生活相关
```

### 原则

- 主要用于话题（Topic）和媒介（Medium）
- 无数量限制
- 无特殊含义标签

## 工作流

### 逻辑 1：PARA 行动导向

```
需要做事 → 创建项目(P-) → 关联领域(A-) → 项目/领域发展中发散观点 → 形成原创笔记
     ↓
项目结束 / 领域不活跃 → 归档(50-ARCHIVE)
```

- **触发**：有明确要做的事情
- **路径**：项目 → 领域 → 原创笔记
- **补充来源**：30-ZETTELCASTEN（原创）和 40-RESOURCES（外部）

### 逻辑 2：卡片盒捕获加工

```
对某领域感兴趣 → 领域笔记(A-/MOC-)发散 → 形成概念/原子笔记 → 加工内化
```

- **触发**：兴趣驱动
- **路径**：领域 → 原创笔记
- **不需要项目**

### 生命周期

```
fleeting → cultivating → active → completed → archived
```
