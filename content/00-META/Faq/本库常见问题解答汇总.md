## 常见问题解答

### 概念区分

#### atomic vs concept vs term 有什么区别？

> 📖 完整对比见 [[Specification/_笔记类型规范#atomic-vs-concept-vs-term]]

#### area vs moc 有什么区别？

> 📖 完整对比见 [[Specification/_笔记类型规范#area-vs-concept-vs-moc]]

#### 为什么 atomic 永不复用？

atomic 是洞察，是你对某个问题的理解。洞察不会过期，只会被深化或修正。删除 atomic = 删除知识资产。

### 方法论

#### 为什么使用 PARA 笔记法？

> 📖 完整解答见 [[为什么使用PARA笔记法]]

PARA 基于行动而非主题组织知识，以「需求推动」立项，让精力聚焦于当下要完成的事。领域（Area）管责任、项目（Project）管行动。

### 命名规范

#### 为什么前缀放 aliases 而不是文件名？

**文件名**：纯标题，正文引用更通顺

```markdown
[[闭包]] 而不是 [[C-闭包]]
```

**aliases**：检索索引，LLM 可以识别类型

```yaml
aliases: [C-闭包, 闭包概念]
```

#### 子主题如何命名？

当子主题名称通用/易混淆时，加父级前缀：

| 场景 | aliases |
|:---|:---|
| Fiber 是 React 的子概念 | `["C-React-Fiber", "Fiber"]` |
| 场景图结构 是 ThreeJS 的子概念 | `["C-ThreeJS-场景图结构", "场景图结构"]` |

### 三层架构

#### 为什么要分层？

- **50-ZETTELCASTEN**：你的原创洞察，source of truth
- **30-RESOURCES**：LLM 整合的概念/索引，LLM 负责维护
- **40-ARCHIVE**：过时的知识

分层让人类负责原创，LLM 负责整合维护。

#### atomic 可以移到 Wiki 层吗？

不可以。atomic 是 source of truth，移到 Wiki 层后 LLM 会修改它。

### 工作流

#### ingest 工作流做什么？

```bash
新 atomic → LLM 分析 → 创建/更新相关 concept/moc
                         ↓
                    更新 wiki-index
                         ↓
                    记录 wiki-log
```

#### lint 工作流检查什么？

| 检查项 | 说明 |
|--------|------|
| 矛盾检测 | 同一概念的不同描述是否有冲突 |
| 孤儿页面 | 没有被引用的笔记 |
| 概念缺口 | 应该有但没有的笔记 |
| 过时笔记 | 内容过时但未更新 |
| 一致性 | wiki-index 和实际内容是否一致 |

#### 什么时候触发 inbox-review？

当你要求 " 审核 Inbox" 或 " 消化捕获篮 " 时。

### 发布和构建

#### 如何本地预览？

```bash
npm run dev
```

#### 如何发布到线上？

推送到 GitHub，Vercel/Netlify 会自动构建部署。

#### 博客文章如何发布？

1. 使用 `template_article.md` 创建笔记
2. 设置 `published: true`
3. 推送到远程
