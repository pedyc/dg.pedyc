## 常见问题解答

### 概念区分

#### atomic vs concept vs term 有什么区别？

| 类型 | 内容 | 示例 |
|------|------|------|
| atomic | 一句话洞察/观点（陈述句） | " 闭包的本质是函数保存了其定义时的作用域链 " |
| concept | 概念总览 + 整合串联 | [[C-闭包]] — 包含定义、命题、机制、图谱 |
| term | 术语定义（客观中立） | [[T-HTTP]] — 协议的标准定义 |

**判断标准**：
- 想表达 " 洞察/观点 " → atomic
- 想表达 " 术语/定义 " → term
- 想做 " 概念整合和索引 " → concept

#### area vs moc 有什么区别？

| 类型 | 定位 | 核心特征 |
|------|------|----------|
| area | 责任范围，需持续关注 | 包含长期目标、心智模型、执行系统 |
| moc | 内容索引，导航入口 | 包含链接集合、核心原则、待补充清单 |

**判断标准**：
- 需要设定学习目标？ → area
- 只是做内容索引？ → moc

#### 为什么 atomic 永不复用？

atomic 是洞察，是你对某个问题的理解。洞察不会过期，只会被深化或修正。删除 atomic = 删除知识资产。

### 命名规范

#### 为什么前缀放 aliases 而不是文件名？

**文件名**：纯标题，正文引用更通顺

```markdown
[[闭包]] 而不是 [[C-闭包]]
```

**aliases**：检索索引，LLM 可以识别类型

```yaml
aliases: [C-闭包, 闭包概念]
```

#### 子主题如何命名？

当子主题名称通用/易混淆时，加父级前缀：

| 场景 | aliases |
|:---|:---|
| Fiber 是 React 的子概念 | `["C-React-Fiber", "Fiber"]` |
| 场景图结构 是 ThreeJS 的子概念 | `["C-ThreeJS-场景图结构", "场景图结构"]` |

### 三层架构

#### 为什么要分层？

- **30-ZETTELKASTEN**：你的原创洞察，source of truth
- **40-RESOURCES**：LLM 整合的概念/索引，LLM 负责维护
- **50-ARCHIVE**：过时的知识

分层让人类负责原创，LLM 负责整合维护。

#### atomic 可以移到 Wiki 层吗？

不可以。atomic 是 source of truth，移到 Wiki 层后 LLM 会修改它。

### 工作流

#### ingest 工作流做什么？

```bash
新 atomic → LLM 分析 → 创建/更新相关 concept/moc
                         ↓
                    更新 wiki-index
                         ↓
                    记录 wiki-log
```

#### lint 工作流检查什么？

| 检查项 | 说明 |
|--------|------|
| 矛盾检测 | 同一概念的不同描述是否有冲突 |
| 孤儿页面 | 没有被引用的笔记 |
| 概念缺口 | 应该有但没有的笔记 |
| 过时笔记 | 内容过时但未更新 |
| 一致性 | wiki-index 和实际内容是否一致 |

#### 什么时候触发 inbox-review？

当你要求 " 审核 Inbox" 或 " 消化捕获篮 " 时。

### 发布和构建

#### 如何本地预览？

```bash
npm run dev
```

#### 如何发布到线上？

推送到 GitHub，Vercel/Netlify 会自动构建部署。

#### 博客文章如何发布？

1. 使用 `template_article.md` 创建笔记
2. 设置 `published: true`
3. 推送到远程
