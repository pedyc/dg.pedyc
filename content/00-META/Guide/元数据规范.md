## 元数据规范

| 字段 | 用途 | 可选值 | 备注 |

| uid | 唯一标识 | 时间戳 | 自动生成 |
| title | 笔记标题 | - | - |
| aliases | 别名 | - | 方便搜索 |
| description | 描述 | - | - |
| tags | 标签 | `#父/子` 格式 | 横向分类 |

### status：笔记状态

> 流转方向：**单项不可逆**（atomic 例外：永不复用）

#### 基础定义

| 状态 | 含义 | 典型触发条件 |
|:---|:---|:---|
| fleeting | 闪念/草稿 | 刚捕获的原始想法 |
| cultivating | 培育中 | 持续补充内容/链接 |
| active | 活跃 | 作为主力引用，被持续维护 |
| completed | 已完成 | 内容成熟但不再主动维护（仍有效） |
| archived | 已归档 | 终态，不再维护 |

#### 按 content-type 的归档语义

| content-type | completed 语义 | 归档触发条件 |
|:---|:---|:---|
| **atomic** | 洞察完成 | ⚠️ **几乎不归档**——洞察是资产，永不过期 |
| **concept** | 概念理解完成 | 版本过时（ES2026 → ES2027）但笔记未更新 |
| **term** | 定义完成 | 定义被证伪 或 被新版本替代 |
| **roadmap** | 版本覆盖完成 | 新版本已发布但笔记未更新 |
| **sop** | 流程验证完成 | 技术栈变更导致流程失效 |
| **area** | 领域探索完成 | 放弃该领域的学习/关注 |
| **moc** | 索引整理完成 | 主题已放弃，无导航价值 |

#### 归档的两层机制

| 机制 | 适用场景 | 操作 |
|:---|:---|:---|
| `status: archived` | 笔记完成/成熟但仍有效，不想维护 | 原目录不动，仅改 status |
| **移入 50-ARCHIVE/** | 明确过时、错误、或长期孤立（入链=0）且无保留价值 | 物理移动到归档目录 |

#### 归档判断决策树

```bash
笔记不更新了？
├── 内容完善 + 仍被引用 + 版本未过时
│   └── → status: completed（原目录不动）
├── 版本已更新但笔记未更新
│   └── → status: archived 或 移入 50-ARCHIVE/
├── 入链=0 + 从未被引用 + 无孤立价值
│   └── → 移入 50-ARCHIVE/
└── atomic 类型
    └── → 永不归档（洞察是资产）
```

> [!warning]
> **Zettelkasten 不删除原则**：atomic 笔记永不被删除；其他类型笔记过时/孤立时归档而非删除。

### content-type：内容分类

> **📖 完整定义见 [[Specification/_笔记类型规范]]** — 含所有 content-type 的目录、前缀、文件名规则、类型对比、状态流转。
> 以下为快速速查：

| 分类 | 类型 | 目录 |
|------|------|------|
| 面向 PARA | `project` | 10-PROJECTS |
| 面向 PARA | `area` | 20-AREAS |
| 面向主题 | `article` | 60-BLOGS |
| 面向时间 | `diary` | 90-DIARY |
| 面向知识管理 | `atomic` | 30-Zettelkasten |
| 面向知识管理 | `concept`, `moc`, `sop`, `question`, `term`, `comparison`, `record`, `roadmap`, `person` | 40-RESOURCES |

**目录规则**：
- **特定型**（由物理位置决定）：`project` → 10-PROJECTS，`area` → 20-AREAS，`diary` → 90-DIARY，`article` → 60-BLOGS
- **通用型**（由 content-type 决定）：atomic → 30-Zettelkasten，其他 → 40-RESOURCES
