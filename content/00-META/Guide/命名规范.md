## 命名规范

### 文件前缀（通过 aliases 实现）

**核心原则**：前缀仅用于 aliases 检索，WikiLink 引用使用纯标题。

前缀由 `content-type` 属性决定，存储在 `aliases` 中。文件名使用纯标题，正文引用更通顺。

> 📖 完整前缀表和命名规则见 [[Specification/_笔记类型规范#三文件命名与-aliases-规则]]

| 前缀   | content-type | 使用方式 |
| ---- | ------------ | ------- |
| P-   | project      | 文件名：`求职.md`，引用：`[[求职]]` |
| A-   | area         | 文件名：`人工智能.md`，引用：`[[人工智能]]` |
| Q-   | question     | 文件名：`如何学习编程.md`，引用：`[[如何学习编程]]` |
| MOC- | moc          | 文件名：`前端知识地图.md`，引用：`[[前端知识地图]]` |
| SOP- | sop          | 文件名：`周回顾.md`，引用：`[[周回顾]]` |
| T-   | term         | 文件名：`TCP.md`，引用：`[[TCP]]` |
| C-   | concept      | 文件名：`闭包.md`，引用：`[[闭包]]` |
| VS-  | comparison   | 文件名：`React vs Vue.md`，引用：`[[React vs Vue]]` |
| R-   | record       | 文件名：`俄乌冲突.md`，引用：`[[俄乌冲突]]` |
| -    | atomic       | 文件名：`闭包的本质是…md`，引用：`[[闭包的本质是...]]`

### 目录前缀

数字前缀用于排序：

```bash
00-META      → 系统元数据
10-PROJECTS  → 项目
20-AREAS     → 领域
30-ZETTELKASTEN → 原创笔记
40-RESOURCES → 外部资源
50-ARCHIVE   → 归档
80-PRIVATE   → 私有内容
90-DIARY     → 日记
99-ASSETS    → 额外资源
```

### 子主题命名规则（隶属于父主题）

当一个笔记是另一个笔记的子主题时，在 aliases 中添加父级前缀，避免命名混淆。

| 场景 | aliases 示例 |
|:---|:---|
| Fiber 是 React 的子概念 | aliases: `["C-React-Fiber", "Fiber"]` |
| Fiber 是 React 的子术语 | aliases: `["T-React-Fiber", "Fiber"]` |
| 场景图结构 是 ThreeJS 的子概念 | aliases: `["C-ThreeJS-场景图结构", "场景图结构"]` |
| 虚拟头节点 是 链表 的子术语 | aliases: `["T-链表-虚拟头节点", "虚拟头节点"]` |

**命名格式**：`{类型前缀}-{父概念}-{子概念}`

**判断标准**：
- 子概念名称通用/易混淆（如 Fiber）→ 必须加父级前缀
- 子概念名称独特/仅限某领域 → 建议加父级前缀
- 子概念是 atomic（陈述句）→ 不需要加前缀

### 命名原则

- 采用中文 + 内容描述
- 避免拼音、缩写和无意义编号
- 禁止特殊字符（? * < > | \ /: "）
