## Wiki Index 格式规范

`00-META/Index/wiki-index.md` 是知识库的导航索引，由 LLM 维护。本文档定义其**唯一格式标准**。wiki-sync-local 每次更新 index、LLM 每次全量重建 index 时都必须遵守本规范。

### 1. 文档结构

```bash
--- frontmatter ---

## Wiki Index
<维护说明一行>
**最后更新：YYYY-MM-DD** — {{本次更新摘要}}   ← 唯一更新标记（头部）

---

## Areas (领域) — N 个
### {子分区标题}
- [[标题]] — 描述

---

## MOCs (领域入口) — N 个
...
## Meta (系统)                                  ← 最后一个分区，固定位于末尾
- [[llm-wiki-schema]] — ...
```

### 2. 分区顺序（固定）

业务分区固定顺序，禁止新增、调换、改名：

| 顺序 | 分区标题 | 内容 |
|---|---|---|
| 1 | `## Areas (领域)` | 顶层领域（area） |
| 2 | `## MOCs (领域入口)` | 主题索引（moc） |
| 3 | `## Concepts (概念)` | 概念整合（concept） |
| 4 | `## Terms (术语)` | 术语表（term） |
| 5 | `## SOPs (标准流程)` | 标准流程（sop） |
| 6 | `## Comparisons (比较分析)` | 对比分析（comparison） |
| 7 | `## Questions (待探索)` | 待探索问题（question） |
| 8 | `## Records (事件记录)` | 事件记录（record） |
| 9 | `## Meta (系统)` | 系统/规范文档，固定位于末尾 |

分区之间以 `---` 分隔。

### 3. 计数标注

每个业务分区标题携带 `— N 个`：

- N = 该分区下**一级条目**总数（`###` 子分区内的条目数之和）
- 不含 `###` 子分区标题本身，不含子条目
- `## Meta (系统)` 分区不标计数
- 全量重建时重新统计，保证准确

### 4. 条目格式

**一级条目**：

```markdown
- [[标题]] — 描述
```

- 标题用笔记**纯标题**（不带 `A-` / `MOC-` / `T-` 等前缀），依赖 aliases 解析
- 纯标题无法解析时才用管道语法：`- [[显示名|文件名]] — 描述`（显示名=纯标题，文件名=带前缀别名）
- 描述取自笔记 frontmatter 的 `description`，压缩为短语（≤ 30 字），**不以句号结尾**
- **禁止**在条目内标注 `（aliases: …）`——别名属于 frontmatter，索引内不重复

**子条目**（person / 归属子页）：

```markdown
- [[父条目]] — 描述
	- [[子条目]] — 描述
```

- 子条目使用 **1 个 tab** 缩进，禁止 2 / 3 tab
- 子条目同样遵循 `- [[标题]] — 描述`

### 5. 排序规则

- `###` 子分区：按主题逻辑顺序排列，不强制字母序
- `###` 子分区内条目：按标题排序（中文按拼音、英文按字母升序）
- 增量插入时插入到对应子分区的正确位置；排序违规不阻塞同步，全量重建时统一修正

### 6. 更新标记

- 仅保留**头部一处**：`**最后更新：YYYY-MM-DD** — {{本次更新摘要}}`
- **删除尾部签名行**（旧版 `*Wiki Index 最后更新…*` 与头部重复，易漂移）
- 摘要：动作短语，用 `/` 分隔，如 `去重归档 / content-type 归位 / 新增求职领域`

### 7. 维护时机

- **增量维护**（创建/删除单条笔记）：wiki-sync-local 按本规范插入/移除条目
- **全量重建**（大规模重构后）：LLM 按本规范重新生成整个 index，重计计数、重排条目、重写摘要
