> [!important] 本文件写「为什么这样定」，不写「该怎么填」
> 判据在 `_templates/template_learning_project.md` 的注释与 [[笔记类型规范]]。若在这里复述条文，它立刻变成第二真值源——而且是没人校的那一份。下面每节只回答三件事：防什么失效、作用在哪一层、怎么算它生效。

## 一、设计目标：这套规则在防四种失效

不是「让学习专项更好写」的建议，是四个具体故障的补丁。列出来是为了让日后改模板的人知道自己在拆哪根梁。

| 失效 | 现象 | 对应规则 |
|:--|:--|:--|
| 目录化 | 专项写成「核心概念 + 问题清单」，有名录、没走过 | 判定链；第三列填不出的不算环节 |
| 产物化 | 以「写完 N 条 atomic」当达成，笔记齐了仍讲不出 | KR 抽样 + 费曼验收；末列必须落到链接 |
| 三处重复 | 同一条 KR 写在战略地图、排期表、验收表，改一处不同步不报错 | KR 只出现一次 |
| 手抄派生值 | 进度百分比、知识点台账、复查日期、「当前阶段」 | 一律不设，需要时用查询 |

第四条与 `template_project` 否掉「手填百分比」是同一条理由：两处维护，必然不一致，且不一致不显形。

## 二、设计主题：三个层次各管一件事

学习专项的内容只在三个层次上出现，越界就会互相吃掉。

**链层：分解。** 回答「这份产出的一生有几道判断、每道判错的代价」。它同时是范围定义——链外的概念自动出局，所以「不做什么」只剩链挡不住的那几条。一条链切不出来的主题不该立项：那是能力集合（如某门语言），属于 concept + MOC。

**KR 层：抽样。** 回答「哪几个综合场景能证明这些点串得起来」。所以它与链的条数本不该相等——链是逐点，KR 是跨点。强求一一对应，等于把链改造成任务分派表。同理，**目标节不写能力句**：那是 KR 的摘要，写进去就是同一层两份清单。

**页层：什么不该出现在这一页。** 凡是能从表里读出来的状态都不写：当前阶段 = 结果列填了几行，障碍 = 末列缺的那一块，下一步 = 下一个没勾的 checkbox。这一页本身就是进展。

**为什么不用 `template_project` 的战略地图。** 它给三样东西，只有一样能搬：任务挂在 KR 下（会退化成「任务做完 = KR 达成」）、KR 分节（与验收表重复）、顺序由依赖决定（要留）。但依赖的性质必须换——**项目依赖 ≠ 理解依赖**，两者可以相反。[[前端工程学习专项]] 是现成反例：提交前那道门在项目顺序上排最前（成本最低），在理解顺序上排第二（不懂「错误代价的落点」，钩子只是一段配置）。所以本模板只留理解顺序（即链），排期退成阶段格里的一行。

## 三、目标验证：怎么算它生效

三条都能在真实专项上查，不靠主观评价：

- **新开一份**：目标节若写不出第三列，说明还没找到链——此时该写 concept，不该立项。
- **写了一半**：KR 表每行的末列若长期空着，说明验收没真发生（费曼没讲，或讲了没记缺口）。
- **收尾时**：「不做什么」超过三条，多半是链没画完，靠禁令在补。

## 四、四次被推翻的判断

设计史比结论有用：下面每一条都是当时看着合理、后来被实际使用推翻的。

| 时间 | 当时定的 | 被什么推翻 |
|:--|:--|:--|
| 11-07 | 验收表加「复查（+14 天）」列 | 复查对象其实是那批 atomic，真实到期时间在 Anki 调度里；页上那份是手抄副本，必然不一致 |
| 11-08 一版 | 九节：背景 / 执行环境 / 学习路径 / 台账 / 战略地图 / 排期 / 验收 / 决策 / 复盘 | 同一条 KR 写在三处；且 260 行里一半是重复。用户要求从最简模板重推 |
| 11-08 二版 | 三节 + 知识点台账 | 台账是成功标准末列的聚合视图，手抄即派生值落库 |
| 11-09 | 三节（目标 / 成功标准 / 进展） | 目标首句与 KR 同义；进展节所述三样都能从表里读出 |

## 五、三处未解的张力

1. **链的粒度没有交叉校验。** 判据只有「第三列填得出」，但同一主题两个人能切出四环或六环，都合规。目前只能靠「环节名是全页唯一 key」防漂移，防不了切法不同。
2. **「必答反例」对 LLM 对手可能失效。** 它读得到表，于是能反推出你答不出什么；也可能顺手把反例答掉，把「未过」说成「过了」。这一环目前只能靠人复核，模板管不到。
3. **sop 的准入靠「我打算再做」这个主观承诺**，事后无法核对它当时是否成立。所以它只能当写作时的提醒，不能当验收判据。
