## 快速开始

本库是基于 Obsidian + Quartz 的个人数字花园，集成 LLM Wiki 维护系统。3 分钟上手。

### Step 1：创建笔记

使用 Templater 插件创建笔记，选择模板类型：

| 想记录什么 | 选择模板 | 自动进入目录 |
|-----------|----------|--------------|
| 闪念/洞察 | `template_atomic.md` | 50-ZETTELCASTEN |
| 概念总览 | `template_concept.md` | 30-RESOURCES |
| 领域入口 | `template_moc.md` | 30-RESOURCES |
| 操作流程 | `template_sop.md` | 30-RESOURCES |
| 术语定义 | `template_term.md` | 30-RESOURCES |
| 项目笔记 | `template_project.md` | 10-PROJECTS |
| 领域笔记 | `template_area.md` | 20-AREAS |
| 博客文章 | `template_article.md` | 60-BLOGS |

### Step 2：填写 frontmatter

```yaml
---
uid: <自动生成>
title: <笔记标题>
aliases: [<类型前缀-标题>]  # 如 C-闭包
tags: [<父/子>]
date-created: <自动>
date-modified: <自动>
content-type: <笔记类型>
---
```

### Step 3：笔记的「状态」看目录，不看字段

本库**没有** `status` 字段。一篇笔记处于什么阶段，由它在哪个目录表达：

```bash
00-INBOX        →  30-RESOURCES    →  50-ZETTELCASTEN  →  40-ARCHIVE
   捕获                加工               原子化              退役
```

- 想知道「哪篇变陈旧了」→ 看「最后写入时间」（`file.mtime`，文件系统给的），或直接开 `99-ASSETS/Bases/笔记滞留与陈旧.base`
- 不要手动新增 `status:`。老笔记里残留的可以不管，看到时顺手删掉即可

> 为什么不设该字段：见 [[元数据规范#为什么没有 status 字段（2026-10-24 废除）]]。实测它记录的是「用了哪个模板」，不是成熟度。

### Step 4：引用而非复制

```markdown
<!-- 错误：复制内容 -->
闭包是指...

<!-- 正确：引用链接 -->
[[闭包]] 是一个核心概念...

<!-- atomic 用陈述句 -->
[[闭包的本质是函数执行时创建的作用域链]]
```

### Step 5：使用 aliases 前缀检索

| 前缀 | 类型 | 示例 |
|------|------|------|
| P- | project | `P-求职` |
| A- | area | `A-人工智能` |
| Q- | question | `Q-如何学习编程` |
| MOC- | moc | `MOC-前端知识地图` |
| SOP- | sop | `SOP-周回顾` |
| T- | term | `T-TCP` |
| C- | concept | `C-闭包` |
| VS- | comparison | `VS-React vs Vue` |
| R- | record | `R-俄乌冲突` |

> **原则**：前缀放 aliases，文件名用纯标题，正文引用更通顺。
