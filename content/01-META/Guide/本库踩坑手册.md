# 本库踩坑手册

只收一类东西：**写错了不会报错，而且你读笔记时看不出来**的坑。

分工：判断类约定（哪种形态、字段该不该填）在 `01-META/Truth/`；方法与边界在 [[本库脚本化]] 与 [[本库Bases约定]]。本文件收的是操作层——命令、编码、配置、发布。

## 一、git

- **pathspec 大小写会静默零命中**。索引里记的是 `90-Diary`，实际目录是 `90-DIARY`；Windows 上两者都能访问，但 pathspec 一条都匹配不上，**不报错**，`commit` 照常「成功」——提交的是空改动。
  - 判据：**提交后必须 `git show --stat` 核对文件清单**，不要只看 commit 返回值。
- 仓库根在上一级 `D:/Workspace/pedyc/dg,pedyc`（Quartz 站点工程），vault 只是 `content/`。根 `.gitignore` 含「忽略自身」的规则（第 3 行），不要重写它。
- `.obsidian/` 被忽略但部分文件已被跟踪，`git add` 这类文件要加 `-f`，否则静默跳过。

## 二、批处理与文本

- **换行一律 LF**。`pathlib.write_text()` 在 Windows 默认写 `\r\n`，批量脚本必须 `write_bytes(b.replace(b"\r\n", b"\n"))` 或 `open(..., newline="")`。
- **shell 会吞反斜杠**：带正则或转义的扫描，一律写成 `.py` 文件再执行，不要 `python -c`。
- **不要用 `printf '\n'` 造测试文件**。Git Bash 会把 `\n` 写成字面量 `/n`，于是「测试文件本身是畸形的」，你验证的是错的假设，还会得出「检测器无效」这种反向结论。
- **批量改写的排除清单必须逐项列出**，只按「归档区免维护」排除不够。五类只读区：`99-ASSETS/copilot/`（对话存档）、`.claude/`（配置与示例）、`01-META/Log/`（流水日志）、`40-ARCHIVE`，以及**规范文档里的反例示例**——改那几处等于把教材改错。

## 三、YAML 与 frontmatter

- **单行数组的项内含半角逗号会被拆成两项**：`author: [字节前端, pedyc]` 解析出的是两项，而不是一项「字节前端, pedyc」。能兜住它的 Linter 规则 `escape-yaml-special-characters` 当前是关闭的，所以用了单行数组就要自己保证项内没有半角逗号。
- **裸数字 `uid` 会被解析成 int**（`uid: 20261025041530` → Number）。目前没有视图按字符串比较 uid，故不改；将来若要写 `uid == "..."`，必须给值加引号，否则恒假且不报错。
- `content-type` 写成数组会让 `.base` 与 dataview 的比较静默失效，属形态定义问题，见 [[笔记类型规范]]「content-type 总览」；`validate_meta.py --all` 会抓这一条。

## 四、Obsidian 配置

- **占位符只有 Templater 会渲染 `<% %>`**，Daily Notes 与核心 Templates 插件都不认，会把占位符原样写进文件且不报错。
  - 症状：`uid` 是字面量、`title` 却是文件名、`date-created` 是 UTC 的昨天 → Templater 根本没跑，是 Linter 在事后补字段。
  - 连带：Linter 的 `lintOnSave` 不走 `foldersToIgnore`，保护模板要靠 `filesToIgnore`；Linter **不会**改 `up` 的写法。
- **模板正文的 `---` 只分隔 `##` 级章节**，`##` 与 `###` 之间不加，否则三级标题被抬到与二级等权。
- **yanki**：`~~挖空~~`→Cloze，孤立 `---`→Basic 分隔符；同步范围只有 `50-ZETTELCASTEN`。atomic 已停挖空，重开前先看 `_templates/template_atomic.md` 里记的连带后果。
- **`Guide/` 下不得有与 `Truth/` 同名的文件**。曾出现僵尸副本，链接会解析到副本上，且「哪个在生效」不可预测。
- **改顶层目录名**：Obsidian 运行时直接 `git mv` 整目录会 Permission denied，用 `robocopy /MOVE` + `git add -A`（git 仍能识别为 rename）。

## 五、发布

`content/` 会被 Quartz 发布成公开站点（`dg.pedyc.site`）。新建 `*.md` 前先确认它是否该公开。`quartz.config.yaml` 的 `ignorePatterns` 目前排除：

```yaml
    - .obsidian
    - 80-PRIVATE
    - _resources
    - _templates
    - _scripts
    - AGENTS.md
    - CLAUDE.md
    - "**/AGENTS.md"
    - "**/CLAUDE.md"
```

`**/` 那两条**不匹配根级文件**（minimatch 实测），所以根级与子目录要各写一套。新增指令类文件时同步这个列表，否则内部约定会被发布到公网——而这件事同样不会报错。
