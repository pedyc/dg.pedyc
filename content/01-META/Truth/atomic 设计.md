> [!important]
> 本文件是 **atomic 形态的唯一真值**。content-type 枚举、各类型定位、模板映射、以及 atomic 与 concept 的分界，仍在 [[笔记类型规范]]；本文件不复述那部分。

## 定位

一句话命题，标题即结论。靠 concept 的核心命题段获得位置，不靠目录组织（`50-ZETTELCASTEN/` 是它的唯一落点，那是目录约束，不是组织方式）。

永不归档、永不删除。

## 标题的第一关：主语可指认

`atomic` 标题会在**离开本文的任何地方单独出现**——被 concept 引用成 `[[...]]`、出现在文件列表与图谱、出现在搜索结果里。所以它得先过一关，比「可判断真假」更前置：

> 把标题抄到一张白纸上，问：**这句话说的是哪个对象上的事？** 若要翻回 `up` 字段、目录路径或正文才能回答，这句话就没有主语。

主语悬空时无所谓真假——读者连它在说什么都不确定，谈不上检验。所以顺序是**先主语，后真假**，反过来的检查会漏掉整整一类残句。

下表两个例子取自 2026-10-28 全库体检里真实犯过的病例（左列是当时的标题，右列是补法）。这是病征演示，不是当前的待修清单——库里现存的篇目以 `.claude/agents/atomic-title-reviewer.md` 的判定为准。

| 病征 | 悬空 | 指认得出 |
|:--|:--|:--|
| 砍掉定语的简称 | `两阶段模型只管单次进入` | `执行上下文的两阶段模型只管单次进入` |
| 行业泛称当专名 | `优先级调度只决定谁先跑` | `React 的优先级调度只决定谁先跑` |
| 引用式主语不交代出处 | `「一句话说清」是观点成形的结果` | `「一句话说清」这个拆分判据是观点成形的结果，不是判据本身` |
| 靠 up 才补全的主体 | `Tool 的执行权在 Runtime 手中` | `Agent 的工具执行权在 Runtime 手中，不在 LLM` |

**反向护栏：不自足 ≠ 必须写全称。** `Fiber`、`IndexedDB`、`WebSocket`、`CORS`、`localStorage` 这类全库唯一且业内公认的专名可以直接裸用，补成全称只会让标题变笨。要限定的是两种：**本身是泛称**（调度 / 依赖图 / 多路复用 / 框架 / 宏），以及**库里存在同名兄弟**（`Context` 同时指 React Context 与 Context Engineering，两边都得带限定）。

一句话判据：**标题里那个东西，能不能被指着说「就是这个」？**

## 正文结构：观点 + 边界 + 至多一个论据

atomic 只该有三种成分，其中「边界」是最常被写错、也最常被整格漏掉的一格：

| 成分 | 写什么 | 常见错误 |
|:--|:--|:--|
| 观点 | 标题那一句本身，正文不必复述 | 先复述标题再展开 |
| **边界** | 什么时候不成立、适用条件、代价，**它给观点划范围** | 把限定当论据写，于是越写越长 |
| 论据 | 至多一个能支撑观点的具体事实、反例或机制 | 一口气列出 3-5 条并列论据 |

判据只有一句：**这句话是在支撑观点，还是在给观点划范围？** 支撑 → 论据；划范围 → 边界。放错格子的后果不是写错，而是「论据格越写越长，边界格永远空着」——读者最终拿到的是一条不知道何时失效的断言。

由此得到一个固定病灶与它的唯一改法：

- **`## 论据/示例` 下再套 `### 论据 / ### 示例 / ### 推论`**。父标题本身就是多余的层，但机械把 `###` 降成 `##` 治不了——病根是里面有 3-5 条论据。只能整篇重写成「观点 + 边界 + 一段论据」。**出现 `### 论据` 基本等于宣告这篇该瘦身。**
- 反过来的信号：一篇 atomic 的自定义章节名，只有两种合法成分——**机制展开**（工作原理 / 实现方式 / 条件清单）属 concept，**限定**（注意事项 / 为什么需要 / 适用场景）属本节说的「边界」。各归各位之后，剩下的通常不够一个 `## 论据` 节，所以这类篇的动作是**补边界**，不是删内容。

> [!warning] 没有第四种成分：不设 `## 关联` 节
> 模板曾在「论据」后加一节 `## 关联` 放裸链接，2026-10-30 移除。实测 114/119 篇写了这一节，其中 **82% 的第一条链接就是 frontmatter 的 `up` 副本**、**89% 是不带任何关系标签的裸链接**——填得动不等于填得对：复盘 6 格需要回看才填得出所以 0/5 空着，这一节丢一个 `[[up]]` 就能交差所以人人有。
>
> 两个互斥的理由：① 它和 `up` 字段构成两处手工维护的同一条事实，改 `up` 时没人会记得同步正文；② 它给「建立连接」提供了不说理由的低成本出口，而本库的要求是**说不出属于哪类关系就不建链接**。要说的「为什么相关」写进边界一句话即可，那本身就是一条洞见。
>
> 「谁引用了我」由反向链接面板回答，「我挂在谁下面」由 `up` 回答，两者都不该手写。存量 114 篇按「先不管遗留，遇到再改」保留。

### 论据归谁：看复用度，不看「被几处引用」（2026-10-30 定）

「论证归 concept」是把三条规则压成一句的简化说法，单看这一句会被执行成「一律上交」，于是 atomic 只剩一句断言、概念里堆满别人的论点。真实判据有两问，先问复用度，再问长度：

| 情形 | 归属 | 处理 |
|:--|:--|:--|
| 只服务这一个论点，写入不超过一行 | 留在 atomic | 它是「当场能验证的最小证据」，不是完整论证 |
| 服务两个以上论点，或需展开成节 | 上移到承载该机制的 concept | atomic 只留指针，不留副本 |

由此三条硬约束：

1. **与 concept 重复的段落是副本，删掉后指过去。** 判据是「抄过来是否零信息量」，逐字与同义改写都算零。
2. **同一论据被第二篇 atomic 需要，它就不再是论据，而是机制**：上移，两篇各自回链。这是「按复用度」的可执行算法。
3. **论证的宿主不必是 `up`。** `up` 表归档位置，不表论证归属（见 [[元数据规范]] 的 up 与「上位」分工）。机制住在哪一篇，链接就指哪一篇；[[浏览器缓存与客户端存储体系]] 把协议那一半的机制放在下位 [[HTTP缓存机制]]，就是这个形态。

为什么不是反过来、把论证都留在 atomic 换「自足」：atomic 承诺的是可判断，不是可自证。可判断由标题（主语可指认）与边界（失效条件）承担，两格都已必填；自证一旦也成为要求，concept 的核心命题段会退化为索引，形态分界（一条判断依据 / 一套理解）随之消失。而复制是唯一真正把两篇焊死的做法——单向上行是可审计的依赖，双向复制是必然漂移且不报错的副本，与「不新增第二真值源」同一个病灶。

两点护栏：

- 上表的「一行」是编辑口径，不是类型判据。本库已两次否决按程度划分类型（atomic 的主客观、sop 能否写死步骤），此处不同——长度只决定「搬不搬」，不决定它是不是 atomic。
- 词汇是 concept 造的（「失效判定权」本身出自 [[浏览器缓存与客户端存储体系]]），所以「脱离 concept 完全可读」达不到。追求它只会长出第二套术语，那是更贵的一种耦合。

### 瘦身顺序：先读 up，再删 atomic（参考口径，不是判据）

> [!note] 2026-10-30 定为参考
> 这条**不是必须满足的判据**：没有任何环节统计字数，也就没有通过/失败可判。2026-10-30 实测 119 篇中 54 篇（45%）超过 500 字，而这条从未被触发过——一条无人执行的规则，效果等于不存在。它保留的用途是**复查时的排序依据**，不是合格线。

超过 500 字的 atomic，超出的部分几乎都能在父概念里找到，删掉的是重复，不是知识。所以复查一篇长 atomic 时，先读它的 `up`，再决定删哪一段，不要先改字句。

它不能升级成判据，有两个理由：长度不是类型判据（本库已两次否决按程度划分类型）；atomic 的合格线是「边界是否划清、论据是否只有一条」，与字数无关。真要拿它当检查项，必须先给它一个触发点（ingest 或 lint 时检查），否则它只会继续是一条被引用的空文。

## 与 Anki：新笔记不挖空（2026-10-24 起）

> **存量写了 `~~挖空~~` 的篇目保留不动**——不清理、不批量删除。新建 atomic 不再写挖空。

这是一个明确取舍，不是纠正错误：

| | Cloze（挖空） | Basic（不挖空） |
|:--|:--|:--|
| 卡片正面 | 句子 + 空格 | 完整观点句 |
| 复习动作 | 强制回忆那个词 | 读到观点，自评能否展开 |
| 复习强度 | 高 | 中——少了强制回忆环节 |
| 制作成本 | 每次都要判断「哪个词是关键机制词」 | 零成本 |

选 Basic 的理由是**成本不对称**：挖空要求每次写笔记多做一次判断，而这个判断经常做不准（实测有 `~~同步写法，~~` 把逗号一起挖进去的写法，说明「只挖 1~2 个机制词」这条规则实际没被执行）。

省下的成本可以直接换成更多篇 atomic。**卡面本身就有复习价值——看到观点、自问能不能展开，这个过程已经发生；少了问答环节只是强度下降，不是归零。**

因此：

- **新笔记**：正文不写 `~~挖空~~`，同步到 Anki 是 Basic 卡（整篇一卡正面）
- **存量**：保留 `~~`，同步过去仍是 Cloze 卡，形态不变。两种卡并存，可接受
- `noteId` 不要手动删除——已同步的卡片有复习记录挂在上面

其余与切卡相关的约定仍然有效：

- 正文不要出现孤立的 `---`（避免被任何切卡逻辑误判为分隔符）
- `tags` 若仍同步，会被当作 Anki 标签
- `## 论据/示例` 属于论证，从来就不参与挖空
