> [!important]
> 本文件是 **project 形态的唯一真值**。content-type 枚举、各类型定位、模板映射仍在 [[笔记类型规范]]；字段定义在 [[元数据规范]]。本文件不复述那两部分。

## 定位

PARA 的 P：**一个时间盒内要产生一个可判定结果的工作**。它不是「主题的容器」（那是 area），也不是「一条判断」（那是 atomic）。

一句话判据：**到 `expire` 那天，能不能指着某样东西说「这件事结束了」？** 指不出来，它要么是 area（没有终点），要么还没立项。

## 构成要件：三件，缺一即不是 project

| 要件 | 载体 | 缺了会怎样 |
|:--|:--|:--|
| 时间盒 | frontmatter `expire` | 没有到期日，「做完」与「放弃」都无从判断；它会永久留在 `10-PROJECTS`，变成半个 area |
| 可判定的结果 | 目标节那句 Outcome | 退化成「一直在做的事」。问题不在懈怠，在没有能到的终点 |
| 工作区入口 | 目录里的那一篇主页 | 进行中的工作没有入口，知识随任务结束散落（见 [[类型设计判据]] 的失效形态） |

**因此 `expire` 对 project 不是可选字段。** [[元数据规范]] 把它列为 project 的专属字段，此处补半句：它同时是构成要件。实测（2026-11-10）8 篇候选里 7 篇填了，唯一的例外 `dg.pedyc` 当次即改判为 area——这不是巧合，它说明**填不出 `expire` 的「项目」其实是领域**。同日另一篇到期未完成的 `P-斑驳光背景实现` 归档后，`10-PROJECTS` 现存 6 篇 project，**6 篇全填了 `expire`**。

## 两种正文形态：终点在哪

project 只有两种正文形态，不由模板数量决定，由**终点在这份文件里还是在别处**决定。2026-11-10 实测 8 篇，全部落在这两类里（其中 2 篇当日分别改判为 area 与归档，现存 6 篇）。

| | 主页型 | 自足型 |
|:--|:--|:--|
| 什么时候用 | 结果外在他处：求职、作品集、站点改版 | 结果是「学到能讲清」，产出是知识资产 |
| 正文装什么 | 目标（Outcome + 不做什么）、关键结果清单、决策日志 | 目标（代价 + 判定链）、成功标准表（KR / 判据 / 怎么验 / 结果 / 缺什么） |
| 任务在哪 | KR 下的 `- [ ]`；实际内容在同目录的普通笔记里 | 成功标准末列，落成 atomic 或 sop |
| 结束标志 | 交付物能在屏幕上指认 | 每一行的「怎么验」都过 |
| 存量样本 | [[Agent求职]] · [[前端工程学习专项]] | [[缓存机制学习专项]] |

两者的共同点比差异重要：**都不设进展节、都不设复盘节、都不写百分比、只有一个日期**。差异只在前两节的形状。

> **形态会改，判据不会。** [[前端工程学习专项]] 2026-11-10 从自足型改为主页型：判定链降为目标里的一句话，KR 下挂 checkbox 与三篇子专项。原因是按自足型写，"该学什么"必须由链承担，链于是长成一张大表，附带 42 条读物清单——一份读物目录里找进度，读者要做两次映射；改成主页型后，链的两条判据（划范围、供倒推）仍在，只是不再占据正文主结构。**自足型不是"学习类项目"的默认形态**：只有当「学到能讲清」本身就是可交付结果、且没有可以外挂的子专项时，它才比主页型省事。

> **模板只有两个，不是三个。** 第二个模板（`template_learning_project`）能成立，是因为它的骨架真的不同（判定链 + 五列验收），不是「规模小一点的 project」。反例是 `template_sub_project.md`，2026-11-10 删除：骨架（目标 / 成功标准 / 决策日志）全库零实例，而且准入条件一旦满足就落回 `template_project`——**「只做一件事」是规模差异，不是形态差异，规模不需要独立模板。**
>
> 子项**何时才是 project**，判据是**它自己有没有独立的 `expire` 与可判定结果**：[[前端工程学习专项-构建]] 有（11-15 到期，自测五题 + 体积报告），Agent 求职的「AgentLoop 专项」没有（它的完成由父页 KR1 的勾选表达）。有，就给它自己的 project 主页；没有，它就是一条任务，照真实形态写成 concept 或 question。

## 目标节：首句写代价，不另设背景

目标节第一句回答「不做会怎样」，一句话。**不单设 `## 背景` 节**——它的内容要么已经写在 `description` 里（[[Agent求职]] 的背景段与它的 description 是同一句话的两种长度），要么属于 record（这件事的来龙去脉：时间线 + 出处）。

判据：把「背景」整节删掉，读者是否就不知道为什么要做这件事？若是，缺的是代价那一句，不是那一节。

## 关键结果：可判定的结果，不是任务清单

KR 就是成功标准，**不再另列一份「成功标准」**——同一层两份清单必然漂移。

- 每条 KR 需要一行**判据**（怎么算达成、能被别人验证）。
- 任务挂在 KR 下用 `- [ ]` 勾选。**进度 = 勾选数**。
- **不写 `(40%)` 这类数字。** 它们加起来是 100，却不驱动任何选择：三个 KR 都要做完，不是按权重分配时间；新增一条专项时没人回头改权重，于是数字与实际条数不一致且不报警。与 `quadrant` 同型——派生值落库。
- 节名用 `## 关键结果`，不用 `## 战略地图`。这一节装的是可勾选的结果，地图是比喻，读的人要先翻译一次。

## 自足型：判定链即范围

自足型的目标节先画一条链，不是先写「要学会什么」——后者不可判定，任何收尾都成立。

| 列 | 填什么 |
|:--|:--|
| 环节 | 一份产出的一生里的一段：一次请求、一次发版、一份产物。**不用章节名** |
| 判什么 | 这一步要下的那个判断，一句 |
| 判错的代价 | 判错长什么样，会在哪一步露出来 |

**第三列填不出的不是环节，是知识点**——挪去 atomic。**链即范围**：链外的概念自动出局，「不做什么」只剩链挡不住的那几条。

**切不出链就别开专项。** 能力集合（某门语言、某个岗位）没有生命周期，那是 concept + MOC 的事。

产出是链上缺的那一块：环节 → atomic，动作 → sop，骨架增删 → concept 修正（无新文件，最易漏记），断链 → 修好或明判不修。sop 准入：步骤多到下次会忘、且还要再做。

**KR 与环节不必一一对应。** 链是逐点分解，KR 是跨环节抽样；KR 也不该把链的每一行改写一遍，那是换个地方重抄链。

**「怎么验」默认费曼**：口述 5 分钟，必覆盖指定的几问，必答一个反例，说不清即未过。**「讲得通」不算过**——对手会顺着人说，把「讲得通」判成「掌握」。

## 读什么：断链即待写

未知领域的学习专项由 AI 起草，灰链就是待写清单，不另建台账（逐条状态是派生视图，手抄即两处维护）。

失败点不在格式，在顺序。起草时一旦能看到 `wiki-index`，「该读什么」就退化成「库里有什么」——答案空间被检索集封死了。所以分三遍，前两遍之间隔一堵墙：看不见库，也看不见彼此。

### 第一遍：换问法，不换态度

不写「列出这个领域要读什么」。这题只能靠回忆答，而回忆是热度加权的，本身就是另一份库存的存量清单——**换一份库存，还是照着存量列**。

改写出「走一遍这条链的五道关口，每道关口要下的判断是什么，下这个判断之前得知道什么」。前一种问法产出知识点，后一种问法产出**判断缺口**；缺口在库里通常没有对应笔记，于是自然落成灰链。让 AI「敢」没有用，换一个它答不出来的问法才有用。

### 第二遍：给外部锚点，两稿盲写再并

「领域应该有什么结构」也不能从模型的记忆里取，理由同上。取一份库外、且与库无关的实物：官方文档目录、课纲、认证大纲、招聘 JD 的能力项。AI 的动作从「回忆」变成「转抄并对账」，转抄没有锚定问题。

两遍各自盲写（第二遍看不到第一遍），再取并集；两遍的差集是最值得先读的部分。锚点写进页面一行（`依据：…`），否则将来没人能判断这份清单是抄的还是想的。

### 第三遍：对库

查 `wiki-index`。有则实链，无则按目标形态拟一个标题留灰链。

### 期望形状：灰链率

冷领域的第一版**大部分读物应该是灰的**。灰率低不是完备，是清单被库的存量约束过的痕迹。

2026-11-10 实测：四篇在用专项的「读什么 / 学习路径」共 46 条读物链，灰的 2 条（4.3%）——交付 0/7、构建 0/8、缓存 0/22、质量 2/9。前端工程这么宽的领域灰率 4%，说明这四份清单都是从库的存量倒推的。

| 灰率 | 读法 |
|:--|:--|
| 冷领域 < 20% | 可疑：清单多半照库列的，重做第一遍 |
| 冷领域 40% 以上 | 正常：缺口被识别出来了 |
| 已经熟的领域接近 0 | 正常，不需要灰链 |

灰率只在**冷领域**上成立——缓存那篇 0 灰是对的，那是已经会的东西。所以它是体检项，不是判据：脚本报数（`check_criteria.py --todo`），人看数。不做成判据，是因为「清单有没有覆盖领域」在本库内不可判定，写一条查不了的判据只会造出假合规。

### 排除项是广度的证据

清单末尾留几条「该读但不读」。**列不出排除项，说明枚举没有走过整片领域**——没想过的东西写不进排除。它同时落实「链即范围」：链外的概念自动出局，但出局这件事要说出来。

### 三条约定

| 约定 | 为什么 |
|:--|:--|
| **不标 `（待写）`** | 它是派生值——目标文件在不在，链接颜色已经说了。手写一份会随笔记创建而变成假信息，而且没人会回头删 |
| **断链标题必须能直接当笔记标题用** | 将来创建就是在灰链上点一下。`[[ESLint 配置]]` 建的时候还得再想一次「这是 concept 还是 atomic」；`[[Prettier]]`（term）、`[[开发态与构建态的分岔不在压缩，在模块由谁解析]]`（atomic）不用想——**标题的语法形式已经说明了形态** |
| 链接后可以接一句**动机** | 「卡在协议层的存活与应用层的可用不是一回事」不随笔记创建而失效；「待写」会。**状态会过期，动机不会** |

**断链不清零。** 结项时读什么节还留着灰链是正常的——学习不必写满所有读物。它随专项归档，将来写那篇时反链自动出现，入口就在原处。反过来，为了「看着干净」把灰链改成纯文本，等于把已经识别出的缺口重新藏起来。

## 不设进展节

> 实测（2026-11-10）：`10-PROJECTS` 的 8 篇 project 中 **0 篇**有 `## 进展`；模板侧同批清理干净，三个 project 模板再也找不到这一节。它不是「写得少」，是从未被使用。

三格都不必手写：

| 格 | 已经从哪读出来 |
|:--|:--|
| 当前阶段 | 哪几行 KR 有结果；哪几组 checkbox 已勾完 |
| 当前障碍 | 末列空着的那一行，或第一个停住的勾选项 |
| 下一步 | 第一个未勾项 |

手写一遍是重抄派生值，而手抄的那份**先过期**。这条对全部 project 形态成立，不只是学习专项——[[E43 不设「进展」节|E43]] 原来只写了学习专项，2026-11-10 扩回全形态。

## 复盘与归档：复盘发生在归档那一刻

> 实测（2026-11-10）：正文 `## 复盘` 全库 **0 篇** project 在用；唯一一篇在 `40-ARCHIVE/`，它已经归档了。

复盘不是进行中 project 的常驻章节：项目走到一半写不出「哪条判断被推翻」，写出来的是猜测。正确时机是 **`expire` 到期、决定关掉的那一刻**，与归档是同一次动作。所以模板不设这一节，归档时补。

**到期不等于完成。** `P-斑驳光背景实现` 的 `expire` 是 2026-09-14，到期后近两个月没动、一直留在项目区——这是「用沉默代替决定」。到期只有两个合法动作：

1. **续期**：改 `expire`，理由一行进决策日志。
2. **归档**：移到 `40-ARCHIVE`，补复盘。

它最终走了第 2 条（2026-11-10），复盘写在归档文件末尾。第三个选项「什么都不做」会让 `10-PROJECTS` 慢慢退化成第二个 `20-AREAS`：两类页面结构本来就相似，区别只剩 `expire`，而到期的 project 恰好也失去了 `expire` 的意义。

## 与 area 的分界

| | area | project |
|:--|:--|:--|
| 问的 | 这块责任我要不要一直管 | 这件事什么时候结束 |
| 有 `expire` | 没有（`20-AREAS` 19 篇 area 中 0 篇填） | 有，且必填 |
| 结构 | `## Area: X` + 领域定义 / 里程碑 / 专题导航 | 目标 / 关键结果 / 决策日志 |
| 结束 | 不结束，只可能被放弃 | 到期归档 |

**结构相似不构成判据。** [[dg.pedyc]] 曾用完整的 Area 骨架（领域定义 / 里程碑 / 专题导航 / 领域健康度），却把标题写成 `## Project: dg.pedyc` 放在 `10-PROJECTS/`，且没有 `expire`——2026-11-10 按本节判据改判为 area，移入 `20-AREAS/A-知识管理/`。两型的差别只有一条：**到点能不能关掉**。所以判型只看 `expire`，不看题材，也不看有没有里程碑。
