> [!important] 本文件定位
> 本文件是**「为什么本库有这 13 种形态」的唯一真值**。形态的枚举、aliases 前缀、模板映射、使用场景仍以 [[笔记类型规范]] 为准，本文件不复述。
> 分工一句话：**笔记类型规范说「有哪几种、怎么写、某篇该归哪一型」，本文件说「凭什么有它」。**
> 两边都自称真值时按内容判归属，不按先后：同一件事若两边说法相反，是**本文件越界写了判定规则**，改本文件，不改枚举。判据负责「靠什么维度区分」，判定负责「这一篇落在哪」。

## 一条形态要过的三关

新增一种类型，必须三问全答得出。任何一问答不出，它就不该是类型，而应是某个类型的形态或分区：

| # | 问 | 答不出会怎样 |
|:--|:--|:--|
| 1 | **上游结构**：库里哪条结构约束要求它存在 | 它只是「这类内容不一样」，不是一种形态 |
| 2 | **失效形态**：不设它，这类内容会烂成什么样 | 说不出失效，它没有存在理由 |
| 3 | **分界判据**：与最近邻靠什么区分 | 若只能靠题材或程度区分，它是分区，不是形态 |

第三关是本库的硬约束（P16）：**类型按形态划分，不按程度，也不按题材。** 程度包括长短、主客观、能不能写死步骤；题材包括记人、记事、记技术。

## 两个测试：某个类型是不是多余

| 测试 | 判据 | 命中即 |
|:--|:--|:--|
| 一 | 它的内容能否被另一个类型完整容纳，且唯一区分靠题材或程度 | 它是分区，不是形态，应并入或降为子模板 |
| 二 | 不设它，这类内容会不会无处可放 | 会 → 不多余；不会 → 多余 |

两项同时成立（能被容纳 + 不设也不会丢内容）才算多余。测试一命中而测试二不命中，是「该并但还没并」——2026-11-09 的 `person` 正是这一档。

## 13 种形态

本表只回答「凭什么有它」。有哪几种、怎么写、放哪个模板归 [[笔记类型规范]]；某一型具体怎么落到某一篇（判定规则）也归它，本表的分界列只点到「靠什么区分」。

| 形态 | 上游结构 | 不设它会怎样 | 与最近邻的分界 |
|:--|:--|:--|:--|
| `atomic` | 卡片盒的原子性 + `50-ZETTELCASTEN` 单形态目录 + Anki 单句卡 | 洞见只能埋在 concept 里，既不能被单条引用，也制不成卡 | 与 `concept` 看标题能否判真假；与 record 注记看能否被反驳 |
| `concept` | 三层粒度的微观层：理解一套运作 ≠ 记住一条断言 | 只有结论没有机制，追问「为什么这样」时无处安放 | 与 `moc` 看有无核心命题段；与 `term` 看名字的外延是否由规范给定 |
| `term` | 规范名的外延由文献给定，不能与领域内容混装 | 规范名被聚合内容占掉，每次入链都要先猜「指规范还是指领域」 | 与 `concept` 看正文主体是否超出该规范定义的对象 |
| `record` | 外部事实的落地：非我原创、有客观基础、有边界 | 剪藏与我的判断混装，判断以「已经记过了」的姿态躲掉该有的边界 | 与 `atomic` 看归属：记它说了什么 → record，因此我认为 X → atomic |
| `roadmap` | 同一组阶段 × 同一组维度的横向对照，全库只存一份 | 每个阶段的笔记各写一张表，改一处不同步且不报错 | 与叙事性内容看有无对照矩阵；与 record 事件看是否以阶段为行、同一组维度为列 |
| `comparison` | concept「关键区别」一节的容量上限：维度多到要打分就装不下 | 多维矩阵塞进概念页，概念页退化成对照表 | 与 `concept` 看是否跨对象、以维度矩阵为主体 |
| `question` | 岔路：收敛前的分叉本身有价值 | 被否掉的方案随收敛一起消失，只剩一条「正确路径」 | 与 `sop` 看还留不留岔路；与题单 `moc` 看是否只索引不探索 |
| `sop` | `question` 的收敛态之一：答案是动作序列 | 同一套流程每次从头重想，步骤散在对话里 | 与 `question` 同上；与 `atomic` 看收敛物是动作还是断言 |
| `moc` | 三层粒度的中观层：导航视角，只索引不消化 | 入口散落，找回只能靠搜索 | 与 `concept` 看有无核心命题段（消化禁令） |
| `area` | PARA 的 A + 宏观层：必须含长期目标 | 责任域没有主页，领域知识没有根 | 与 `moc` 看有无责任与目标；与 `concept` 看有无 area 专属字段 |
| `project` | PARA 的 P：时间盒 | 进行中的工作没有工作区入口，知识随任务结束散落 | 与 `area` **只看 `expire`**（结构相似不算，`dg.pedyc` 是反例，2026-11-10 已据此改判为 area）；子项是不是 project 看它自己有没有独立截止与可判定结果 |
| `article` | 内外两种读者：内化给自己，成文给不在这条链上的人 | 对外长文与内部笔记混装，发布状态无处标注 | 与 `concept` 看是否有单一读者与一条对外叙事线 |
| `diary` | 时间序列 + 卡片盒的闪念入口 | 按天发生的想法只能塞进 `atomic`，丢掉时间维度 | 与 record 事件看是否一天一格、按日期组织 |

## 三处需要写明的边界

### record 的第五形态：人物（2026-11-09 并自 `person`）

人物不是形态，是题材。原 `person` 与 record 的唯一区分是「记人 / 记事」，正落在 P16 禁止的那条线上，故并入 record，成为它的第五形态：

| 形态 | 中段写什么 | 最低要求 | 模板 |
|:--|:--|:--|:--|
| 人物 | 生平 / 时间线 / 成就 / 思想 / 关系 / 名言 | 一条可核实的生平事实 + 一个出处 | `template_person.md` |

`template_person.md` 是 record 的子模板，不映射独立类型——同 `template_source.md` 的先例。

**生卒、国籍、职业不落 frontmatter。** 它们写在正文「人物卡片」表格里：那张表读正文时就在眼前，再在 frontmatter 存一份等于两处维护，而两处不一致不会报错。`birth` / `death` / `nationality` / `occupation` 四个字段已进 [[元数据规范#字段墓碑]]。

### roadmap 的独占物是矩阵，不是线性叙事

这一型最容易被当成「凡是线性的都往这放」。判据收紧为一句话：**同一组阶段 × 同一组维度只存一份**。判断依据是「有没有对照矩阵」，不是「内容是否按时间排列」，更不是「阶段是版本还是职级」——版本、职级、里程碑都可以是行。

具体到某一篇该归 roadmap、concept 的演进段，还是 area 的里程碑，判定规则在 [[笔记类型规范#roadmap vs 线性叙事：看矩阵，不看题材]]，本文件不重写一遍。

### article 与 diary 有一半合法性来自目录

`60-BLOGS/` 必 `article`、`90-DIARY/` 必 `diary`，是目录对形态的单向限制。这两个形态拿不出别的独占物时，这条目录约束就是它们的上游结构；一旦目录约束取消，它们要重新过一遍三关。

**这是「形态与归属正交」的已声明例外，不是新原则。** 正交的意思是不存在「某形态必落某目录」的推导；这两个目录反过来成立——某目录只收某形态。三个例外都由 [[本库目录结构]] 声明（`50-ZETTELCASTEN` 只收 atomic），本文件只是指出它们的上游结构恰好是目录约束。除这三处外，形态与归属互不推导。

## 变更顺序

改类型系统时顺序不可反：**本文件（判据）→ [[笔记类型规范]]（枚举与定义）→ 模板与 `validate_meta.py` → 存量回填 → 校验**。先改枚举后改模板，会出现「模板还在生成已废除的值、校验却已放行」的窗口，而这个窗口不报错。

只改**判定规则**（某篇该归哪一型）时不必走这条链：判定归 [[笔记类型规范]] 的「类型辨析」节管，不涉及枚举、模板与脚本，改完最多触发一次存量复查。
