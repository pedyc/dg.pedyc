## 背景

随着大语言模型技术的发展，AI Agent 正逐渐从简单的对话系统发展为能够理解任务、调用工具、执行工作流并与外部系统交互的软件系统。

对于希望进入 Agent 工程领域的开发者而言，仅掌握模型 API 调用或提示词编写是不够的，还需要具备系统设计、[[工具集成]]、[[任务编排]]、状态管理、可靠性保障和工程交付等能力。

本人具有前端开发背景，拥有 JavaScript、TypeScript 及现代前端工程体系方面的经验，并正在开发 `pedyc-harness` 项目。

这些经验可以成为转向 Agent 工程的基础：
- 将前端工程中的模块化、类型系统和工程规范迁移到 Agent 系统开发。
- 将复杂交互和状态管理经验应用于 Agent 工作流与人机协作设计。
- 将 `pedyc-harness` 作为探索 Agent 治理、独立验证和 Evidence 机制的工程实践项目。

> 本项目的核心思路不是单纯学习 AI 概念，而是通过持续实践，形成可展示、可验证、可复用的工程能力，最终完成从前端开发者到 Agent 工程师的职业转型。

---

## 核心目标

- [ ] **目标一：建立 Agent 工程知识体系。** 系统掌握 LLM API、Prompt Engineering、Tool Calling、Structured Output、RAG、Agent 工作流、状态管理、记忆机制、评估与可靠性保障等核心技术。
- [ ] **目标二：完成至少 2 个具有实际工程价值的 Agent 项目。** 至少包含一个能够体现任务执行、工具调用和验证机制的完整项目，并具备清晰的架构文档、测试和演示材料。
- [ ] **目标三：形成可用于求职的技术竞争力。** 完成 Agent 相关简历、项目介绍、技术面试题库和模拟面试，能够独立解释项目架构、关键技术决策、实现细节及其局限性。
- [ ] **目标四：获得 Agent 相关 Offer。** 主动投递 Agent Engineer、AI Engineer、LLM Application Engineer 等相关岗位，并根据面试反馈持续改进。

**成功标准：**

1. 能够独立设计、实现、测试和部署一个具备实际任务执行能力的 Agent 应用。
2. 至少完成 2 个可公开展示的工程项目，其中至少 1 个具有完整的项目文档、测试记录和演示材料。
3. 能够清晰解释 Agent 系统的核心架构、关键技术、失败模式、评估方式及工程权衡。
4. 完成针对目标岗位的简历和面试准备，建立持续的求职投递与反馈机制。
5. 在项目期限内获得至少 1 份 Agent 或 LLM 应用开发相关正式 Offer。

## 执行计划

### 阶段一：基础建设期

**目标：建立知识框架，明确岗位要求，完成基础技术验证。**

#### 任务一：岗位需求调研

- 搜集 Agent Engineer、AI Engineer、LLM Application Engineer 等岗位的招聘信息。
- 记录招聘要求中的技术栈、项目经验、学历要求和工作职责。
- 区分必须具备的能力、加分项和暂时不需要深入掌握的技术。
- 建立岗位要求与个人现有能力之间的差距清单。
- 根据实际招聘需求确定学习顺序，避免脱离就业目标进行无边界学习。

#### 任务二：建立 Agent 知识体系

重点学习以下内容：

- LLM 基础：Token、上下文窗口、模型推理、采样参数和模型局限性。
- LLM API：消息格式、流式输出、结构化输出、错误处理和重试。
- Prompt Engineering：指令设计、上下文组织、输出约束和提示词评估。
- Tool Calling：工具定义、参数校验、调用结果处理和工具权限控制。
- Agent 工作流：任务分解、状态管理、执行循环、停止条件和失败恢复。
- RAG：文档处理、Embedding、检索、重排序和上下文构建。
- Agent 可靠性：日志、Tracing、评估、测试和人工介入机制。

#### 任务三：完成基础 Agent 实验

- 使用 TypeScript 实现一个能够调用 LLM 的基础应用。
- 实现结构化输出和参数校验。
- 实现至少一个外部工具调用。
- 记录模型输出错误、工具调用失败和上下文管理问题。
- 编写基础测试，验证主要执行路径。

#### 任务四：建立学习与求职管理系统

- 在 Obsidian 中建立 Agent 技术知识库。
- 使用 PARA 组织学习资料、项目文档和求职记录。
- 使用 Zettelkasten 方式沉淀核心概念及其关系。
- 建立岗位投递记录，跟踪投递日期、招聘要求、面试进度和反馈。
- 每周复盘学习进度与项目进度。

**阶段交付：**

- Agent 岗位需求分析文档。
- Agent 技术学习路线图。
- 基础 Agent 实验项目。
- 个人技能差距清单。

### 阶段二：项目攻坚期

**目标：通过完整项目建立 Agent 工程实践能力，并形成具有辨识度的技术成果。**

#### 任务一：推进 pedyc-harness

围绕 Coding Agent 治理与独立验证方向持续完善项目。

重点工作：

- 明确 Task Contract、Policy、Execution、Independent Verification 和 Evidence 等核心模块的职责。
- 探索自然语言任务到结构化任务契约的转换机制。
- 设计 Agent 执行过程中的权限请求和人机协作机制。
- 建立可复现的执行记录、验证结果和 Evidence 审计机制。
- 研究与现有 Agent 宿主环境的集成方式。
- 通过真实任务验证架构设计，识别无法验证、无法约束或成本过高的部分。
- 完善项目文档、测试、示例和使用说明。

**项目目标：** 将 `pedyc-harness` 从架构探索逐步推进为具有明确使用场景、可运行实现和独立验证能力的工程项目。

#### 任务二：开发完整 Agent 应用

选择一个边界清晰、能够展示实际任务执行能力的应用场景。

候选方向：

- 面向开发者的代码分析与辅助工具。
- 能够调用多个工具完成信息收集和任务处理的研究助手。
- 面向特定业务流程的自动化 Agent。
- 具有任务规划、执行状态跟踪和结果验证能力的工作流系统。

实现过程中重点关注：

- 用户输入与任务定义。
- 任务规划和执行状态管理。
- 工具注册、调用及权限控制。
- LLM 输出解析和结构化校验。
- 错误处理、重试和任务恢复。
- 执行日志、Tracing 和结果评估。
- 必要时的人类确认与人工介入。
- 部署、测试和使用文档。

**项目目标：** 完成一个可以运行、演示和复现的 Agent 应用，而不仅仅是一个调用模型 API 的聊天界面。

#### 任务三：验证工程可靠性

- 为关键模块编写单元测试和集成测试。
- 设计典型任务、边界条件和失败场景。
- 记录任务成功率、工具调用错误率、执行耗时及模型调用成本。
- 对比不同提示词、工作流和验证策略的实际表现。
- 识别 Agent 自我报告与独立验证结果之间的差异。
- 对无法可靠自动判断的结果明确标记不确定性，并保留人工审核入口。

#### 任务四：完善项目展示材料

- 编写 README，明确项目解决的问题、核心能力和使用方式。
- 绘制系统架构图和关键执行流程图。
- 录制项目演示视频或制作可访问的在线 Demo。
- 整理关键技术决策及其替代方案。
- 记录真实测试结果、已知限制和后续计划。
- 整理 GitHub 仓库，确保代码、文档和示例具有可读性。

**阶段交付：**

- 可运行的 `pedyc-harness` 版本。
- 至少一个完整 Agent 应用。
- 自动化测试与验证记录。
- 项目 README、架构文档和演示材料。
- 可用于简历与面试的项目技术总结。

---

### 阶段三：求职收尾期

**目标：将学习与项目成果转化为招聘方能够理解和评估的能力证明。**

#### 任务一：完善简历

- 根据目标岗位要求调整简历内容。
- 突出 TypeScript、系统设计、工程实现和 Agent 项目经验。
- 使用具体的技术决策、实现内容和验证结果描述项目。
- 区分已经完成的能力与仍在探索的方向。
- 避免将尚未实现的功能描述为已经具备的能力。

#### 任务二：准备技术面试

重点准备以下主题：

- JavaScript、TypeScript 和 Node.js。
- HTTP、异步编程、并发控制和错误处理。
- LLM 基础、上下文窗口、Token 和模型调用机制。
- Prompt Engineering、Structured Output 和 Tool Calling。
- Agent 工作流、任务规划、状态管理和工具执行。
- RAG、Embedding、向量检索及相关评估方法。
- Agent 可靠性、Tracing、测试、验证和成本控制。
- 项目架构设计、技术选型和工程权衡。

重点练习：

- 使用 3～5 分钟清晰介绍自己的 Agent 项目。
- 解释关键模块为什么这样设计，以及有哪些替代方案。
- 说明项目中遇到的真实问题、失败案例和解决过程。
- 针对系统设计问题给出模块划分、数据流和异常处理方案。
- 对自己没有实践过的技术明确说明认知边界。

#### 任务三：持续投递与面试

- 建立目标公司和岗位清单。
- 根据岗位要求调整简历中的项目描述与技术重点。
- 持续进行岗位投递，记录投递时间和反馈。
- 对每次技术面试进行复盘，整理不会的问题和回答不足之处。
- 根据反馈调整学习优先级和项目完善方向。
- 在条件允许时，考虑 Agent 应用开发、LLM 平台开发及相关 AI 工程岗位作为相邻职业入口。

#### 任务四：完成 Offer 决策

收到 Offer 后，综合考虑：

- 工作内容是否涉及 Agent、LLM 应用或相关工程系统。
- 技术栈与个人长期发展方向的匹配程度。
- 团队的工程实践、代码质量和技术成长环境。
- 薪资待遇、工作地点、工作时间和其他合同条件。
- 岗位对未来技术发展和职业路径的支持程度。

**阶段交付：**

- Agent 工程师求职简历。
- 技术面试知识库。
- 项目介绍与系统设计材料。
- 岗位投递与面试复盘记录。
- Offer 评估记录及最终入职安排。
