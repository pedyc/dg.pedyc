## 目标

建立对 AI Agent 基本概念、核心特征与整体架构的理解，能够从系统设计的角度解释 Agent 如何接收任务、进行决策、调用工具并根据执行结果推进任务。

## 成功标准

- [x] **概念理解**：能够脱稿解释 Agent、LLM、Tool、Environment、Orchestrator、Memory、Context 等基本概念，以及 Agent 与普通 LLM 调用的区别。 ✅ 2026-09-23

> - LLM：是负责理解和生成语言的模型，本身主要负责根据输入上下文生成输出
> - Agent：Agent = LLM + 上下文 + 工具，LLM负责思考，上下文负责感知，工具负责能力。是一个能够围绕目标进行决策，并通过行动与环境交互，以完成任务的系统
> - Tool：是Agent可以调用的外部能力，让Agent能够对环境产生影响或者获取外部信息
> - Environment：是Agent所处并与之交互的环境
> - [[Orchestration]]：负责协调Agent系统中的组件执行和状态管理，按照系统规则推进任务
> - Memory：用于保存可能跨越当前会话的持久化记忆
> - Context Manager：Agent在每轮会话中选择提供给LLM的Context
> - Agent与普通LLM调用的区别：LLM主要负责生成/推理，Agent则是==围绕目标，通过感知、决策二和行动与环境进行循环交互==

- [x] **架构表达**：能够独立绘制并标注一张基本 Agent 架构图，说明各模块的职责及其关系。 ✅ 2026-09-23
![[Agent Architecture.excalidraw]]
- [x] **运行流程**：能够解释 Agent 从接收任务、获取上下文、决策、执行动作、观察结果到结束任务的基本流程。 ✅ 2026-09-23

> 接收任务→获取上下文→决策→执行动作→观察结果→判断终止

- [x] **设计分析**：能够结合一个具体任务，分析 Agent 的目标、可用工具、执行环境、反馈机制及终止条件。 ✅ 2026-09-23

> 具体任务：用户输入「给项目中的登录按钮增加 loading 状态」，Agent 需要读取代码、修改文件，并能够运行测试。
> Agent目标：登录请求进行时显示loading状态；请求结束后恢复正常；请求期间防止重复提交
> 可用工具：read_file、search_code、edit_file、run_command、git_diff
> 执行环境：项目代码仓库、文件系统、Node.js运行环境、测试框架及相关开发工具
> 反馈机制：通过文件读取结果了解现实实现；通过工具执行结果了解修改是否成功；通过测试、类型检查和Git Diff检查实现情况
> 终止条件：代码修改完成，相关验收条件得到验证，且没有尚未处理的阻塞问题。若验证失败，则继续修复或报告问题；不能仅凭LLM自我声明认定任务完成
