## 问题

LLM 如何理解 Context？为什么两条冲突的信息会影响 Agent 决策？按照一般逻辑，不是应该取最近的信息吗？

## 回答

一般直觉是：

> 最近的信息应该优先。

但 LLM 不是这样工作的。
它不会自动按时间排序，也不会自动判断哪条更新、哪条更权威。它只是==在当前 Context 上做概率性推理==。

LLM 会基于整个可见 Context 进行推理，但不同位置的信息并不一定具有相同的影响，而且模型本身不会自动为信息建立我们期望的"真实性、时效性、优先级"体系。

---

### 1. LLM 如何理解 Context？

LLM 不是数据库，也不是规则引擎。

它理解 Context 的方式是：

> **把整个 Context 当作一个整体，基于训练中学到的模式，预测下一步最可能输出什么。**

它不会：

- 自动给信息打时间戳
- 自动判断哪条更新
- 自动识别哪条更权威
- 自动解决矛盾

它只会：

- 看哪些信息在上下文中更显著
- 看哪些模式和训练数据更一致
- 看哪些信息在当前位置更"顺"

所以，**"最近"不等于"优先"。**

---

### 2. 为什么"取最近"这个逻辑不成立？

"取最近"是人类在数据库或版本控制中的习惯。

但在 LLM 中：

- Context 是平铺的文本，不是带时间戳的记录
- 模型没有内置的"版本比较器"
- 模型不知道哪条是"最新写入"
- 模型也不知道哪条是"旧版本残留"

除非你显式告诉它：

```text
[最新] 项目使用 Vue
[过期] 项目使用 React
```

否则模型不会自动按时间取最新。

---

### 3. 位置会影响注意力，但不等于优先级

LLM 对 Context 中不同位置的信息，注意力确实不同。

常见现象：[[Lost in the Middle现象|lost in the middle]]

- 开头和结尾的信息更容易被注意
- 中间的信息容易被忽略
- 重复出现的信息更容易被强化
- 表述更具体的信息更容易被采用

所以：

> **位置影响注意力，但不等于逻辑优先级。**

如果旧信息在结尾，新信息在中间，模型可能反而采用旧信息。

---

### 4. 冲突信息为什么会影响 Agent 决策？

因为 Agent 的决策不是一次性的，而是多轮循环。

冲突信息会导致：

**第一轮：模型选一个版本**

```text
Context:
  文档：React
  用户：Vue
```

模型可能选 React，也可能选 Vue，还可能混合。

**第二轮：基于错误版本执行**

```text
选 React → 读 React 文件 → 修改 React 组件
```

**第三轮：工具结果与 Context 冲突**

```text
Tool Result：项目里没有 React 文件
Context：文档说 React
```

模型这时可能：

- 继续相信文档
- 怀疑工具结果
- 尝试两者兼容
- 反复摇摆

**结果：**

- 决策不稳定
- 多轮循环无法收敛
- 错误累积
- 成本飙升

---

### 5. 为什么模型不直接问"哪个对"？

因为 LLM 的默认行为是：

> **继续生成，而不是停下来质疑上下文。**

它被训练成"根据给定信息完成任务"，而不是"先审核信息是否矛盾"。

除非 Prompt 明确要求：

```text
如果 Context 中存在冲突，请先指出冲突，不要直接执行。
```

否则它会倾向于直接选一个看起来合理的版本继续。

---

### 6. 冲突信息影响决策的四个机制

| 机制 | 说明 |
|---|---|
| 无时间感知 | 模型不知道哪条更新 |
| 无权威判断 | 模型不知道哪条更可信 |
| 位置偏差 | 位置影响注意力，但不代表优先级 |
| 多轮累积 | 错误版本会在后续循环中放大 |

---

### 7. 怎么让模型正确决策？

核心原则：

> **不要指望模型自动裁决冲突，要显式告诉它结论和优先级。**

推荐做法：

1. **标注时效**

```text
[最新] Vue
[过期] React
```

2. **标注权威来源**

```text
以最新代码为准，文档仅供参考。
```

3. **显式给出裁决**

```text
冲突已确认：使用 Vue，忽略 React。
```

4. **移除过期版本**
	 如果确认无用，直接删除。

5. **要求模型先检查冲突**

```text
如果发现 Context 中有冲突，先列出冲突，再请求确认。
```

---

### 8. 总结

LLM 不会自动"取最近的信息"，因为：

- 它没有时间感知
- 它没有版本比较能力
- 它没有权威判断
- 它只是基于整个 Context 做概率推理

冲突信息之所以影响 Agent 决策，是因为：

- 模型可能选错版本
- 错误会在多轮循环中累积
- 模型倾向于继续生成，而不是停下来质疑

一句话：

> **LLM 不是按时间取最新，而是按概率取最顺。冲突信息不会自动被解决，只会被模型随机选择或混合。**
