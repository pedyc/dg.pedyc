## 问题

压缩 Context 时，如何避免丢失关键信息？

## 回答

压缩 Context 的风险不是"变短"，而是：

> **把关键信息压掉了，模型却不知道。**

所以核心思路是：**压缩可以丢细节，但不能丢决策依据。**

可以从以下七个方面避免丢失关键信息。

### 1. 先标记关键信息，再压缩

不要直接对整段 Context 做摘要。

先分类：

- **必须保留**：目标、约束、当前状态、关键事实
- **可以压缩**：过程、日志、全文、历史细节
- **可以删除**：重复、过期、无关信息

**原则：**

> 先判断价值，再做压缩。

---

### 2. 压缩"过程"，保留"结论"

多轮循环中，过程往往很长，但结论很短。

不推荐保留：

```text
调用工具 A → 返回日志 → 分析 → 调用工具 B → 失败 → 换方案 C
```

推荐保留：

```text
已尝试 A、B，均失败；当前采用 C。
```

**原则：**

> 历史用于避免重复，不需要逐字保留。

---

### 3. 保留约束和边界，不压缩

约束类信息通常很短，但一旦丢失，方案就可能不可用。

例如：

- 不能引入新依赖
- 必须兼容旧版本
- 不能修改数据库 schema
- 必须保持 API 向后兼容

**原则：**

> 约束宁可重复，不可丢失。

---

### 4. 保留冲突和优先级

压缩时最容易丢掉的是"谁优先"。

例如：

```text
旧文档：React
用户最新确认：Vue
```

压缩后不能只剩：

```text
技术栈：React / Vue
```

而应保留：

```text
技术栈：Vue（用户最新确认，优先于旧文档）
```

**原则：**

> 冲突信息压缩后，必须保留结论和优先级。

---

### 5. 保留来源和时效

压缩后的信息如果失去来源，模型就无法判断可信度。

推荐保留：

```yaml
source: src/pages/Login.tsx
updated_at: 2026-10-04
confidence: high
```

**原则：**

> 信息可以压缩，来源和时效不能丢。

---

### 6. 用"摘要 + 指针"代替全文

不要只给摘要，也不要只给全文。

更好的方式是：

```text
摘要：登录校验逻辑在 handleSubmit 中，未处理空值。
原文位置：src/pages/Login.tsx:42-80
```

这样既省空间，又保留了可回溯性。

**原则：**

> 压缩后仍要能找回原文。

---

### 7. 压缩后做一次"缺失检查"

压缩完成后，问四个问题：

1. 目标还在吗？
2. 约束还在吗？
3. 当前状态还在吗？
4. 关键事实和来源还在吗？

如果任一缺失，模型就可能跑偏。

**原则：**

> 压缩不是终点，校验才是。

---

## 一个实用模板

压缩后的 Context 可以长这样：

```yaml
task:
  goal: 修复登录页面 Bug
  success: 登录流程正常，测试通过

constraints:
  - 不能引入新依赖
  - 保持 TypeScript 类型完整

state:
  current: 已定位到表单校验逻辑
  tried:
    - 修改 useState 初始值 → 无效
  remaining:
    - 修复校验
    - 补充测试

facts:
  - file: src/pages/Login.tsx:42-80
    summary: handleSubmit 未处理空值
    source: 最新代码
  - error: "TypeError: cannot read 'value' of undefined"

priority:
  - 用户最新描述 > 旧文档
```

---

## 总结

压缩 Context 时避免丢失关键信息：

1. 先标记关键信息，再压缩
2. 压缩过程，保留结论
3. 约束和边界不压缩
4. 保留冲突和优先级
5. 保留来源和时效
6. 用"摘要 + 指针"代替全文
7. 压缩后做缺失检查

一句话：

> 压缩可以丢细节，但不能丢目标、约束、状态、结论和来源。
