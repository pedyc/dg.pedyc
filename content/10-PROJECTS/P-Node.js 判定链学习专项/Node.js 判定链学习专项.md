## 目标

不学会怎样：能把事件循环的六个阶段背出来，却在服务卡住时说不出是哪一步的判断错了——把卡顿笼统归给 CPU，或把一次同步读文件当成「只是这次请求慢一点」。按 API 分类记知识点只能逐项回忆，没法从一次请求的现象倒推到该改哪一层。

判定链：一次请求的一生，收包到齐 → 分发入业务 → 落到处理代码 → 异步结果回来 → 响应写出 → 收尾放手。

| 环节 | 判什么 | 判错的代价 |
|:--|:--|:--|
| 收包到齐 | 这坨字节算不算一条完整、合法的报文，边界在哪、收完了没 | 就在收包这步露：把没收全的当整条 → 解析错位、400；或一直判「没完」→ 请求悬挂，根本进不了业务 |
| 分发入业务前 | 交给哪段逻辑、它有没有资格被放行 | 在分发这步露：交错 handler 或放了越权 → 直接吐出错响应或不该给的数据，业务还没跑就错了 |
| 落到处理代码 | 是同步阻塞还是异步等待，要不要把 event loop 让出去 | 不在本请求露，在同时到达的其他请求那步炸：单线程被占死 → 并发延迟雪崩、集体超时 |
| 异步结果或错误回来 | 回调对得上哪个请求上下文、异常有没有被接住、要不要就此终止 | 在结果落地这步露：没接住的异常冒泡 → 进程退出，或本请求永不返回、客户端一直干等 |
| 响应写出 | 头还能不能改、是不是只写这一次、end 掉还是 keep-alive 复用 | 在写出这步露：头已发又改或写两次 → headers already sent；该 end 没 end → 客户端等不到结束，或复用连接把残留串给下一请求 |
| 收尾放手 | 占着的句柄、连接、流是释放还是归还池，定时器与监听摘不摘 | 不在本请求露，到后续第 N 个请求才现形：连接与 FD 耗尽、内存涨到 OOM，而前面每个请求看着都正常 |

不做什么：链挡不住的几件事——语言语法与引擎编译归 [[JavaScript]] 与 [[V8 引擎]]，浏览器宿主归 [[浏览器]]，框架与路由约定的用法归 [[NextJS]]，没有文件系统与线程池的运行时归 [[Edge Runtime]]。它们与本链并行，不是链上的环节。

## 成功标准

> 一行一个 KR，判据要能被别人验证。三关与上面六个环节不必一一对应。未过的那一行，末列写一句接不上的判断，右边落到链接。

| 关键结果 | 判据 | 怎么验 | 结果 | 缺的那一块 → 落成什么 |
|:--|:--|:--|:--|:--|
| 不看笔记，从头讲一遍一次请求在 Node 里的六个判断关口 | 说清每一环的判断归谁做、判错在第几步露出来 | 口述 5 分钟；必覆盖①报文边界由谁判②让不让出 event loop ③错误由谁兜底④句柄何时归还；必答反例：同步读文件为什么不只是「这个请求慢一点」 |  |  |
| 任给一段服务代码，指出它会卡在哪一环 | 能说出另一种写法会在哪一步坏掉，而不是只说「这样不好」 | 现场抽三段（同步 `fs.readFileSync`、大 JSON 序列化、`process.nextTick` 递归）；必答反例：把 CPU 密集任务丢进 libuv 线程池为什么仍然会卡 |  |  |
| 给一个线上卡顿现象，倒推是哪一环的判断错了 | 从「哪些请求慢、CPU 与延迟是否同向」推出是事件循环、I/O 还是句柄泄漏 | 以「CPU 正常但 P99 突然抬高」开场口述；必答反例：为什么事件循环延迟比 CPU 占用更能反映服务卡顿 |  |  |

## 读什么

依据：两稿盲写后合并。G1 只给领域名，从「一次请求的一生」画出六道判断关口；G2 只给库外锚点，按 [Node.js 官方学习路径](https://nodejs.org/en/learn) 与 [API 文档目录](https://nodejs.org/api/) 的分类逐个环节问「要下这个判断，事先得知道什么」，两稿互不可见。第三步才对库：库里已有对应笔记的用文件名实链，没有的按目标形态拟标题留灰链。灰链即待写清单，不标「待写」，链接后只写动机。

两稿的差集最值得先读：G2 按官方类目转抄，覆盖的是模块与 API；G1 从链上推出的「分发放行」「句柄归还」「连接复用残留」几簇，官方目录里没有对应类目，因此全部落成灰链。

### ① 收包到齐

- [[HTTP]] — 报文边界的上游口径，本环只取「一条报文怎么算收完」
- [[一次 TCP 收包不等于一条完整 HTTP 报文]]——按字节到达顺序解析，会把半条报文当成整条
- [[报文边界由 HTTP 解析器判定，早于用户代码]]——业务 handler 拿到的已是解析结果，边界不归它判
- [[req 是 IncomingMessage 可读流]]——请求体是流不是字符串，「收完」的时机因此落在流事件上
- [[chunked 与 Content-Length 互斥]]——两种定界方式同时出现，边界判断就没有唯一答案
- [[Header 名不区分大小写]]——头解析在业务之前完成，取错大小写归不到业务层

### ② 分发入业务前

- [[路由分发由用户代码决定，Node 内置 http 不提供路由]]——放不放行是应用层的判断，不是运行时给的
- [[身份与限额判断必须发生在请求体读取之前]]——读完再拒绝，带宽与内存已经被消耗掉
- [[权限模型默认关闭]]——不显式开启，进程默认能读整个文件系统

### ③ 落到处理代码

- [[事件循环]] — 通用任务队列模型，Node 的六阶段差异才是本环要补的
- [[宏任务]] — 每轮取一个，是阶段推进的刻度
- [[微任务]] — 每阶段后整队清空，与 nextTick 的先后是常见误判
- [[V8 引擎]] — 引擎负责执行、运行时负责调度，先划清分工
- [[libuv]]——线程池与 I/O 多路复用的分工，正是「语言之外那一层」
- [[Node 事件循环阶段]]——timers / poll / check / close 的顺序，判断「让不让出」的坐标系
- [[libuv 线程池只承接部分阻塞操作，网络请求不走线程池]]——把网络请求算进线程池，会误判扩容方向
- [[线程池默认大小为 4]]——调大不是免费的，代价落在内存与上下文切换
- [[同步 API 阻塞事件循环]]——判断的是「这段会不会占住唯一线程」，不是「这个 API 快不快」
- [[CPU 密集任务阻塞事件循环]]——正则回溯与大 JSON 序列化同属这一类
- [[一次同步读文件占住的是整个进程，不只当前请求]]——本环判错代价的原型
- [[nextTick 队列先于微任务清空]]——递归调用会把 I/O 饿死
- [[setImmediate 在 check 阶段执行]]——与 `setTimeout(fn, 0)` 的先后在 I/O 回调内外相反
- [[Buffer]]——定长字节块，判断「一次搬多少」的底座
- [[Stream]]——分块搬运，与 Buffer 是全量还是分块的分岔
- [[背压]]——生产快于消费时由谁减速，判断落在流的接口上
- [[cluster 是多进程非多线程]]——绕过单进程上限与绕过 CPU 阻塞不是同一档
- [[共享内存需 SharedArrayBuffer]]——worker_threads 与多进程的分界在这里
- [[child_process 经 IPC 序列化]]——隔离强，代价落在消息序列化

### ④ 异步结果或错误回来

- [[Promise]] — 语言侧的错误传播，与回调约定对照着读
- [[fs 回调为错误优先]]——第一参数约定是运行时的事实，不是库的设计
- [[try catch 抓不到回调里的异常]]——同步的 try 覆盖不到异步回调的栈
- [[未捕获异常默认退出进程]]——判「要不要就此终止」时的默认值
- [[uncaughtException 之后继续服务是不安全的]]——进程状态已不确定，继续服务是把错误扩散
- [[请求上下文靠闭包或 AsyncLocalStorage 传递，不靠全局变量]]——并发请求的回调共用一个进程
- [[async_hooks]]——异步资源的生命周期，用来定位「这个回调属于哪个请求」
- [[Diagnostics Channel]]——运行时埋点，与 async_hooks 的观察粒度不同
- [[相对路径基于 process.cwd() 解析]]——同一段代码在本地与 CI 可能指到不同文件

### ⑤ 响应写出

- [[res 须 end 才结束响应]]——不 end，客户端等不到结束
- [[响应头一旦发出就不能再改]]——headers already sent 的根因在写出时序
- [[keep-alive 复用连接时残留字节会串给下一请求]]——边界没清，错误落在下一个请求上
- [[HTTP2]] — 多路复用之后仍残留的传输层阻塞，用作「一次写出」的对照

### ⑥ 收尾放手

- [[流没被消费完时连接不会归还 keep-alive 池]]——连接复用的前提是流被读完或销毁
- [[未清理的定时器与监听器让请求上下文无法回收]]——泄漏不发生在本次请求
- [[FD 耗尽发生在第 N 个请求，前 N-1 个都正常]]——本环判错代价的原型
- [[retained size 才反映泄漏]]——浅层尺寸看不出谁在持有
- [[rss 含堆外内存]]——Buffer 在堆外，堆快照里看不到全部
- [[CPU profile 是采样统计]]——火焰图的「宽」是采样占比，不是精确耗时
- [[--inspect 不在首行暂停]]——调试器连上不等于停在起点

### 该读但不读（链外，排除）

- TypeScript 类型系统（「运行时不做类型检查」「类型注解被直接剥离」「枚举属不可擦除语法」）：编译期的事，链上没有一道关口要判它。
- 包管理与版本（「^ 不跨主版本」「lockfile 固定依赖树」「npx 先找本地 bin」「exports 限制子路径导入」）：发生在进程启动之前，不在一次请求里。
- 测试框架（「node:test」「--test 每文件独立进程」「skip 不计入失败」）：验证手段，不是运行时的判断。
- 安全加固（「path.join 不阻止 .. 穿越」「Math.random 非密码学安全」「allocUnsafe 不清零内存」）：属另一责任域，链上只保留「权限模型默认关闭」一条。
