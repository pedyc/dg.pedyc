## 背景

当前纯 Neovim 的配置由于插件过多、LSP 与 Debugger 维护成本高而显得繁琐复杂。我希望在享受 VSCode 强大生态（调试器、丰富插件、开箱即用的前端工具链）的同时，完整保留并复用 Neovim 高效的核心键位映射与编辑肌肉记忆。

## 核心目标

- [ ] 建立一套轻量化、专门服务于 VSCode 的 `vscode-neovim` 独立配置，剥离冗余的 UI 插件与独立 LSP。
- [ ] 统一 VSCode 原生快捷键与 Neovim 键位冲突，实现 90% 以上核心代码编辑与导航动作无缝切换。

**成功标准**：在 VSCode 中可顺畅使用 Neovim 模式进行全天日常编码，无明显键位冲突与输入卡顿，纯 Neovim 配置目录体积与加载时间减少 50% 以上。

## 战略地图

* **KR1：完成独立配置精简与插件集成**（权重 50%）
	* 搭建 `init.lua` 条件加载逻辑（通过 `vim.g.vscode` 区分独立模式与嵌入模式）。
	* 在 VSCode 中成功安装并跑通 `vscode-neovim` 插件。
* **KR2：键位映射统一与冲突消除**（权重 50%）
	* 迁移 Leader 键常用指令（文件树、全局搜索、格式化、代码跳转等）。
	* 解决 `Ctrl/Cmd` 组合键在 VSCode 与 Neovim 之间的捕获冲突。

## 执行计划

### 阶段一：准备与配置解耦

* [ ] 梳理当前 Neovim 中高频使用的键位映射（Keymaps）与核心动作清单。
* [ ] 在 `init.lua` 中引入 `vim.g.vscode` 判定，隔离 UI（Bufferline/Statusline）、LSP、Treesitter 渲染等 VSCode 已内置的功能。
* [ ] 在 VSCode 中安装官方扩展 `VSCode Neovim`（`asvetliakov.vscode-neovim`），并配置 Neovim 二进制执行路径。

### 阶段二：键位对齐与冲突调优

* [ ] 在 VSCode `keybindings.json` 中配置与 VSCode 内部命令的桥接（如通过 `workbench.action` 触发文件树展开、多光标等）。
* [ ] 配置 VSCode 下的 Leader 键组合（如 `<leader>ff` 触发 VSCode Quick Open，`<leader>ca` 触发 Code Action）。
* [ ] 处理滚动冲突与分屏导航（将 `Ctrl-w` 窗口跳转映射至 VSCode 编辑器组切换）。

### 阶段三：测试与归档

* [ ] 进行全流程编码测试（包含文件切换、全局搜索替换、多光标编辑、代码折叠）。
* [ ] 备份并归档精简后的 `init.lua` 与 VSCode `settings.json` / `keybindings.json`。
* [ ] 撰写个人工作流速查清单（Cheat Sheet）。
