## SOP：使用代理与抓包工具分析网络流量

建立一套分层化、标准化的网络流量捕获与调试操作流程，覆盖从轻量级浏览器接口检查到跨端 HTTPS 中间人解密及底层 TCP/IP 握手排查的全场景。

* **目标**：快速定位接口协议错误、Header/Cookie 异常、跨域拦截、SSE 流式中断以及 SSL/TLS 握手失败等网络通信问题。
* **实现**：按分层模型选用合适工具——应用层优先采用 Chrome DevTools 与 Charles/mitmproxy，传输层采用 Wireshark 配合 SSLKEYLOGFILE 解密。
* **问题溯源**：本 SOP 是 [[Q-如何系统化排查复杂网络环境下的请求异常与握手失败]] 的收敛成果——经过直接代码断点打日志与系统化抓包分析的实践对比，固化为标准流程。

---

### 适用场景

* 场景 1：Web/H5 前端联调阶段排查接口 4xx/5xx 错误、CORS 跨域预检（OPTIONS）阻断或 Header 缺失。
* 场景 2：移动端 App / 微信小程序与 Webview 容器通信抓包，需解密 HTTPS 明文载荷。
* 场景 3：大模型流式输出（SSE/WebSocket）出现数据阶段性卡顿、TCP 频繁重传或连接意外重置（RST）排查。

### 核心步骤

1. **步骤 1：工具选型与层级确认**
	* **Level 1（轻量应用层）**：针对当前浏览器页面，按 `F12` 打开 DevTools Network 面板。
	* **Level 2（中间人 HTTP 代理）**：需要断点修改数据、模拟慢网、或者抓取移动端 App/客户端请求时，使用 Charles、mitmproxy 或 Whistle。
	* **Level 3（链路/网络/传输层）**：当遇到连接被强行 Reset（TCP RST）、DNS 污染、TLS 握手阶段报错（无 HTTP 报文生成）时，使用 Wireshark。

2. **步骤 2：配置 HTTPS 中间人解密（针对 Level 2 工具）**
	* **PC 端配置**：在 Charles / mitmproxy 中启用 `SSL Proxying`，添加捕获规则为 `*:*` 或指定目标域名。
	* **安装并信任根证书（关键）**：
		* **桌面端**：导出工具自签名的 Root CA 证书，安装至系统钥匙串/受信任根证书颁发机构，勾选"始终信任此证书"。
		* **移动端（iOS / Android）**：手机连接同一 Wi-Fi，配置 HTTP 代理指向电脑 IP 与端口（默认 8888 或 8080）。浏览器访问代理专属地址（如 `chls.pro/ssl`）下载描述文件。
		* **系统证书激活**：iOS 需在【设置 → 通用 → 关于本机 → 证书信任设置】中手动开启完全信任；Android 7+ 需确保应用开启了 `<network-security-config>` 信任用户证书。

3. **步骤 3：多维度流量捕获与精准过滤**

	* **DevTools 过滤**：利用 `domain:api.example.com`、`status-code:500`、`method:POST`、`-mime-type:image/*` 快速缩小排查范围。
	* **Wireshark 显示过滤语法**：
		* 过滤指定 IP 与端口：`ip.addr == 192.168.1.100 && tcp.port == 443`
		* 过滤 TCP 异常状态：`tcp.analysis.retransmission`（重传）、`tcp.flags.reset == 1`（复位断开）
		* 过滤 HTTP 请求路径：`http.request.uri contains "/api/v1/chat"`

4. **步骤 4：数据断点注入与流量重写（Mock / Breakpoint）**

	* 在 Charles/Whistle 中使用 **Rewrite / Map Local**：
		* 将线上接口重定向至本地 Mock JSON 文件或开发服务器。
		* 在 Header 中追加 `Authorization` 或篡改 Cookie 测试权限边界。

5. **步骤 5：导出排查凭据**

	* 接口问题导出标准 **HAR（HTTP Archive）** 文件，供后端或跨团队复现排查；
	* 底层网络问题导出 **.pcap / .pcapng** 抓包文件并附带环境时间戳与解密密钥。

### 实践/示例

#### 1. 终端环境配置代理（抓取 Node.js / Python 脚本发出的网络请求）

Node.js 与部分 CLI 工具默认不走系统代理，需显式声明环境变量：

```bash
# 临时配置当前终端终端会话走 Charles/mitmproxy（假设端口为 8888）
export HTTP_PROXY="[http://127.0.0.1:8888](http://127.0.0.1:8888)"
export HTTPS_PROXY="[http://127.0.0.1:8888](http://127.0.0.1:8888)"

# Node.js 临时跳过自签名证书校验（仅限本地排查）
export NODE_TLS_REJECT_UNAUTHORIZED="0"

# 发起测试请求
curl -I [https://api.github.com](https://api.github.com)
```

#### 2. 配合 Chrome 导出 SSLKEYLOGFILE 实现 Wireshark 完美解密 TLS

针对现代 TLS 1.3 / HTTP/2 流量，若无法使用代理工具，可通过导出预主密钥在 Wireshark 中直接解密：

```bash
# macOS / Linux 启动 Chrome 并注入秘钥转储路径
export SSLKEYLOGFILE="$HOME/ssl_keys.log"
open -a "Google Chrome" --args --user-data-dir="/tmp/chrome_dev"

# Windows 命令提示符:
# set SSLKEYLOGFILE=C:\ssl_keys.log
# start chrome.exe
```

* **Wireshark 关联配置**：

进入【Preferences → Protocols → TLS】（旧版为 SSL），将 `(Pre)-Master-Secret log filename` 指向 `$HOME/ssl_keys.log`。抓包面板中原本加密的 `Application Data` 将直接被解析为 HTTP/2 或明文 HTTP。

#### 3. 命令行快速抓包（Linux 服务器环境配合 tcpdump）

```bash
# 捕获指定网卡 eth0 上 443 端口的数据包，保存为 traffic.pcap
sudo tcpdump -i eth0 -nn -s 0 tcp port 443 -w traffic.pcap

# 抓取指定主机并且排除 SSH (22端口) 数据包
sudo tcpdump -i any host 10.0.0.15 and not port 22 -c 1000 -w debug.pcap
```

### 常见坑点

* ⛔ **反模式：移动端抓包看到 `SSL Handshake Failed` / App 提示"网络连接不可用"**：
* **根因**：Android 7.0+ 默认不再信任用户级 CA 证书（User Certificates），仅信任系统级证书（System Certificates）；或者 App 开启了 **SSL Pinning（证书绑定）**。
* **对策**：开发包在 `res/xml/network_security_config.xml` 中配置 `<trust-anchors><certificates src="user"/></trust-anchors>`；对于已上线的 App，需通过 Frida / Xposed 脚本动态绕过证书绑定。
* ⛔ **反模式：在前端 DevTools 中看 SSE 流式接口一直处于 Pending 且没有任何分块输出**：
* **根因**：中间层 Nginx 或反向代理网关开启了 Gzip/缓冲区（`proxy_buffering on`），导致分块内容被缓冲，直至达到阈值或连接关闭才一次性吐出。
* **排查**：检查响应头是否包含 `X-Accel-Buffering: no` 与 `Content-Type: text/event-stream`。
* ⛔ **反模式：抓包分析完未关闭本地系统代理**：
* **根因**：抓包工具关闭后，操作系统网络设置中的代理配置未及时还原，导致浏览器与全局网络访问彻底报错（`ERR_PROXY_CONNECTION_FAILED`）。务必确认抓包工具正常退出或手动清理代理设置。
