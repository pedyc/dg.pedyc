## 🚀 P- 算法提升专项（前端面试向）

### 🎯 目标与触发条件

> [!summary]
> **触发场景**：当 **准备前端岗位面试** 或 **算法能力成为职业瓶颈** 时。
> **预期结果**：3 个月内，**掌握面试常考算法题型**，能独立解决 **LeetCode 中等难度题目**，**高频题熟练度达 90%**。

**成功标准**：
- ✅ 完成 **150+** 经典题（覆盖所有常考类型）
- ✅ 能 **15 分钟内** 写出中等题最优解
- ✅ 建立 **算法题解笔记库**（便于复习）
- ✅ 面试中算法轮 **通过率 ≥80%**

---

### 🛠 前置准备

#### 工具链

- [ ] **刷题平台**: [LeetCode](https://leetcode.com) 或 [力扣中国](https://leetcode.cn)（建议开会员，看企业题库）
- [ ] **代码环境**:
- VS Code + [LeetCode插件](https://marketplace.visualstudio.com/items?itemName=LeetCode.vscode-leetcode)（本地调试）
- 或直接网页刷题
- [ ] **笔记系统**: Obsidian 建立 [[算法题解模板]]（见下文）
- [ ] **可视化工具**: [VisuAlgo](https://visualgo.net)（理解数据结构动态过程）

#### 知识储备

- [ ] **JavaScript 基础**: 数组、对象、Map、Set、栈、队列的手动实现
- [ ] **时间/空间复杂度**: 能分析 O(1), O(n), O(log n), O(n²)
- [ ] **ES6+ 特性**: 解构、展开运算符、箭头函数的使用

#### 心态准备

- **接受 " 不会 "**: 算法是技能，不是天赋，10 道题后就会找到感觉
- **质量 > 数量**: 1 道题吃透 > 10 道题刷过
- **前端的优势**: 用熟悉的 JS 刷题，不用强求 C++/Java

---

### 🪜 核心流程

#### 阶段一：筑基期（第 1-2 周）—— 打地基，建立思维框架

**目标**：掌握基础数据结构，建立 " 题感 "

| 模块 | 核心知识点 | 推荐题量 | 代表题目 |
|------|-----------|---------|---------|
| **数组/字符串** | 双指针、滑动窗口、前缀和 | 10-15 | 两数之和、无重复最长子串、三数之和 |
| **链表** | 反转、合并、环形检测 | 8-10 | 反转链表、合并有序链表、环形链表 |
| **哈希表** | 计数、映射、缓存 | 5-8 | 有效的字母异位词、两数之和 |
| **栈/队列** | 括号匹配、单调栈 | 5-8 | 有效的括号、每日温度 |

**每日节奏**：

```bash
⏰ 早上 30分钟：复习昨天错题（🔄 低脑力）
⏰ 上午 1小时：学习新知识点 + 看题解（⚡ 高专注）
⏰ 下午 1小时：独立刷题 2-3 道（⚡ 高专注）
⏰ 晚上 15分钟：整理笔记，记录收获（🔄 低脑力）
```

**阶段产出**：
- [ ] [[算法题解模板]] 创建并试用
- [ ] 完成 30 道基础题，建立 [[算法-筑基期错题集]]

---

#### 阶段二：攻坚期（第 3-6 周）—— 覆盖核心题型

**目标**：掌握面试高频考点，能独立解决中等题

| 模块 | 核心知识点 | 推荐题量 | 代表题目 |
|------|-----------|---------|---------|
| **二叉树** | 遍历（前中后层）、DFS/BFS、路径总和 | 10-15 | 二叉树遍历、最大深度、路径总和 |
| **递归/回溯** | 排列、组合、子集、岛屿问题 | 10-12 | 全排列、组合总和、岛屿数量 |
| **动态规划** | 斐波那契、背包问题、最长子序列 | 10-15 | 爬楼梯、打家劫舍、最长递增子序列 |
| **排序/查找** | 快排、归并、二分查找 | 8-10 | 排序数组、搜索旋转排序数组 |

**每日节奏**：

```bash
⏰ 早上 30分钟：复习错题本（🔄）
⏰ 上午 1.5小时：攻克一个题型（如：今天专攻回溯）（💡 高创意）
⏰ 下午 1小时：刷 2-3 道同类题巩固（⚡）
⏰ 晚上 30分钟：整理题型模板（🔄）
```

**关键技巧**：
- **题型模板化**：每种题型总结一个 " 解题模板 "（如回溯 = 递归 + 路径记录 + 撤销）
- **一题多解**：同一道题尝试暴力 → 优化 → 最优解
- **前端视角**：有些题可以用 JS 特有解法（如用 Map 代替对象）

**阶段产出**：
- [ ] [[算法-题型模板手册]]（回溯模板、DP 模板等）
- [ ] 完成 80 道题，累计 110 题
- [ ] 能独立画出递归树/状态转移图

---

#### 阶段三：冲刺期（第 7-10 周）—— 真题演练 + 查漏补缺

**目标**：适应面试节奏，强化薄弱点

| 模块 | 核心任务 | 重点 |
|------|---------|------|
| **高频题二刷** | 重复刷前两个阶段的错题和经典题 | 熟练度 > 速度 |
| **企业题库** | LeetCode 企业题库（目标公司） | 针对性练习 |
| **模拟面试** | 限时 20-25 分钟/题，口述思路 | 表达清晰度 |
| **前端特有题** | 手写 Promise、防抖节流、LazyMan | 结合 JS 特性 |

**每日节奏**：

```bash
⏰ 早上 1小时：限时模拟 2 道题（⚡）
⏰ 上午 1小时：企业题库专项（⚡）
⏰ 下午 1小时：二刷错题，总结套路（🔄）
⏰ 晚上 30分钟：口述今天题目的解题思路（💡）
```

**阶段产出**：
- [ ] [[算法-高频100题]] 熟练度达 90%
- [ ] [[算法-模拟面试记录]]（记录卡壳点）
- [ ] [[前端手写题合集]]

### ⚠️ 常见坑点与排错

#### 前端刷题特别注意事项

| 坑点 | 症状 | 解决方案 |
|------|------|----------|
| **JS 精度问题** | 大数相加出错 | 用 BigInt 或字符串模拟 |
| **引用类型陷阱** | 回溯时结果全空 | 拷贝路径：`path.slice()` 或 `[…path]` |
| **递归超时** | LeetCode 报 TLE | 加备忘录（记忆化搜索） |
| **this 指向问题** | 类方法中 this 为 undefined | 用箭头函数或 bind |
| **数组越界** | 访问 `nums[-1]` | 先判断索引有效性 |

#### 刷题心态问题

| 现象 | 原因 | 对策 |
|------|------|------|
| 看题解能懂，自己写不出 | 被动学习 | 看题解后合上屏幕，自己默写 |
| 一道题卡 2 小时 | 死磕过度 | 30 分钟无思路就看题解，搞懂后再默写 |
| 刷过的题又忘 | 没有间隔重复 | 用 [[算法-错题本]] 定期复习 |
| 焦虑别人刷了 500+ | 横向比较 | 150 题吃透 > 500 题水过 |

### 🧬 原理与优化

#### 底层逻辑

本流程基于 **刻意练习** 和 **间隔重复** 原理设计：
- **阶段一**：建立认知框架（知道有什么）
- **阶段二**：模式识别（知道怎么解）
- **阶段三**：自动化（不用想就能写）

#### 前端特有优势

- 用 **JS 刷题** 更贴近日常工作，一举两得
- 很多算法思想可以应用到 **性能优化**（如双指针优化渲染）
- 手写题直接考察 JS 功底

#### 优化日志

- **2026-03-09**: 初版建立，参考 Google、Meta 前端面经
- **待优化**: 根据实际进度调整各阶段题量
