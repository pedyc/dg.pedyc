## 目标

不学会怎样：面试被问到缓存只能照背清单，一追问第二层就露底。这些词不在同一层——强缓存、协商缓存、Memory Cache、Disk Cache、Service Worker、Cache API、IndexedDB、localStorage、Cookie、CDN 有的存 HTTP 响应，有的存应用数据，有的其实只是一种结果。按介质排成表只能逐项记忆，没法推理。

**判定链**：一份副本的一生，谁写它 → 谁先答 → 谁判它新鲜 → 谁判它作废 → 作废后付什么。

| 环节 | 判什么 | 判错的代价 |
|:--|:--|:--|
| 写入 | 这份副本存的是响应还是应用数据，键是谁 | 在错的地方找它，或在错的层改它 |
| 拦截 | 一次请求哪一层先答（SW → 内存 → 磁盘 → 协商 → 源站） | 顺序说反，后面每一句推理都错 |
| 新鲜度 | 这份副本还算不算新鲜，这个判断是谁算的 | 多一次往返，或拿到旧数据 |
| 失效 | 谁有权宣布它作废（浏览器 / 页面 / CDN / 源站） | 「以为清了其实没清」，发版后旧页面不消失 |
| 回源 | 作废之后付什么（往返、重建、降级） | 白屏，或给出不完整的降级 |

**链外不学**：

- **同名异域**：后端 Redis、集群 ETag 调优、LLM 的 KV Cache 与浏览器侧只是同名。集群 ETag 答到「各节点生成口径不一致」为止。
- **不是机制**：`preload` / `prefetch` / `preconnect` 属于加载调度，理由见 [[缓存机制相关问题]] 第 4 组。
- **不背厂商配置与代码片段**：只需知道边缘有一份副本、作废要主动 purge；Nginx 片段与示例合集不产生判断依据。也不搭环境、不写代码、不做演示。

## 成功标准

> 一行一关，判据要能被别人听见。三关与上面五个环节不必一一对应。未过的把「哪一步判断接不上」写进最后一列，并落成一条链接。

| 关键结果 | 判据 | 怎么验 | 结果 | 缺的那一块 → 落成什么 |
|:--|:--|:--|:--|:--|
| 不看笔记，从头讲一遍一次请求 | 说清拦截顺序，并说清每一层命中后哪些层不再被问到 | 口述 5 分钟；必覆盖①拦截顺序②命中即返回③304 是分支不是第三档；必答反例：强缓存是不是零成本 | | |
| 任给一个机制，十分钟归位 | 答出四问（存什么、谁判它失效、失效后付什么、代码能否读写），并指出失效归哪一层、手上有没有开关 | 现场抽三个陌生物（`stale-while-revalidate`、`Vary`、`storage.persist()`）当场归类；必答反例：强缓存、协商缓存、不缓存是不是三档 | | |
| 发版后旧副本，定位到层 | 四类成因（HTML 误配长时效、CDN 未 purge、SW 缓存优先、查询参数没穿透）各说清「哪份副本没被作废」 | 以「清了缓存怎么还是旧的」开场口述；必答反例：强缓存发出去能不能撤回 | | |

## 学习路径（只读和口述）

先读总览 [[浏览器缓存与客户端存储体系]]（节点与关系的全貌），再按四段走。段的切法跟链不同——链按判断排，读按表达排：先学协议层才读得懂存放位置，尽管「写入」在链上排第一。

| 段 | 对应环节 | 读什么 | 自测 |
|:--|:--|:--|:--|
| 1. 协议层 | 新鲜度 · 失效 | [[HTTP缓存机制]] → [[HTTP强缓存]] → [[HTTP协商缓存]] → [[新鲜度]] → [[Cache-Control]] / [[ETag]] / [[Last-Modified]] | 为什么 `max-age` 配了一年还是发请求？`immutable` 省掉的是哪一步？ |
| 2. 存放位置与代码层 | 拦截 | [[Memory Cache 与 Disk Cache]] → [[Service Worker]] → [[Cache API]] | SW 的 `fetch` 拦截和 Disk Cache 谁先？离线时 `no-store` 的响应还能不能拿到？ |
| 3. 存储层 | 写入 | [[Web Storage]] → [[Cookie]] → [[IndexedDB]] | 为什么 Cookie 拖慢所有同源请求？`localStorage` 为什么不该存大对象？ |
| 4. 发版一致性 | 失效 · 回源 | [[Content-Hash]] → [[CDN]] → [[前端静态资源多级缓存配置规范]] → [[RTT]] | 发版瞬间哪几份副本会旧？谁负责让它们变新？ |

想看一版连贯的口语叙述，读 [[前端缓存怎么分类]]——两根轴、四问、分类与易错说法都在里面，本页不再复制一份。面试侧上下文可对照 [[前端面试知识清单]]、[[前端面试常见问题]] 与 [[面试提问的三层递进]]。

外部真值：[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111) 协议层唯一出处（中文教材的三档分法在它里面找不到）· [MDN: HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Caching) 概念到指令的对照 · [MDN: Storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) 浏览器判淘汰那层的规则原文 · [web.dev: Love your cache](https://web.dev/articles/love-your-cache) 各存储 API 的取舍。

## 自测清单

能不看笔记讲出来就打勾。这条清单是整链的验收，不承担间隔复习——复习走 Anki（atomic 进卡），这里只在面试前过一遍。成体系的过题在 [[缓存机制相关问题]]（七组 40 问），本页不复制题目。

**已知缺口**：九条里八条落在拦截、新鲜度、失效三环，「回源」与「写入（应用数据侧）」各缺一条。待补两条：作废之后回源的代价；Cookie / localStorage / IndexedDB 各存什么、谁判它过期。

**第一遍做基线**：不看笔记能讲几条，卡住的把题号记下来（约 30 分钟）；随后过题单第 6 组（发版与 CDN），它最容易被追问到第二层，答不出的当场回填进「待探索」。九条是整链的题、不落具体环节，卡住时按环节回学习路径找那一段。

- [ ] 一次请求按什么顺序被拦截，命中即返回
- [ ] 强缓存、协商缓存、304 各自省掉了什么
- [ ] 四层失效判定权分别归谁，各举一个「以为清了其实没清」的例子
- [ ] `no-cache` / `no-store` / `max-age=0` / `immutable` 各自关掉哪一档
- [ ] `ETag` 与 `Last-Modified` 的差别，以及同时在场时听谁的
- [ ] 为什么 Memory Cache 和 Disk Cache 不是两种缓存
- [ ] 入口 HTML 与哈希资产为什么配两套完全不同的策略
- [ ] 发版后旧副本的四类成因分别落在哪一层
- [ ] 任给一个新机制，十分钟填出四问
