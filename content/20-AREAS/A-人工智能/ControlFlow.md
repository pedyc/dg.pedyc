## 什么是控制流（Control Flow）？

控制流描述的是：程序接下来执行什么，以及执行顺序由什么决定。

## 控制流和AgentLoop是什么关系？

AgentLoop是「宏观骨架」，决定了Agent整体上「循环决策-行动」这件事；ControlFlow是「调度逻辑」，既存在于AgentLoop这个宏观层（循环什么时候停、走哪个分支），也存在于每一轮循环内部（先调哪个工具、失败了怎么办、要不要重试、并行还是串行）。

在AgentLoop中，「谁控制AgentLoop」和控制流分析的最重要的部分。

## 控制流简化流程

```bash
User Task
   │
   ▼
Context
   │
   ▼
LLM Decision 
   │
   ▼
Rutime Control 处理模型输出
   │
   ├── Tool Call ──► 权限检查 ──► 执行工具
   │                                     │
   │                                     ▼
   │                               Observation 获取执行结果
   │                                     │
   │                                     ▼
   │                               更新上下文
   │                                     │
   │                                     └──► 再次调用 LLM
   │
   ├── 结束请求 ──► 检查终止条件 ──► 结束或继续
   │
   └── 其他输出 ──► 按运行时规则处理
```

- LLM Decision：根据当前Context决定下一步做什么
- Runtime Control：控制AgentLoop是否以及如何执行
- Environment / Tools Action：真正改变或观察环境

## 示例：给登录按钮添加loading状态

Agent 执行过程中发生以下事件：

1. LLM 请求搜索登录按钮。
2. Runtime 执行搜索工具。
3. 工具返回登录组件位于 `LoginForm.tsx`。
4. LLM 请求读取文件。
5. Runtime 执行读取工具。
6. LLM 请求修改代码。
7. Runtime 检查权限并执行修改。
8. LLM 请求运行测试。
9. 测试失败，返回错误信息。
10. LLM 根据错误信息提出修复方案。
11. Runtime 执行修复并重新运行测试。
12. 测试通过，LLM 提出结束请求。
13. Runtime 根据运行状态和任务终止条件决定结束，并汇总执行结果。

这里有两个值得注意的地方：

**第一，控制流是动态的。**
Agent 并不是预先固定执行"搜索、读取、修改、测试"四个步骤。它可能根据搜索结果、代码内容和测试反馈调整后续行动。

**第二，模型的决策和 Runtime 的执行相互配合。**
模型决定下一步想做什么，Runtime 根据实际机制处理请求并推进执行过程。

## FAQ

1. 如果 LLM 输出了一个工具调用请求，但 Runtime 因为权限不足拒绝执行，那么控制流发生了什么变化？LLM 的请求是否等于工具已经执行？

> LLM的请求不等于工具已执行。当LLM输出一个工具调用请求，控制流进入权限判定，权限判定不足，控制流进入工具请求失败流程，将信息回传给LLM。

2. 如果工具执行失败，Runtime 一定要让 LLM 重新尝试吗？还是可以直接终止？请解释你的判断依据。

> 这要看控制流设计，如果是一个确定性的任务，工具执行失败一般说明结果失败，可以直接终止。如果对于不确定的任务，工具执行失败不代表结果失败，可以让LLM重新决策调整路径。

3. 假设 LLM 输出"任务已经完成"，但 Runtime 发现必需的测试尚未执行。此时应该如何处理？这体现了 LLM 与 Runtime 在控制流上的什么区别？

> LLM输出"任务已经完成"，不代表控制流认为任务已经完成，控制流会检查测试的完成情况，如果必须的测试未完成，Runtime会将未完成的测试信息加入上下文回传给LLM，要求LLM进行下一轮决策。体现了：==LLM的输出会影响控制流分支，例如提出工具调用或结束请求；Runtime则负责依据运行机制、系统规则和执行难状态推进或终止AgentLoop。==

## 测验

假设 Runtime 规定：

1. 测试是任务的必需检查。
2. 测试失败时，允许 LLM 最多修复两次。
3. 两次修复后测试仍失败，任务进入终止状态。
4. LLM 可以提出结束请求，但不能绕过必需检查。

请回答：

1. 这套规则中，哪些属于控制流规则？

> 控制流规则影响执行顺序、分支和状态转化。所以「3」「4」属于控制流规则，「1」属于验收规则，「2」属于运行时限制。

2. 当测试连续失败三次时，AgentLoop 应如何转换状态？

> - 记录第三次测试失败的结果。
> - 判断修复次数已经达到上限。
> - 不再允许进入新的修复循环。
> - 将任务置于失败终态，或进入专门的失败汇报流程。

3. 为什么"LLM 输出结束请求"不能直接让系统进入 `Completed`？

> LLM的完成声明只是模型输出，不能替代系统规定的验收条件，两者属于不同的职责。
