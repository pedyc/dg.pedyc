## Area: Node.js

> 把 V8 与 libuv 拼成能在服务器上跑 JavaScript 的运行时，管的是语言之外那一层：I/O 由谁调度、模块怎么加载、进程如何扩展。

### 领域定义

- **核心范畴**：事件循环与 libuv 线程池、Buffer 与 Stream、模块系统（CommonJS 与 ESM）、进程与 cluster、包管理与工具链运行时。
- **不包括**：语言语法与语言核心（属 [[JavaScript]]）、浏览器宿主行为（属 [[浏览器]]）、框架用法（属 [[NextJS]] 等）。
- **与相关领域的区别**：[[浏览器]] 与本领域是同一门语言的两个宿主——浏览器给的是 DOM、渲染与同源策略，Node.js 给的是文件、网络与进程；[[JavaScript]] 答「语言本身怎么运作」，本领域答「它跑在什么容器里、容器给了什么、代价是什么」。

### 里程碑

- **愿景**：能判断一段 Node 服务的瓶颈在事件循环、I/O 还是内存，并按这个判断做选型与排障。
- **里程碑**：
	- [ ] 阶段 1：运行时模型——能讲清一次请求从进入事件循环到写回响应的完整路径
		- [ ] 说清宏任务、微任务与 libuv 阶段的关系，并指出 `process.nextTick` 插在哪一层
		- [ ] 说清阻塞一次事件循环的三种常见写法，各举一例
	- [ ] 阶段 2：模块与包——能解释一次 `require` 与 `import` 的解析顺序与代价
		- [ ] 说清 CommonJS 与 ESM 在加载时机、循环依赖、`__dirname` 上的差异
	- [ ] 阶段 3：I/O 与并发——能判断该用 Stream、worker_threads 还是多进程
		- [ ] 对一个真实场景做出选型，并说明另一种选型会在哪一步坏掉

> 判据：三个阶段都以「能讲清」为落点，不以「读完文档」为落点。阶段 3 的选型必须给出反例，否则只是记住了结论。

### 执行系统

- **关键工具**：npm 与 pnpm（依赖与脚本）、nvm（版本切换）、`--inspect` 与 clinic（性能与内存诊断）
- **跨领域引用**
	- [[浏览器]] — 同一门语言的另一个宿主，对照着读才分得清哪些是语言、哪些是宿主给的
	- [[JavaScript]] — 语言侧的机制归它，容器侧的机制归本领域
	- [[Edge Runtime]] — 并列的第三个运行时：没有文件系统与可用线程池，本领域的多数手段在那里不可用
