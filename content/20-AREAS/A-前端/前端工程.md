## Area: 前端工程

> 将软件工程方法论应用于前端开发，通过规范化、模块化、自动化解决规模化、协作化和性能优化挑战。

**核心目标**：提效、保质、监控。

### 领域定义

- **核心范畴**：开发体验优化、构建编译、质量保障、部署运维、监控治理
- **不包括**：具体业务代码实现、UI 设计
- **与相关领域的区别**：
	- [[前端工程]] 关注「如何高效、可控地交付」
	- [[前端交互]] 关注「如何响应用户」
	- [[前端性能优化]] 关注「如何让页面加载更快」
	- 与 [[软件工程]] 的分工：软件工程给方法与判据，本领域负责这套方法在前端技术栈上的具体形态

### 里程碑

- **愿景**：能独立搭起并维护一条从提交到上线的交付链路，说清每个环节为什么存在、坏了怎么查
- **里程碑**：
	- [ ] 阶段 1：构建链路——从一个空目录搭出开发、构建、产物分析三段可用的配置
		- [ ] 开发态热更新与构建态产物的差异能解释（为什么产出不同、差在哪一步）
		- [ ] 产物分析报告能定位一次真实的体积问题，并说清优化前后的数字
	- [ ] 阶段 2：质量闸门——提交前、合并前、上线前各有一道自动检查
		- [ ] ESLint + Prettier + husky/lint-staged 串成 commit 门，故意违规能被拦下
		- [ ] 单元测试与 E2E 各有一个能跑通的样本（Vitest / Playwright）
		- [ ] CI 上跑通 build + test，失败能阻断合并
	- [ ] 阶段 3：交付与观测——一次真实上线，加一次线上问题回溯
		- [ ] 能独立完成构建产物部署与回滚，回滚不需要重新构建
		- [ ] 接入错误监控（Sentry），用一次线上错误走完「告警 → 定位 → 修复 → 验证」

> 判据：三个阶段各自的验收物都能在项目里指出来——配置文件、流水线、监控面板上的那条告警。写不出「在哪个项目的哪一处」，就是还没达成。愿景原写「提效、保质、监控」三个词，那是目标的方向，不是可验收的落点，故拆成上面九条。
