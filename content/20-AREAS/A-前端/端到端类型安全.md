## MOC：端到端类型安全

在现代全栈开发（尤其是 AI 原生全栈与 TS/Python 异构系统）中，端到端类型安全（End-to-End Type Safety） 是消除"接口契约漂移"、保障重构信心与实现开发期 IDE 级高保真协同的核心质量卡点。它打破了传统"前端 TS 静态类型自嗨，后端任性修改 API"的隔离藩篱，构建起从数据存储、API 通信、到前端 UI 渲染的无缝类型传导链条。

## 1. 编译期静态约束 (Compile-time Boundary)

静态类型检查是类型安全的第一道防线，通过配置与工具链对源码及依赖进行严格的类型边界划定。

- [[tsconfig.json]] — TypeScript 编译器的核心配置文件，定义类型检查严格程度（strict）与模块解析策略
- [[package.json]] — Node.js 项目核心元数据清单，声明模块导出格式、对等依赖以及 types 类型入口定义
- [[SOP-初始化前端工程tsconfig基线配置]] — 针对应用层 Web 工程与基础 NPM 库的标准 TypeScript 基线配置流程

## 2. 同构技术栈类型共享 (Isomorphic Type Sharing)

在 TypeScript 统一的技术栈体系下，通过全栈同构代码库共享或 RPC 机制，实现无 API 接口文件负担的天然类型推导。

- [[NextJS]] — React 全栈同构应用框架，利用服务端组件（RSC）与 Server Actions 实现从服务器到视图的无缝类型共享
- [[tRPC]] — TypeScript 原生全链路 RPC 框架，实现前后端在不生成/编译 API 契约文件的条件下的直接类型共享
- [[Monorepo-类型共享]] — Monorepo 多包拓扑架构下，利用 composite 开启跨子包静态类型拓扑关联与共享

## 3. 异构技术栈边界对齐 (Heterogeneous Boundary Align)

在 TS 前端与 Python 后端等异构 AI 应用开发场景中，通过标准协议文档与客户端代码自动生成技术，解决跨语言类型系统的隔离硬伤。

- [[FastAPI]] — Python 高性能异步 Web 框架，基于原生 Pydantic 类型自动生成符合规范的 OpenAPI Schema 定义
- [[Q-AI全栈项目如何科学选型前后端框架]] — 探讨 AI 场景下（SSE 流、多模态）TS 前端与 Python 后端的协议规范与技术选型决策
- [[SOP-搭建基于Nextjs与FastAPI的流式AI全栈脚手架]] — 实现跨 TS/Python 边界对齐的混合框架脚手架搭建与标准工程流程

## 4. 运行时边界防御 (Runtime Boundary Defense)

由于静态类型语言（如 TypeScript）在浏览器端运行时会面临"类型擦除"，必须引入运行时校验来拦截不受信任的 API 数据流，防止内存与逻辑崩溃。

- [[C-Zod]] — 声明式 Schema 运行时校验库，提供针对 API 外部数据的运行时拦截与强静态类型推导（infer）
- [[C-Pydantic]] — Python 异步生态（FastAPI/Litestar）下的运行时数据校验与解析底座，构建后端的类型拦截盾牌
- [[Q-如何确保代码在本地提交前通过规范校验]] — 借助本地质量卡点将规范拦截前置，确保类型一致性及提交规范
