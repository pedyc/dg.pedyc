## MOC：Node.js 知识测评

> 按能力域分组的自评清单：每条是一个知识点，勾选的判据是「不看资料能讲清它是什么、为什么这样设计，并能说出一条它会失效的边界」。
> 覆盖范围比三篇专题 MOC 更宽——除运行时、模块、I/O 三段外，还含网络、进程、错误诊断、测试、安全与部署。

### 核心原则

- 评测口径：勾选 = 能讲清，并给得出一个反例。只记住 API 名称、或只做过一次配置，都不算通过。这与 [[Node.js]] 领域页「以能讲清为落点，不以读完文档为落点」是同一条判据。
- 断链约定：所有知识点都写成 `[[...]]`。能解析成实链的，说明库内已有对应笔记；显示为断链的，说明库内尚无该笔记。按本库语义，断链是「这条知识已被认可、但还没成文」的待提炼信号，不是错误，因此不改成外链、不降级为纯文本、也不为它临时建空笔记。
- 与专题 MOC 的分工：[[Node 运行时模型]] · [[Node 模块与包]] · [[Node IO 与并发]] 按一次请求的生命周期做导航索引，本页按「能不能讲清」逐条自评。条目会有重叠，但切分的轴不同；本页不复制它们的分类说明，也不复述机制。
- 缺口优先：断链条目就是下一步该写的笔记，处理顺序见 [[笔记类型规范]] 的「断链与 atomic 提炼」。
- 范围边界：语言语法归 [[JavaScript]]，浏览器宿主行为归 [[浏览器]]，框架用法归 [[NextJS]] 等，本页只列 Node 运行时这一层给出来的东西。
