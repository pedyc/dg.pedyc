二叉搜索树的核心优势是**有序 + 查找快**，所以应用场景大多围绕这两点。

## 1. 有序数据的动态维护

需要频繁**插入、删除、查找**，同时还要保持**有序**的场景：

- 排行榜 / 积分榜
- 按时间戳维护的事件队列
- 动态维护一个有序集合

数组插入删除是 O(n)，BST 平均 O(log n)。

---

## 2. 范围查询

BST 天然支持「找出所有在 [a, b] 之间的值」：

```bash
若 node.val < a，只需往右找
若 node.val > b，只需往左找
否则 node.val 在范围内，左右都要查
```

应用：

- 数据库索引的范围扫描
- 查询某时间段内的订单 / 日志
- 地理信息系统中按坐标范围检索

---

## 3. 查找第 k 小 / 第 k 大

在每个节点维护**子树节点个数**，就能 O(log n) 找到第 k 小元素。

应用：

- 求中位数
- 排行榜取第 k 名
- 流式数据中动态求第 k 大

---

## 4. 前驱 / 后继查询

快速找到「比 x 小的最大元素」或「比 x 大的最小元素」。

应用：

- 日程安排：找某个时间点前后的最近会议
- 自动补全：找字典序相邻的单词

---

## 5. 数据库与文件系统索引

- **B 树 / B+ 树** 是 BST 的多路扩展，广泛用于数据库索引和文件系统
- MySQL 的 InnoDB、大部分关系型数据库的索引底层都是 B+ 树
- 原因是 BST 每个节点只存一个值，磁盘 IO 次数多；B+ 树一个节点存多个值，降低树高，减少磁盘访问

---

## 6. 语言标准库中的有序容器

很多语言用平衡 BST（红黑树等）实现有序 map / set：

| 语言 | 容器 | 底层结构 |
|---|---|---|
| C++ | `std::map` / `std::set` | 红黑树 |
| Java | `TreeMap` / `TreeSet` | 红黑树 |
| Python | 无内置，`sortedcontainers` | 类似平衡树 |
| Go | 无内置，常用第三方 | 红黑树 |

这些容器支持：有序遍历、范围查询、前驱后继、第 k 小。

---

## 7. 平衡 BST 的具体变种及应用

| 结构 | 特点 | 典型应用 |
|---|---|---|
| AVL 树 | 严格平衡，查找快 | 查找密集、插入删除少的场景 |
| 红黑树 | 弱平衡，插入删除快 | 语言标准库、Linux 内核 |
| B / B+ 树 | 多路，矮胖 | 数据库、文件系统 |
| Treap / Splay | 随机 / 自适应 | 竞赛、缓存 |

---

## 8. 其他场景

- **表达式树**：中序遍历还原中缀表达式
- **霍夫曼编码**：用优先队列（堆，本质也是树结构）构建
- **路由表**：按 IP 前缀查找（用 Trie 或 BST 变种）
- **内存分配**：按地址大小维护空闲块

---

## 一句话总结

BST 的典型应用 = **需要有序 + 需要动态增删查** 的场景。
一旦数据是静态的，排序数组 + 二分就够了；一旦需要频繁变动还保持有序，BST 及其变种（红黑树、B+ 树）就是首选。
