## 术语：光栅化

> **主题**：#计算机科学/计算机图形学/渲染管线

### 定义

光栅化（rasterization）是把**用几何描述的画面**转成**按像素格取样的位图**的过程。它做两件事：离散化（连续坐标 → 像素格）与覆盖判定（哪一格被哪个图元盖住、盖住多少）。

界线在输出上：光栅化回答「哪个像素属于哪个图元」，不回答「这个像素该是什么颜色」——后者是片段着色器的职责。所以 GPU 管线里光栅化之后的产物叫**片段**（fragment）而不是像素，因为它还没有颜色。

### 在渲染管线中的位置

| 阶段 | 做什么 | 连续 / 离散 |
|:--|:--|:--|
| 顶点着色器 | 顶点坐标变换（模型 → 世界 → 视图 → 投影） | 连续 |
| 图元装配 | 顶点组装成三角形、线段 | 连续 |
| 裁剪 | 去掉视锥体外的图元 | 连续 |
| 屏幕映射 | 映射到屏幕坐标系，仍是浮点 | 连续 |
| **光栅化** | 覆盖判定，产出片段 | **离散** |
| 片段着色器 | 逐片段计算颜色 | 离散 |
| 深度测试与混合 | 决定可见性，写入帧缓冲 | 离散 |

这张表的用处只有一处：**光栅化是整条管线里唯一一次「连续 → 离散」的跳变**。此后的所有代价都按像素或片段计价，而此前的所有代价按图元计价。理解这一点，才能判断一个优化该动几何量还是该动像素量。

### 固有代价：走样

光栅化即采样，采样必然走样。一个像素只能取一个值，而图元在像素内的覆盖是连续的，边缘处必然失真（锯齿）。MSAA、超采样、后处理抗锯齿都是**增加采样数**，让误差变小，不是消除误差。

由此得一条：分辨率越高，走样越轻，但光栅化成本按面积增长——成本与 `像素数 × 每像素采样数` 成正比。这是所有实时渲染在中低端设备上要做的取舍。

### 同名不同义：浏览器里的光栅化

浏览器的渲染流水线里也有一步叫 raster（中文同样译作光栅化），但它和图形学讲的光栅化**只有「把连续描述转成像素格」这一个共同点**：

| | 图形学光栅化 | 浏览器光栅化 |
|:--|:--|:--|
| 输入 | 3D 图元（顶点 + 索引），带深度 | 2D 绘制指令（display list），无深度 |
| 变换 | 顶点着色器做 MVP 变换，再投影到屏幕 | 变换由合成阶段用矩阵完成，光栅化只画 2D |
| 判定归属 | 三角形覆盖 + 深度测试 | 路径填充 + 图层顺序 |
| 谁执行 | GPU 图形管线的一段 | raster 线程池（CPU）或 GPU 进程（GPU rasterization） |
| 产物 | 帧缓冲中的像素 | 图层切片的位图（tile） |
| 何时发生 | 每帧一次 | 图层内容变化时；可按需提前，视口附近的 tile 优先 |

关键差别在实现路径：**浏览器的光栅化不跑三角形管线和深度测试**，它是 2D 绘制（Skia 的路径填充与抗锯齿），合成靠图层顺序而非 z 缓冲。所以看到「浏览器光栅化」时，把它理解成「把绘制指令画成一张位图」比理解成「三角形落地」更接近事实。

三个由此推出的结论：

- `will-change: transform` 之所以让动画流畅，是因为它让元素独立成层，动画期间只需合成器改矩阵，**不重新光栅化**。同理，`will-change: width` 会触发布局、重绘与重新光栅化，加上去只会更慢。
- 光栅化成本约与 `面积 × DPR²` 成正比。同样一个图层，DPR 2 的屏幕上像素数是 4 倍，这也是高分屏上滚动更容易掉帧的一层原因。
- 「滚动卡但主线程空闲」通常不在 JS，而是光栅化跟不上：tile 尚未就绪，合成器只能继续平移旧位图，于是看到空白或模糊。

### 常见误判

- **「光栅化 = GPU 渲染」**：CPU 也能光栅化，而且浏览器默认大量走 CPU raster，GPU rasterization 是一项可开关的优化而非前提。
- **「矢量图不失真，所以不需要光栅化」**：不失真指源数据无损；送显示前必然光栅化一次，那一刻就离散了。矢量图的优势是可以按任意 DPR 重新光栅化，不是不用光栅化。
- **「重绘就是重新光栅化」**：重绘是重新产出绘制指令，光栅化是把指令画成位图。二者常同时发生，但可以只发生后者——DPR 变化、缩放、图层被丢弃后恢复，都会在不重绘的情况下重新光栅化。
