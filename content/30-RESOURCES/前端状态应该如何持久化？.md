## 问题拆解

前端的"状态持久化"本质上是在解决一个问题：

> **页面/应用重新加载、关闭、重新打开之后，哪些状态还应该存在？应该存在多久？由谁负责恢复？**

不要把所有状态都持久化。比较合理的做法是先按**生命周期和数据来源**分类。

## 解决方案

### 1. 根据状态类型进行持久化

|状态类型|例子|是否持久化|常见位置|
|---|---|--:|---|
|UI 瞬时状态|Modal 开关、hover、loading|❌|`useState` / `ref`|
|页面状态|当前 Tab、筛选条件、分页|看需求|URL / `sessionStorage`|
|用户偏好|深色模式、语言、侧边栏宽度|✅|`localStorage` / IndexedDB|
|业务数据|用户资料、订单、文章|通常需要|服务端 + 客户端缓存|
|草稿/离线数据|表单草稿、编辑器内容|✅|IndexedDB|
|身份认证|token、session|谨慎|Cookie / 服务端 Session|

所以不要形成：

```text
所有状态
   ↓
localStorage
```

而应该是：

```text
                    ┌─ 瞬时 UI 状态 ──────→ 内存
                    │
前端状态 ──── ─┼─ 页面/可分享状态 ─────→ URL
                    │
                    ├─ 会话状态 ─────────→ sessionStorage
                    │
                    ├─ 用户偏好 ─────────→ localStorage
                    │
                    ├─ 大量/离线数据 ──────→ IndexedDB
                    │
                    └─ 业务事实 ─────────→ Server
```

---

### 2. 根据判断标准进行持久化

问自己三个问题：

#### ① 刷新页面后应该还在吗？

如果 **不应该**：

```ts
const [isOpen, setIsOpen] = useState(false)
```

不用持久化。

如果应该：

继续判断。

---

#### ② 这个状态是否属于 URL？

例如：

```text
/products?category=phone&page=2&sort=price
```

这种状态最好放 URL，而不是 `localStorage`。

原因是 URL 有几个天然优势：

- 可以分享
- 可以收藏
- 可以前进/后退
- 可以 SSR
- 可以直接定位到当前页面状态

例如：

```ts
const params = new URLSearchParams(location.search)

const page = Number(params.get('page') ?? 1)
const category = params.get('category')
```

典型：

```text
搜索关键词
筛选条件
排序
分页
当前 Tab
详情页 ID
```

---

## 持久化判断决策树

以后遇到任何状态，都可以这样问：

```text
这个状态是什么？
       │
       ├─ UI 临时状态
       │      ↓
       │    Memory
       │
       ├─ 应该出现在 URL？
       │      ↓
       │     URL
       │
       ├─ 只需要本次 Tab？
       │      ↓
       │ sessionStorage
       │
       ├─ 用户偏好？
       │      ↓
       │ localStorage
       │
       ├─ 大量 / 复杂 / 离线？
       │      ↓
       │ IndexedDB
       │
       └─ 服务端业务事实？
              ↓
            Server
```

**尤其要记住一个原则：**

> **持久化不是状态管理的一部分，而是状态生命周期设计的一部分。**

这也是为什么在 React 里讨论 `useState / useReducer / Context` 时，最好先把"**状态属于谁、生命周期多久、是否需要跨刷新存在、谁是真正的数据源**"搞清楚，再决定具体用什么状态管理工具。
