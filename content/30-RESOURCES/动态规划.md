动态规划：把大问题拆成重叠的子问题，用一张表记录每个子问题的最优解，避免重复计算，最终推出大问题的解。

> **动态规划**一般用于求最优值 / 方案数，用 `dp` 数组存结果
> **核心**：状态转移方程

## 什么时候用动态规划？

- 求最优值 / 方案数 / 可行性，不是枚举所有方案。
- 有重叠子问题：同一个子问题被多次计算。
- 有最优子结构：大问题的最优解由小问题的最优解构成。
- 无后效性：当前状态只依赖更小的状态。

## 思考模板

1. 原问题：求最优解/方案数 或 判断可行性？
2. 状态定义：`dp[i]` 或 `dp[i][j]` 代表什么？
3. 状态转移方程：`dp[i]` 怎么由更小的状态推出来？例如斐波那契 `dp[i] = dp[i-1] + dp[i-2]`
4. 边界条件：最小的状态是什么？它们的值是多少？例如斐波那契 `dp[0] = 0, dp[1] = 1`
5. 计算顺序：从哪个状态开始算？按什么顺序遍历？
6. 答案位置：最终答案在 `dp` 的哪个位置？
7. 空间优化（可选）：能不能把二维 `dp` 压缩成一维？能不能用滚动变量？
	- 看 `dp[i]` 依赖哪些状态。如果只依赖前一行 / 前几个，就能压缩。

### 思路示例

- LeetCode198：[打家劫舍](https://leetcode.cn/problems/house-robber)

```bash
1. 原问题
   求能偷到的最大金额。

2. 状态定义
   dp[i] = 考虑 [0, i] 的房子，能偷到的最大金额。

3. 状态转移方程
   最后一步：偷不偷第 i 个房子？
   偷：nums[i] + dp[i-2]
   不偷：dp[i-1]
   dp[i] = max(dp[i-1], nums[i] + dp[i-2])

4. 边界条件
   dp[0] = nums[0]
   dp[1] = max(nums[0], nums[1])

5. 计算顺序
   dp[i] 依赖 dp[i-1] 和 dp[i-2]
   -> i 从小到大

6. 答案位置
   return dp[n-1]

7. 空间优化
   dp[i] 只依赖前两个
   -> 用两个变量 prev1, prev2
```
