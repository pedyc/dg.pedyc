## 术语：双跑

> **主题**：#软件工程/交付

### 定义

双跑（parallel run，中文也作并行运行、双轨运行）指新旧两套实现同时处理同一份真实输入，**只有旧实现的结果对外返回**，新实现的结果被异步抓取、与旧结果逐字段比对；当差异收敛并持续一段时间后，才把新实现提升为权威、移除旧路径。

它回答的是一个其他手段回答不了的问题：怎么知道新实现的**行为**与旧的等价——不是「跑得通」，是「算得一样」。出处是遗留系统替换的实践传统，Martin Fowler 的 StranglerFigApplication（2004）与后续 legacy displacement 模式把 parallel run 固定为该场景的标准手段；GitHub 以 Scientist 库把同一思路命名为「受控实验」（controlled experiments），Stripe 的 shadow mode 迁移属于同族做法。

三个条件同时成立才算双跑，缺一条就退化成了别的东西：

| 条件 | 具体含义 |
|:---|:---|
| 同一份输入 | 真实生产输入，不是构造的测试用例——双跑的全部价值来自那些没人想到要写的用例 |
| 新路径无副作用 | 比对期不写共享存储、不发消息、不调外部服务。这条最常出错，也是双跑自己造成事故的唯一方式 |
| 有自动对账 | 差异被记录到可复现：输入、两侧输出、时间戳；并按原因归类，而不是只数条数 |

### 与相邻手段的区别

| 对照          | 差在哪                                                |
| :---------- | :------------------------------------------------- |
| [[灰度]]      | 灰度让一撮用户真的看到新结果，双跑的新结果谁都不看。前者验「上线后稳不稳」，后者验「行为等价不等价」 |
| 影子流量 / 暗发布  | 影子只复制流量，通常不对账；双跑的价值恰在对账。没有比对，只能证明新系统扛得住，不能证明它算得对   |
| 双写          | 双写同时写两个数据源，保的是数据不丢；双跑同时算两套结果，保的是语义不变               |
| A/B 测试      | A/B 期待两组有差异并测量高下，双跑期待没有差异——差异就是缺陷                  |
| 单元测试 / 集成测试 | 测试覆盖的是「有人想到的」分支；双跑覆盖的是生产数据里那些没人想到的脏值、某个客户独有的结算类型   |

### 边界

- **计算翻倍**。请求-响应型业务普遍付得起；重批处理可能不可行，退路是按固定比例采样，并对稀有输入过采样——差异恰恰集中在稀有输入上。
- **观察窗口要盖住完整业务周期**。月结、季结的路径一周内不出现，窗口不够就只是「看起来一致」。
- **写路径做不了**。有状态写操作无法同时真写两份，双跑只适用于读路径与纯计算路径。
- **它必须有个终点**。不结束的双跑等于长期维护两套实现，比迁移之前更糟；差异归零之后仍要保留一段可回退期，因为低频差异会在数周后浮现。
