## SOP：实现图片与多媒体渐进加载

通过"轻量占位 → 视口监听/浏览器原生懒加载 → 渐进式/响应式高保真替换"的标准链路，优化页面首屏加载性能（FCP/LCP）并避免累积布局偏移（CLS）。

* **目标**：降低初始页面载荷、避免 CLS 抖动，实现平滑自然的媒体加载体验。
* **实现**：结合现代 HTML5 特性（`loading="lazy"`、`<picture>`、AVIF/WebP）、骨架/模糊占位（LQIP/BlurHash）与 `IntersectionObserver` 动态调度。
* **问题溯源**：本 SOP 是 [[Q-如何优雅解决长页面富媒体资产加载导致的卡顿与布局抖动]] 的收敛成果——经过全量静态加载、简单懒加载与渐进式占位方案的对比验证，固化为标准工程流程。

---

### 适用场景

* 场景 1：电商商品瀑布流、长图文资讯/文章等含有大量静态图片的页面。
* 场景 2：短视频流、音视频预览卡片等高带宽消耗多媒体组件按需加载。
* 场景 3：网络环境受限（如移动端弱网）下对首屏体验（LCP/FCP）有严格指标要求的场景。

### 流程图解

```mermaid
flowchart TD
	A[页面初次挂载] --> B[渲染容器并固定宽高比 Aspect-Ratio]
	B --> C[展示轻量占位: 纯色背景 / BlurHash / LQIP]
	C --> D{是否属于首屏关键媒体 / LCP?}
	D -->|是| E[预加载/高优先级加载: loading='eager' fetchpriority='high']
	D -->|否| F[按需加载: loading='lazy' 或 IntersectionObserver 监听进入视口]
	F --> G[元素进入视口阈值 Buffer]
	E --> H[请求现代格式/响应式资源: AVIF/WebP srcset]
	G --> H
	H --> I{媒体资源解码加载完成?}
	I -->|是| J[CSS 平滑过渡替换占位, 移除 Skeleton/Blur]
	I -->|失败| K[渲染兜底 Error Placeholder 并上报监控]
````

### 核心步骤

1. **步骤 1：固定媒体容器宽高比，消除 CLS**
	* 为媒体容器或 `<img>`/`<video>` 显式设置 `width`、`height` 属性或 CSS `aspect-ratio`，确保资源加载前浏览器已分配确定占位空间，防止布局抖动。

2. **步骤 2：生成与注入低成本占位（LQIP / BlurHash / 骨架屏）**
	* 构建期或服务端（OSS/CDN）生成极小尺寸的 Base64 模糊缩略图（LQIP，通常 < 1KB）或 BlurHash 编码字符串。
	* 客户端优先渲染 Canvas/CSS Blur 占位，避免白块出现。

3. **步骤 3：配置现代格式与响应式分发策略**
	* 优先使用 `<picture>` 与 `srcset` / `sizes`，根据设备分辨率（DPR）与屏幕视口协商最佳尺寸和格式（AVIF > WebP > JPEG/PNG）。

4. **步骤 4：分层触发加载与视口检测**
	* **首屏/LCP 资源**：严禁懒加载，标记 `fetchpriority="high"` 及 `loading="eager"`。
	* **非首屏图片**：使用原生 `loading="lazy"`。
	* **音视频与复杂交互多媒体**：采用 `IntersectionObserver` 进行视口阈值（如 `rootMargin: '200px'`）提前预热，按需挂载 `<video>` 源或 `HLS/DASH` 流。

5. **步骤 5：渐进式淡入与状态收尾**
	* 监听图片 `onload` 事件或视频 `canplay` 事件，通过 CSS `opacity` / `filter` 平滑过渡，并销毁临时监听器与占位图层。

### 实践/示例

**1. 响应式与渐进式图片组件实现（Vue / React / HTML 范式）**

```html
<!-- 固定容器比例，防止 CLS -->
<div class="media-container" style="aspect-ratio: 16 / 9; background: #f0f0f0;">
<!-- 底层 LQIP 模糊占位 -->
<img 
	src="data:image/jpeg;base64,/9j/2wBD…" 
	aria-hidden="true" 
	class="placeholder-blur"
/>

<!-- 顶层高保真响应式媒体（渐进替换） -->
<picture>
	<source type="image/avif" srcset="hero-400.avif 400w, hero-800.avif 800w" sizes="(max-width: 600px) 100vw, 800px">
	<source type="image/webp" srcset="hero-400.webp 400w, hero-800.webp 800w" sizes="(max-width: 600px) 100vw, 800px">
	<img
		src="hero-800.jpg"
		alt="案例演示"
		width="800"
		height="450"
		loading="lazy"
		decoding="async"
		onload="this.classList.add('loaded')"
		class="main-media"
	/>
</picture>
</div>

<style>
	.media-container {
		position: relative;
		overflow: hidden;
	}
	.placeholder-blur {
		position: absolute;
		inset: 0;
		width: 100%;
		height: 100%;
		object-fit: cover;
		filter: blur(10px);
		transform: scale(1.05); /* 避免模糊边缘溢出白边 */
	}
	.main-media {
		position: relative;
		width: 100%;
		height: 100%;
		object-fit: cover;
		opacity: 0;
		transition: opacity 0.3s ease-in-out;
	}
	.main-media.loaded {
		opacity: 1;
	}
</style>
```

**2. 视口多媒体（视频/音频）按需加载 Observer 示例**

```js
// 提前 200px 缓冲预加载多媒体资源
const mediaObserver = new IntersectionObserver((entries, observer) => {
entries.forEach(entry => {
	if (entry.isIntersecting) {
		const mediaElement = entry.target;
		const dataSrc = mediaElement.dataset.src;
		
		if (dataSrc) {
			mediaElement.src = dataSrc;
			if (mediaElement.tagName === 'VIDEO') {
				mediaElement.load();
			}
		}
		mediaElement.classList.add('media-active');
		observer.unobserve(mediaElement); // 完成加载后解除监听
	}
});
}, { rootMargin: '0px 0px 200px 0px' });

document.querySelectorAll('video[data-src], audio[data-src]').forEach(el => {
mediaObserver.observe(el);
});
```

### 常见坑点

* ⛔ **反模式：对首屏 LCP（最大内容绘制）主图开启 `loading="lazy"`**：会导致浏览器延迟排队请求关键图片，严重恶化 LCP 性能评分[cite: 1]。首屏关键视觉图必须设为 `loading="eager"` 或配合 `<link rel="preload">`。
* ⛔ **反模式：未设置固定宽高比（未留白）导致回流**：图片载入瞬间撑开页面，引起剧烈页面跳动和高额 CLS 扣分[cite: 1]。
* ⛔ **反模式：占位图（LQIP）体积失控**：Base64 缩略图单张若超过 2~3KB，在批量渲染时会导致 HTML DOM 体积暴增，阻塞关键渲染路径[cite: 1]。
* 🔧 **排查：图片淡入出现白屏闪烁**：检查是否在图片未完成 `decoding` 时就触发了显示。建议给图片加上 `decoding="async"` 并在 `onload` 确认完成后再平滑淡入[cite: 1]。
