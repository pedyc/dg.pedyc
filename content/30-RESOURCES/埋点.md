## 术语：埋点

> **领域**：#前端/数据分析

### 定义

埋点（Tracking/Monitoring）是采集用户行为数据的技术手段。通过在应用中植入代码，当用户触发特定行为时，向服务端发送包含行为信息的数据，用于分析用户行为和优化产品。

**核心要素**：
- 触发时机（点击、曝光、页面访问）
- 上报数据（用户 ID、行为类型、上下文信息）
- 上报地址（服务端接收端点）

**注意要点**：
- 无侵入性：埋点代码与业务逻辑分离，不影响主流程
- 异步上报：数据上报不影响用户操作性能
- 可配置：可通过平台配置自定义数据上报类型
- 可扩展：支持自定义事件和属性
- 降级策略：网络失败时本地缓存，恢复后重传

### 埋点类型

| 类型 | 触发方式 | 典型场景 |
|:---|:---|:---|
| **点击埋点** | 用户点击元素 | 按钮点击、链接点击 |
| **曝光埋点** | 元素展示在屏幕 | 广告展示、内容曝光 |
| **页面埋点** | 页面进入/离开 | 页面访问、停留时长 |
| **自定义埋点** | 业务自定义 | 关键行为追踪 |

### 埋点方案对比

| 方案        | 实现方式     | 优点   | 缺点       |     |
|:-------- |:------- |:--- |:------- | --- |
| **代码埋点**  | 手动植入代码   | 精准控制 | 维护成本高    |     |
| **全埋点**   | 自动捕获所有交互 | 覆盖全面 | 数据量大、噪音多 |     |
| **可视化埋点** | 可视化工具配置  | 无需编码 | 灵活性低     |     |

### 跨学科含义

- **在数据分析中**：埋点是数据采集的入口，决定数据质量
- **在前端工程中**：埋点 SDK 是基础设施，跨团队复用
- **在产品运营中**：埋点数据支撑 A/B 测试、用户画像、转化分析
