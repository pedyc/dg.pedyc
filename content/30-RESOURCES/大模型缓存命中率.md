## 术语：大模型缓存命中率

**主题**：#人工智能/LLM推理工程

### 定义

在大型语言模型（LLM）推理与 Serving 架构中，**缓存命中率（Cache Hit Ratio）** 通常指推理引擎在处理输入请求（Prompt / 上下文）时，**成功匹配并复用已有的 KV Cache 或 Prompt Cache 的比例**。

在大模型系统中，命中率通常按 **Token 维度（Token-level Prefix Hit Ratio）** 衡量，而非传统 Web 的纯请求次数维度：

$$\text{Hit Ratio}_{\text{token}} = \frac{N_{\text{cached\_tokens}}}{N_{\text{prompt\_tokens}}} \times 100\%$$

* $N_{\text{cached\_tokens}}$：输入 Prompt 中成功在前缀树/基数树（Radix Tree）中命中、无需重复执行注意力机制（Attention）计算的 Token 数量。
* $N_{\text{prompt\_tokens}}$：用户请求输入的总 Prompt Token 数量。

**技术价值与性能影响**：
* **大幅降低首字延迟（TTFT，Time to First Token）**：跳过高计算复杂度的 Prefill 阶段，直接载入显存中的 Key-Value 向量。
* **节省 GPU 算力与吞吐提升**：减少冗余 GEMM 计算，使单卡/集群在相同并发下吞吐量（Tokens/s）提升数倍。
* **降低推理计费成本**：主流商业 API（如 Claude Prompt Caching、OpenAI Context Caching、DeepSeek 上下文缓存）对命中缓存的输入 Token 通常提供 50%～90% 的价格折扣。

#card

> 在 LLM 推理（Serving）中，什么是 Token 级的缓存命中率？其核心价值是什么？
> 指输入 Prompt 中直接复用已有 KV Cache / Prompt Cache 而无需重新计算的 Token 占总 Prompt Token 的比例。
> 核心价值：消除 Prefill 冗余计算、极大压降首字延迟（TTFT）、节省 GPU 显存与算力、降低 API 计费成本。

### 跨学科 / 多维层级含义

* **在 推理引擎底层（vLLM / Chunked Prefill / RadixAttention）中**：特指基于 PagedAttention 和前缀基数树的物理显存命中。当多个请求共享 System Prompt、Few-Shot 示例或多轮对话历史时，公共前缀被锁定在 GPU 物理 Block 中，直接被后续请求指针共享。
* **在 语义缓存与网关层（Semantic Cache，如 GPTCache）中**：指在向量嵌入（Embedding）层面，通过近似最近邻检索（ANN）判断新输入与历史提问的语义余弦相似度是否超过阈值（Cosine Similarity $\ge \tau$）。命中后直接返回历史生成结果，完全不经过大模型前向推理。
* **在 商业 API 与调度路由层（Prompt Caching）中**：指用户发起的调用请求命中服务商服务端特定节点冷热缓存的比例。依赖服务端的粘性会话路由（Sticky Routing）将相同前缀的请求调度至同一物理 GPU 实例。
