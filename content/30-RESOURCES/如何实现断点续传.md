## 问题

> 前端如何实现大文件断点续传？上传中途中断后如何恢复？

---

## 背景

浏览器上传大文件（如视频、安装包、数据集）时，网络波动或服务端超时可能导致上传中断，从头重传成本极高。断点续传的核心思路：将大文件切分成多个小块（chunk），独立上传并记录状态，中断后只重传失败的 chunk。

---

## 解决方案

### 方案一：文件切片 + 上传前查询服务端状态

**整体流程：**
1. 文件切 chunk → 计算文件 hash（唯一标识）
2. 询问服务端：该 hash 已上传了哪些 chunk index
3. 跳过已上传的，只传缺失的 chunk
4. 全部完成后通知服务端合并

**前端核心代码：**

```js
// 1. 文件 hash（SHA-256）
async function getFileHash(file) {
  const buffer = await file.arrayBuffer()
  const hashBuffer = await crypto.subtle.digest('SHA-256', buffer)
  const hashArray = Array.from(new Uint8Array(hashBuffer))
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('')
}

// 2. 切片（默认 5MB）
function createChunks(file, chunkSize = 5 * 1024 * 1024) {
  const chunks = []
  let start = 0
  while (start < file.size) {
    chunks.push(file.slice(start, start + chunkSize))
    start += chunkSize
  }
  return chunks
}

// 3. 上传主流程
async function uploadFile(file) {
  const hash = await getFileHash(file)
  const chunks = createChunks(file)

  // 查询服务端已上传的 chunk
  const res = await fetch(`/api/status?hash=${hash}`)
  const { uploaded } = await res.json()  // Set<index>

  // 并发控制，逐批上传
  const pool = new Set()
  for (let i = 0; i < chunks.length; i++) {
    if (uploaded.has(i)) continue

    const form = new FormData()
    form.append('chunk', chunks[i])
    form.append('hash', hash)
    form.append('index', i)
    form.append('total', chunks.length)

    const task = fetch('/api/upload', { method: 'POST', body: form })
      .then(r => { if (!r.ok) throw new Error(`chunk ${i} 失败`) })
    pool.add(task)
    task.finally(() => pool.delete(task))
    if (pool.size >= 4) await Promise.race(pool) // 限流
  }
  await Promise.all(pool)

  // 通知合并
  await fetch('/api/merge', { method: 'POST', body: JSON.stringify({ hash, total: chunks.length }) })
}
```

**服务端关键逻辑：**

```js
// 接收 chunk → 存入 /tmp/{hash}/{index}
app.post('/api/upload', async (req, res) => {
  const { hash, index } = req.body
  await fs.mkdir(`/tmp/${hash}`, { recursive: true })
  await fs.writeFile(`/tmp/${hash}/${index}`, req.file.buffer)
  res.json({ ok: true })
})

// 查询已上传的 chunk index
app.get('/api/status', async (req, res) => {
  const { hash } = req.query
  const dir = `/tmp/${hash}`
  if (!fs.existsSync(dir)) return res.json({ uploaded: [] })
  const files = await fs.readdir(dir)
  res.json({ uploaded: files.map(Number) })
})

// 合并所有 chunk
app.post('/api/merge', async (req, res) => {
  const { hash, total } = req.body
  const dir = `/tmp/${hash}`
  const ws = fs.createWriteStream(`/uploads/${hash}`)
  for (let i = 0; i < total; i++) {
    ws.write(await fs.readFile(`${dir}/${i}`))
  }
  ws.end()
  await fs.rm(dir, { recursive: true })
  res.json({ url: `/uploads/${hash}` })
})
```

### 方案二：秒传机制

上传前先发 HEAD 请求检测 `hash` 是否已在服务端存在，若存在直接返回 URL，零流量完成。

### 设计要点

| 问题 | 方案 |
|------|------|
| 文件唯一标识 | 浏览器 SHA-256 hash |
| 断点恢复 | 上传前调 `/api/status` 获取已上传 index |
| 并发控制 | 限制 4~6 并发，防浏览器连接上限 |
| 弱网恢复 | 单个 chunk 独立重试（指数退避） |
| 暂停/继续 | `AbortController` 控制请求 |

### 我的理解

断点续传的核心不在于"传"而在于"查"——每次上传前查一下服务端有哪些 chunk，传输过程其实是无状态的。hash 计算是另一个瓶颈，大文件用 Web Worker 跑 SHA-256 避免卡 UI。
