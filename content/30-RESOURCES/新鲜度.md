## 术语：新鲜度

> **主题**：#计算机网络/缓存

### 定义

新鲜度（freshness）指一份缓存的响应仍处在有效期内、可以直接复用而无须向源站验证的状态。它是缓存的第一个判定，判完才轮到验证。

判定式只有一条不等式：

```bash
response_is_fresh  ⇔  freshness_lifetime > current_age
```

两边的来源不同，混起来就会算错：

| 量 | 来源（优先级从高到低） |
|:--|:--|
| `freshness_lifetime` | `s-maxage`（仅共享缓存）→ `max-age` → `Expires` 减 `Date` → 启发式估算 |
| `current_age` | 响应头 `Age`（上游缓存已存了多久）加上本地驻留时间 |

启发式只在响应没有任何显式新鲜度指令时生效，常见做法取 `Last-Modified` 距今天数的 10%；规范允许实现自定，所以「同样的响应在不同客户端新鲜多久」不保证一致。

### 三种状态与各自的出路

| 状态 | 缓存的动作 |
|:--|:--|
| fresh | 直接命中，不产生网络往返 |
| stale | 回源验证（条件请求），或按 `stale-while-revalidate` 先返回旧的、后台再验 |
| stale 且 `must-revalidate` | 不得再用，必须验证成功才可返回 |

### 常见误判

- **`max-age=0` 不等于不缓存**。它只是让副本一存下来就 stale，每次都要验证；真正禁止存储的是 `no-store`。
- **fresh 不等于与源站一致**。新鲜度是「约定的有效期」，不是「同步状态」；源站在此期间改了内容，缓存照样返回旧的，而 HTTP 没有标准的主动失效通道（purge 属于厂商 API，不是协议）。
- **带 `Authorization` 的响应默认不做启发式**。想让它被共享缓存复用，需要显式给出 `public` / `s-maxage` / `must-revalidate`。
- **「强缓存 / 协商缓存」不是规范术语**。它们是中文教材对 fresh 命中与 stale 验证这两段行为的命名，对应的是新鲜度判定的两个分支，不是两套并列机制。

### 与 RTT 的关系

RTT 不是新鲜度的度量，是维持新鲜度的代价单位：新鲜度越高（有效期越短），回源验证越频繁，每条路径上多付的往返就越多。`stale-while-revalidate` 的作用是把这次往返从用户的关键路径上挪走，它没有提高新鲜度。

顺带一个容易混的同形词：QUIC 的 0-RTT 说的是连接恢复时省掉一次握手往返，与缓存是否新鲜无关。
