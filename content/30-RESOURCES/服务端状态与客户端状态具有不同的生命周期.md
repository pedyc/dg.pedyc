## 服务端状态与客户端状态具有不同的生命周期

服务端状态由远程系统维护，而客户端状态通常由当前应用控制，两者在数据所有权、更新来源、生命周期和一致性要求方面存在差异，因此应根据各自特征选择管理策略。

### 论据/示例

#### 论据

1. **数据所有权不同**：客户端状态通常由前端应用直接维护；服务端状态的权威版本由远程服务或数据库维护。
2. **更新来源不同**：客户端状态可以由用户交互直接改变；服务端状态可能被其他用户、后台任务或其他系统修改。
3. **生命周期不同**：组件状态可能随组件卸载而销毁；服务端数据则可能长期存在，并在多个页面或会话中被重新获取。
4. **一致性要求不同**：客户端状态通常关注交互行为是否正确；服务端状态还需要考虑缓存失效、重新验证和并发更新。
5. **适合的工具不同**：组件状态、全局 Store 和服务端数据缓存工具解决的问题并不完全相同。

#### 示例

一个用户资料页面可能同时包含两种状态：

**客户端状态：**

```tsx
const [isEditing, setIsEditing] = useState(false);
```

`isEditing` 由当前界面的交互控制，通常属于客户端状态。

**服务端状态：**

```tsx
const { data: user, isLoading } = useQuery({
queryKey: ["user", userId],
queryFn: () => fetchUser(userId),
});
```

`user` 的权威数据来自服务端，客户端查询库负责请求、缓存和相关状态管理。

即使客户端缓存了用户资料，也不意味着缓存就是权威数据来源。

#### 推论

设计状态管理方案时，应先识别数据的来源和所有权，再决定采用何种管理机制。

对于服务端状态，需要进一步考虑：

- 缓存何时失效。
- 何时重新获取数据。
- 多个请求同时发生时如何处理。
- 数据更新失败时如何恢复。
- 如何处理服务端数据与本地编辑状态之间的冲突。
