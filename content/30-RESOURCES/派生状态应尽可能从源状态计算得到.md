## 核心观点

如果某个状态能够通过已有源状态确定性地计算得到，就应优先使用计算结果，而不是重复保存一份独立状态。

### 论据/示例

#### 论据

1. **减少重复数据**：同一事实只需要一个权威数据来源，避免多个副本分别更新。
2. **降低同步成本**：如果派生值被单独保存，就必须确保源状态变化时派生值也同步更新。
3. **减少不一致风险**：通过计算得到派生值，可以避免源数据与派生数据之间出现矛盾。
4. **明确数据依赖**：派生状态的计算逻辑能够直接表达它依赖哪些源状态。

#### 示例

假设购物车中保存了商品及其价格、数量：

```tsx
const [items, setItems] = useState([
	{ id: 1, price: 100, quantity: 2 },
	{ id: 2, price: 50, quantity: 1 },
]);

const total = items.reduce(
	(sum, item) => sum + item.price * item.quantity,
	0
);
```

`total` 可以直接由 `items` 计算得到，因此通常不需要再单独使用一个状态保存总价。

不推荐在没有必要的情况下同时维护：

```tsx
const [items, setItems] = useState([]);
const [total, setTotal] = useState(0);
```

因为每次修改商品数量、价格或商品列表时，都必须同步更新 `total`。

#### 推论

并非所有计算结果都必须实时重新计算。

当计算成本较高时，可以使用记忆化、缓存或框架提供的计算属性优化性能，但应区分：

- **派生状态**：从其他状态计算得到。
- **缓存结果**：为了性能而保存的计算结果。
- **独立状态**：具有独立生命周期或独立更新语义的数据。
