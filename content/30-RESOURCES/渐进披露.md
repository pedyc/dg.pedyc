## 术语：渐进披露

**主题**：#AI/Agent/上下文工程

### 定义

**渐进披露**（progressive disclosure）是 Agent 的上下文装载策略：模型在某一轮只看到技能与工具的**简短描述**（名称 + 触发条件），只有当它判定某项确实需要时，该技能的完整正文、该工具的完整定义才被加载进上下文。

两条通道：

- **渐进披露上下文**：技能（skill）按需加载，触发时才展开正文
- **渐进披露工具**：工具通过检索（tool search）按需加载，先只暴露名字与用途

### 解决什么

一次性加载的做法是：所有技能正文 + 所有工具 schema 全塞进 system prompt。能力越全，prompt 越长，而其中大部分内容在多数轮次里根本用不到——它买到的不是能力，是上下文预算的提前占用。

渐进披露把「能力清单」与「能力内容」拆开，使 **prompt 长度与能力总量脱钩**。Anthropic 给出的口径是：Claude Code 面向更强的模型把 system prompt 缩减了 80% 以上，缩减的正是与渐进披露技能、工具相关的部分。推论见 [[渐进披露消除了拆子代理的主要动机]]。

### 前提与代价

- **触发描述必须写准**。描述写偏，该加载的技能就不会加载，而模型不会报错——它只是不知道这项能力存在。这是静默失败，比 prompt 过长更难排查。
- **复杂度转移到纪律**。省下的 token 要用精心维护的 system prompt、对上下文窗口与记忆的刻意处理来换。缺这份纪律，单循环反而比多代理更差。
- **依赖 harness 支持延迟加载**。技能只能全量预载、工具只能全量注册时，这个策略不成立。

### 易混

- **不等于前端的「懒加载」**：前端懒加载省的是首次加载时间，渐进披露省的是每一次推理的上下文预算。
- **不等于「检索」**：检索解决「外部知识太多」，渐进披露解决「自己的能力说明太长」——被披露的内容一直在 harness 里，只是没进窗口。
