## 核心观点

状态应该由最接近其使用边界的合适所有者持有，只有在存在明确的共享需求时，才应提升到更高层级管理。

### 论据/示例

#### 论据

1. **降低不必要的耦合**：局部状态由局部组件管理，可以避免无关组件依赖同一个全局 Store。
2. **缩小状态变化的影响范围**：状态所有权越明确，越容易理解哪些组件能够修改它，以及修改后会影响哪些部分。
3. **简化生命周期管理**：与组件生命周期紧密相关的状态通常适合保留在组件内部，避免不必要的全局残留。
4. **避免过度设计**：不是所有状态都需要通过 Redux、Pinia 或其他全局状态管理工具管理。

#### 示例

React 中，一个只控制当前弹窗显示与隐藏的状态：

```tsx
function ProfileButton() {
const [isOpen, setIsOpen] = useState(false);

return (
<>
	<button onClick={() => setIsOpen(true)}>
		查看资料
	</button>

	{isOpen && <ProfileModal />}
</>
);
}
```

这里的 `isOpen` 只服务于当前组件，因此没有必要默认将它放入全局 Store。

如果多个页面都需要访问当前用户信息，则可以考虑将用户状态提升到合适的共享层。

#### 推论

状态提升不应仅仅由组件层级决定，还应考虑：

- 共享范围。
- 状态生命周期。
- 更新责任。
- 数据来源。
- 模块之间的依赖关系。
