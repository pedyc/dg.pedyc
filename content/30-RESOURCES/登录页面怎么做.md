## 问题

> 登录页面怎么做？

---

## 背景

前端场景高频面试题，考察对**登录闭环**的整体把握：表单 → 校验 → 请求 → 登录态存储 → 路由守卫 → 登出/刷新。回答不只在背表单，而应体现对安全、用户体验、多端适配的考量。

---

## 解决方案

### 1. 表单与交互层

- **校验**：手机号/邮箱格式、密码强度；失焦 + 提交双重校验
- **状态**：loading 防重复提交、错误提示、`disabled` 态
- **体验**：密码可见切换、回车提交、记住我、验证码/滑块（风控）

### 2. 请求与登录态存储（核心考点）

登录接口返回 token（JWT），存储位置决定后续携带方式：

- **Cookie**：`httpOnly` + `Secure` 防 XSS 读取，浏览器自动随请求携带；代价是需防护 CSRF（`SameSite` 等）
- **localStorage**：需在请求拦截器手动附加 `Authorization` 头；无 `httpOnly`，XSS 可读取
- 两者本质都是「客户端持有凭证」，真正的权限校验永远在后端
- 详见 [[JWT]]、[[Web存储]]

### 3. 路由守卫与权限

- 前端守卫：未登录跳登录页，登录后按角色控制可访问路由
- 注意：前端守卫只是体验层，后端必须二次校验
- 相关：[[前端路由权限控制方案（RBAC）]]（待建）

### 4. 安全

- 传输层 **[[HTTPS]]**，防中间人
- **XSS**：`httpOnly` Cookie、输入输出转义、[[CSP]]
- **CSRF**：`SameSite` / 同源校验 / 双重 token
- 防暴力破解：验证码、失败次数限制、风控

### 5. 登录态刷新与登出

- token 过期 → **refresh token 静默续期**
- 401 统一拦截 → 刷新重试 / 跳转登录
- 登出：清除登录态 + 跳转

### 6. 进阶变体

- 第三方登录（OAuth）、单点登录（SSO）：一套登录态跨多个应用
- 多端：PC / 移动 / H5 登录态同步与失效策略

### 我的理解

登录页只是入口，核心是**登录态管理闭环**。面试加分点在于主动谈安全（httpOnly / CSRF / HTTPS）与刷新机制，而不是只背表单和跳转逻辑。
