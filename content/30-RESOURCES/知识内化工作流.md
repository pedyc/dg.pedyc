## SOP：知识内化工作流

> 覆盖两种知识内化模式：浏览器的被动剪藏和 AI 对话的主动创作，统一经过「捕获 → 加工 → 入库」。

目标：任何来源的知识都能快速、一致地进入知识库，不堆积、不遗漏
边界：**本 SOP 只做路由**——决定一条内容走哪条路、由谁负责。各环节的标准动作在子 SOP 里，此处只引用不复制。

### 适用场景

> 与 [[信息收集工作流]] 的分工：信息收集管「水源」（RSS/抖音/博客的选源→扫描→标记），本 SOP 管「进水」（决定保存后的剪藏→提取→入库）。两者是流水线上下游，不重叠。

- **模式 A — 浏览器剪藏**：阅读网页/文章/文档时发现有价值内容，需要快速保存到知识库
- **模式 B — AI 对话创作**：与 AI 深入探讨某个领域后，对话中产生了可记录的洞察，需要沉淀为笔记
- 两种模式共享同一套加工和入库标准

### 四条管道，本 SOP 在第二环

| 环节            | 负责的 SOP      | 产出物          |
| :------------ | :----------- | :----------- |
| 水源            | [[信息收集工作流]]  | 值得读的链接       |
| **进水（本 SOP）** | 知识内化工作流      | 已判定形态与归属的笔记  |
| 沉淀            | [[信源落地SOP]]  | 素材落地页 + 知识资产 |

### 核心步骤

#### 模式 A：浏览器剪藏

1. **捕获** — 使用 Obsidian Web Clipper 保存为 markdown 到 `00-INBOX/`
2. **审核** — 运行 `llm-wiki-local review`，判形态与归属
	 - **外部素材（长文、论文、剪藏）→ `record`**，按主题簇落到 `30-RESOURCES/`，后续走 [[信源落地SOP]]
	 - **我自己的文章草稿 → `article`**，落 `60-BLOGS/`
	 - **可整合进 wiki 层的客观知识（机制、定义、对比）→ `llm-wiki-local ingest`**，收敛为 `term` / `concept` / `comparison`
	 - 形态判据只有一处真值：[[笔记类型规范]]，不凭印象
3. **沉淀** — 按上一步判定分别执行；素材类走 [[信源落地SOP]]，含 `## 来源` / `## 产出` 两个挂载位
4. **入库** — `wiki-sync-local` 更新 wiki-index 与 wiki-log；批量改动时可手动跑 `_scripts/build_wiki_index.py --note "…"`

#### 模式 B：AI 对话创作

1. **提取** — 对话结束时，让 AI 把本次对话整理成一篇 `record`：主张、论据、未解决的分歧
2. **判断** — 人从中挑出「我想长期持有」的句子，写成 `atomic`
	 - AI 可以起草，**落不落由人定**：`atomic` 是判断，判据见 [[笔记类型规范#atomic 的正文结构：观点 + 边界 + 至多一个论据]]
3. **关联** — 检查对话涉及哪些 `concept` / `MOC`，更新其核心命题并挂上引用
4. **入库** — 记录 wiki-log，标记本次对话产出

### 实践示例

**模式 A**：读到一篇关于 React 性能优化的长文

```bash
Web Clipper → 00-INBOX/
            → llm-wiki-local review: 外部素材 → record
            → 30-RESOURCES/书单/ + ## 来源 + ## 产出（信源落地SOP）
            → wiki-sync-local
```

**模式 B**：与 AI 讨论状态管理方案

```bash
对话结束 → AI 整理成 record（3 条主张 + 2 处未解决矛盾）
        → 人从中挑 2 句写成 atomic
        → 更新 [[Zustand vs Redux]] 的对比结论
        → wiki-sync-local
```

### 常见坑点

- ⛔ **模式 A 堆积**：剪藏太多不审核，Inbox 膨胀
	- 🔧 排查：定期审核，每周至少清理一次；`00-INBOX/` 只有一层，不建子目录
- ⛔ **模式 B 流失**：对话产生了好洞察但不记录，等同于没发生过
	- 🔧 排查：对话结束务必执行收尾四步（提取 → 判断 → 关联 → 入库）
- ⛔ **把剪藏长文当 `article` 送进 `60-BLOGS/`**：`article` 是「我自己写的对外输出」，剪藏是别人的东西。误判的代价是博客目录混入他人作品，且素材失去 `## 来源` 挂载位。
	- 🔧 排查：frontmatter 里有 `author` / `source` / `published` 的，先假设是 `record`
- ⛔ **让 AI 直接产出 `atomic`**：`atomic` 是「我的独立陈述句判断」，AI 起草的是「文本摘要」。直接落库会让 atomic 目录混入大量伪判断，而这个目录的价值恰恰在于「每一条都是人下过的判断」。
	- 🔧 排查：这条命题，我能说出它在什么条件下不成立吗？说不出就不是判断
