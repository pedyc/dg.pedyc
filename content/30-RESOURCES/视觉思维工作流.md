## 🚀 SOP：如何执行视觉化思考全流程

### 🎯 目标与触发条件 (Goal & Trigger)

> [!summary]
> 触发场景：当面对复杂问题理不清头绪、团队沟通出现歧义、或需要进行系统架构设计时。
> 预期结果：产出一份逻辑自洽、重点突出的视觉产物（如流程图、架构图或决策矩阵），而非艺术作品。

### 🛠 前置准备 (Mise-en-place)

- [x] 工具（Low-Fi）：纸笔、白板或 iPad，用于初期的 [[发散思维]]。✅ 2025-12-18
- [x] 工具（Hi-Fi）：[[Excalidraw]]（手绘风）、Lucidchart / Draw.io（严谨风）。✅ 2025-12-18
- [x] 心态：「Pattern over Art」——重逻辑模式，轻绘画技巧。✅ 2025-12-18
- [x] 参考：打开 [[视觉工具选择矩阵]] 备查。✅ 2025-12-18

### 🪜 核心流程 (The Workflow)

#### 阶段一：定义与诊断 (Look & See)

1. 一句话定义目标
	- 写下核心问题：是为了生成创意（发散），还是为了优化流程（收敛）？
	- 定义受众：是给自己看（草图），还是给老板看（决策图）？

2. 识别认知模式
	- ❓ 决策点：根据问题特征选择思维模型
		- 想要新点子 → [[发散思维]]（允许无约束联想）
		- 要搞清步骤 → [[线性思维]]（A → B → C）
		- 找根本原因 → [[系统思维]]（关注反馈循环）
		- 要做二选一 → [[批判性思维]]（评估权重与真假）
		- 搞不清层级 → [[结构化思维]]（分类与包含）
		- 需要讲故事 → [[类比思维]]（隐喻与映射）
		- 进阶：要转化为代码 → [[计算思维]]（If-Then 规则）

#### 阶段二：映射与草绘 (Imagine)

3. 选择视觉映射工具
	- 依据第 2 步的结论，查阅 [[视觉工具选择矩阵]]。
	- 简单性优先：能用火柴人解决的，不要用 3D 建模。

4. 快速草绘
	- 使用黑白线条快速勾勒骨架。
	- **不要**在这个阶段纠结配色和图标美观度。

#### 阶段三：优化与展示 (Show)

5. 应用 Gestalt 法则重构
	- 检查 [[Gestalt视觉法则]] 的应用情况：
		- 去噪：用「图形与背景」分离核心信息与背景噪音。
		- 分组：用「接近性」把相关的模块（如同一个微服务下的组件）放在一起。
		- 引导：用「连续性」和箭头指引视线流动。

6. 验证有效性
	- 自测问题：遮住文字说明，外行人能看懂图里 80% 的逻辑吗？
	- 如果看不懂，退回第 2 步，检查是否选错了认知模式（例如把循环系统画成了线性流程）。

### ⚠️ 常见坑点与排错 (Troubleshooting)

- ⛔ 反模式：装饰主义
	- 现象：花大量时间找好看的图标，但连线逻辑是乱的。
	- 修正：回到黑白模式，确认逻辑跑通后再上色。
- ⛔ 反模式：工具错配
	- 现象：用思维导图（树状）去画生态系统（网状），导致连线乱成一团麻。
	- 修正：切换为因果回路图或概念图。
- 🔧 故障排查：如果觉得图表太拥挤，用 [[奥卡姆剃刀]] 砍掉非核心元素。

### 🧬 原理与优化

- 底层逻辑：本流程基于 [[Dan Roam]] 的「看—观察—想象—展示」模型，以及 [[认知负荷]] 理论（想法分块）。
