## 问题

> 高并发场景（如秒杀、大促、热点新闻）下，大量用户同时访问，前端如何从各个层面优化以保障可用性和体验？

---

## 背景

高并发场景下，后端压力集中在流量入口，前端虽不直接应对并发请求，但大量用户的浏览器同时发起资源请求、接口调用、轮询，会导致 CDN 回源率飙升、接口超时、浏览器卡死等问题。前端的核心思路是 **帮后端减负 + 让自己更轻**。

---

## 解决方案

### 答案 1：静态资源缓存与 CDN

高并发下最立竿见影的手段——让请求止步于 CDN，不落到源站。

- **强缓存**：`Cache-Control: max-age=31536000, immutable` 对不常变的资源（图片、字体、chunk-vendors）设置一年强缓存，浏览器直接走本地缓存，零请求到达服务器
- **协商缓存**：HTML 等入口文件用 `ETag/Last-Modified`，CDN 节点验证文件是否变化
- **CDN 预热**：大促前主动将静态资源推送到 CDN 边缘节点，避免突发流量下的回源雪崩
- **资源合并**：HTTP/2 之前合并文件减少连接数；HTTP/2 下改为细粒度资源 + 按需加载

### 答案 2：首屏加载优化

用户感知到的"快"取决于首屏时间，而非全部资源加载完。

- **SSR/SSG**：首屏 HTML 由服务端生成，浏览器直接渲染，减少 JS 解析和执行时间
- **骨架屏**：数据到达前占位，消除白屏等待焦虑
- **关键 CSS 内联**：将首屏 CSS 内联到 HTML，非关键 CSS 异步加载
- **图片懒加载**：`loading="lazy"` 或 IntersectionObserver，首屏只加载视口内图片
- **资源预加载**：`<link rel="preload">` 提前加载关键资源，`preconnect` 提前建立连接

### 答案 3：请求优化与降级

高并发下要主动做减法——砍掉非核心请求，合并高频请求。

- **请求聚合**：短时间内多次请求合并为一次（如 `requestIdleCallback` 收集、批量发送）
- **防抖/节流**：搜索建议、滚动加载等高频触发场景必须限流
- **接口降级**：监控接口错误率，超过阈值时前端主动降级（展示缓存数据 / 静态占位 / 引导刷新）
- **轮询替代方案**：即时通信场景用 WebSocket/SSE 替代短轮询，减少 HTTP 连接开销
- **数据预取**：用户行为预测（如 hover 到链接时）提前拉取下一页数据

### 答案 4：渲染与计算优化

浏览器主线程是单线程，高并发下要避免长任务阻塞渲染。

- **虚拟列表**：长列表只渲染可视区域，内存占用和 DOM 节点数恒定
- **Web Worker**：数据处理、日志上报、加密运算等非 UI 操作移出主线程
- **`requestAnimationFrame` + 时间分片**：批量 DOM 操作分散到多帧，避免单帧 JS 执行超时
- **代码分割**：路由级的动态 `import()`，首屏只加载当前路由代码，非首屏路由延迟加载

### 答案 5：监控与容错

高并发时什么都可能发生，必须有监控和兜底。

- **Performance API + Web Vitals**：采集 LCP/FID/CLS 等真实用户指标
- **错误边界**：React `ErrorBoundary` 或 Vue `errorCaptured`，单个组件崩溃不影响全页
- **上报策略**：错误/性能数据用 `sendBeacon()` 上报，不阻塞页面卸载；上报队列做节流，避免高并发时上报流量压垮自己

### 我的理解

高并发前端优化的三条核心原则：

1. **能不请求就不请求** — 缓存 > CDN > 接口，越靠近用户的层解决问题越好
2. **能不渲染就不渲染** — 虚拟列表、懒加载、骨架屏，减少主线程的无效工作
3. **有备无患** — 降级方案 + 监控告警，假设一切都会挂

这些手段之间是乘法关系：CDN 命中率 95% × 缓存命中率 80% × 接口降级兜底，最终落到源站的流量可能只有原始流量的 1% 不到。
