> 虚拟列表的核心思想是只渲染可见区域——无论数据总量多大，只在 DOM 中维护当前视口能看到的 N 条元素，其余数据用空白占位模拟滚动高度。

## 论据/示例

```js
// 核心计算逻辑
function getVisibleRange(scrollTop, containerHeight, itemHeight, buffer = 2) {
  const startIndex = Math.max(0, Math.floor(scrollTop / itemHeight) - buffer)
  const visibleCount = Math.ceil(containerHeight / itemHeight) + buffer * 2
  const endIndex = startIndex + visibleCount
  return { startIndex, endIndex, visibleCount }
}

// 渲染时只需遍历 startIndex ~ endIndex
items.slice(startIndex, endIndex).map(renderItem)
```

关键数据：
- 1 万条数据，传统渲染 → 10000 个 DOM 节点，内存 ~50MB+
- 虚拟列表 → 固定 10~20 个 DOM 节点，内存 < 1MB
- DOM 节点数与数据总量无关，只取决于容器高度和 itemHeight
