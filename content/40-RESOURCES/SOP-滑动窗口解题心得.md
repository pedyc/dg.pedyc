## 🚀 SOP：滑动窗口解题法

> [!summary] 🎯 目标与触发条件 (Goal & Trigger)
> **触发场景**：当需要解决 **子串/子数组** 相关问题时，特别是涉及 **连续区间**、**满足特定条件的最长/最短子串**、**定长子串统计** 等场景。
> **预期结果**：将 $O(n^2)$ 的暴力解法优化为 $O(n)$ 或 $O(n \log n)$ 的高效解法。

### 🪜 核心流程 (The Workflow)

> 一句话概括：入、更新状态、出

#### 阶段一：初始化与定义

1. **定义变量**
	 - `i = 0` (窗口右边界，作为循环索引)
	 - `left = i-k-1` (窗口左边界，当 `left<0` 时窗口不存在，可以使用 `continue` 关键字跳过循环)
	 - `window = {}` 或 `new Map()` (记录窗口内元素状态)
	 - `result = 0` 或 `[]` (存储最终结果)
	 - `valid = 0` (记录窗口满足条件的程度)

#### 阶段二：确定循环结构

```javascript
var findMaxAverage = function (nums, k) {
    let avg = 0;
    let max = -Infinity;
    // 每次循环右指针扩张
    for (let i = 0; i < nums.length; i++) {
        avg += nums[i]
        let left = i - k + 1
        if (left < 0) continue;
        max = Math.max(avg, max)
        // 收缩窗口，为下一次循环做准备
        avg -= nums[left]
    }
    return max / k
};
```

#### 阶段三：确定窗口状态

- 每次循环窗口右边界扩张
- 在循环结束前手动收缩窗口左边界
- 确定窗口状态和循环约束条件

#### 阶段四：更新结果

6. **在合适的位置记录答案**
	 - **找最大窗口**：在收缩前或外层循环结束时更新
	 - **找最小窗口**：在收缩过程中更新

### ⚠️ 常见坑点与排错 (Troubleshooting)

- ⛔ **反模式**: 在收缩窗口时忘记更新 `window` 状态，导致状态不一致
- ⛔ **反模式**: 左右指针移动顺序错误，导致漏算或重复计算
- 🔧 **故障排查**:
	- 如果遇到 **无限循环**：检查收缩条件是否可能永远为真
	- 如果遇到 **结果错误**：添加 `console.log` 打印 `left`、`right`、`window` 状态，逐步调试
	- 如果遇到 **边界错误**：特别注意 `right-left+1` 与 `right-left` 的区别（包含右端点与否）

### 🧬 原理与优化

- **底层逻辑**: ==本流程基于 **双指针** 和 **哈希表** 的原理设计，通过维护一个动态窗口，避免重复计算。==
- **时间复杂度**: 每个元素最多被右指针访问一次，被左指针访问一次，因此是 $O(2n) \approx O(n)$。
- **空间复杂度**: 使用哈希表存储窗口状态，最坏情况 $O(k)$，其中 $k$ 是字符集大小。

### 📚 经典例题

1. **无重复字符的最长子串** (可变窗口，找最大)
	 - 关键：用 Set 记录窗口内字符，遇到重复时收缩
2. **最小覆盖子串** (可变窗口，找最小)
	 - 关键：用 Map 记录目标字符需求，valid 计数判断是否覆盖
3. **找到字符串中所有字母异位词** (固定窗口)
	 - 关键：窗口大小固定为 p 的长度，比较窗口与 p 的字符频率
