## 术语：依赖注入

> **主题**：#前端开发/设计模式

### 定义

依赖注入（Dependency Injection，DI）是一种设计模式，==将对象所需的依赖从内部创建改为从外部注入==，使调用方无需关心依赖的创建过程。

**核心原则**：Hollywood Principle —— "Don't call us, we'll call you"（不要调用我们，我们会调用你）

**三种注入方式**：
- **构造函数注入**：通过构造函数参数传入依赖
- **Setter 注入**：通过 setter 方法传入依赖
- **接口注入**：通过接口方法传入依赖

```typescript
// 传统方式：内部创建依赖（紧耦合）
class UserService {
  private db = new Database(); // 内部创建
}
// 调用方式
const service = new UserService(); // 在new的过程中已经耦合了db

// --- 分割线 ---

// 依赖注入：外部注入依赖（松耦合）
class UserService {
  constructor(private db: Database) {} // 依赖注入
}
// 调用方式
const db = new MySQLDatabase(); // 解耦
const service = new UserService(db); // 外部注入
```

### 跨学科含义

- **在 Java/Spring 中**：Spring Core 容器的核心功能，通过 IoC 容器管理 Bean 生命周期
- **在 Python/Django 中**：通过装饰器 `@inject` 或框架特性实现
- **在 JavaScript/前端中**：Angular 的依赖注入系统是典型实现
