## 问题

> 当前本库的双向链接多为"引用"（A 文提及 B 文），但理想的链接应成为"思维脚手架"——阅读 A 文时，通过链接自然联想到 B 文的论点，产生跨笔记的推理。如何实现从引用到脚手架的跃迁？

---

## 背景

本库目前有数百条双向链接，但多数是"一次性引用"：A 笔记引用了 B 笔记，阅读时点过去看一眼就返回，没有形成持续的思维支撑。真正有价值的链接应该像脚手架一样：

- 打开 A 笔记时，侧边自然浮现与当前议题相关的 B、C、D 观点
- 写作时，链接关系帮你发现"这个论点和那篇 atomic 冲突了"
- 思考时，链接网络帮你定位到"这个问题上次是怎么解的"

当前的本库结构（PARA + Zettelkasten）提供了链接的原料，但缺乏"链接即思考"的设计机制。

---

## 解决方案

### 答案 1：从"引用"升级为"理由化链接"

每次加链接时，不只写 `[[xxx]]`，而是写 **为什么链接**：

```bash
// 不推荐：这个方案也适用于 [[SOP-XXX]]
// 推荐：这个方案也适用于 [[SOP-XXX]]，因为两者共享同一个前提——前置过滤优于事后整理
```

**本质**：把"链接是什么"变成"链接为什么"，让链接承载推理关系。
**代价**：写作负担加重，需要多思考一层。

### 答案 2：定义链接的类型语义

借鉴知识图谱的关系类型，给链接打标签：

| 类型 | 语义 | 示例 |
|------|------|------|
| `支持` | B 支持 A 的论点 | A 引用 [[atomic-XXX]] 作为论据 |
| `反对` | B 与 A 矛盾 | A 与 [[concept-YYY]] 观点冲突 |
| `细化` | B 是 A 的具体化 | [[MOC-知识获取]] → [[SOP-信息收集工作流]] |
| `前提` | B 是 A 的逻辑前提 | 理解 A 前必须先读 B |
| `类比` | B 与 A 结构相似 | A 的机制类似于 [[C-ZZZ]] |

**实现方式**：MOC / concept 笔记中用表格或分节管理关系，而非简单罗列 wikilink。
**代价**：维护成本高，需要定期审计链接语义是否过时。

### 答案 3：基于当前上下文的"被动浮现"⭐

不改变链接方式，而是优化阅读界面（如 Obsidian 的 Graph View / Local Graph / 反向链接面板），让相关笔记自然浮现。

**关键优化点**：
- 善用 Local Graph 而非 Global Graph（前者聚焦当前笔记邻域）
- 为常用概念建立"锚点 MOC"，让 MOC 成为思维的枢纽节点
- 在 concept 笔记中设"争议与矛盾"章节，主动暴露不一致

**优势**：零额外写作负担
**劣势**：依赖工具能力，无法在写作时主动引导思考
**洞察**：这是本库所使用的方式

### 我的理解

三个答案互补，分别作用于不同环节：

```bash
写作时（理由化链接）→ 组织时（链接类型化）→ 阅读时（被动浮现）
    ↑                                        |
    └────────────────────────────────────────┘
```

写作时标注链接理由，组织时赋予语义类型，阅读时利用工具被动浮现。三者形成闭环：每次阅读暴露新的连接点，促使你补充理由化链接。

当前本库最缺的是"理由化链接"——大多数链接只有位置没有原因。可以先从 atomic 笔记入手，每条引用加上"为什么"。
