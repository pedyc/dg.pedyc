> Svelte（4 及以前）不在运行时记录「旧值」来判断变化，而是给每个响应式变量在编译期分配固定的一位：赋值即 `|=` 点灯，更新函数用一次 `&` 判断自己那一组依赖里有没有灯亮。

**边界**：这套方案要求「被标记的东西在编译期就有固定编号」。Svelte 5 的信号在运行时创建、数量不固定，且「脏」不再是一张成员表而是每个节点各自的状态字段（`CLEAN` / `DIRTY` / `MAYBE_DIRTY`）；位标志仍在用，但编码的已是一个节点的几个布尔属性，而不是「哪些变量变了」。所以这个说法要带版本，不能当作 Svelte 的通性。

## 论据/示例

**产物里的两行**。编译后的组件实例持有 `$$.dirty` 数组，`$$invalidate(i, value)` 落到 `make_dirty`：

```js
function make_dirty(component, i) {
	if (component.$$.dirty[0] === -1) {
		dirty_components.push(component); // 本轮第一次变脏：入队 + 申请一次 flush
		schedule_update();
		component.$$.dirty.fill(0);
	}
	component.$$.dirty[(i / 31) | 0] |= 1 << (i % 31);
}
```

模板更新函数则用掩码把自己那一组依赖一次性问完：

```js
p(ctx, [dirty]) {
	if (dirty & /*count*/ 1) set_data(t0, /*count*/ ctx[0]);
	if (dirty & /*doubled*/ 2) set_data(t2, /*doubled*/ ctx[1]);
}
```

`/*count*/ 1` 里的 `1` 不是运行时算出来的，是编译器把 `1 << 变量编号` 折叠成的**字面量**。这一步是整件事的关键：`&` 的右操作数在构建期就定了，运行时既没有查表也没有移位，只有一次整数比较。

**为什么是位而不是数组或 Set**。三种存法的成本差在「问一次」上：

| 存法 | 标记 | 问「这组里有没有变」 |
|:--|:--|:--|
| 对象/Map 按变量名 | 一次写入 | 逐个 `get` + 判断 |
| 数组按下标 | 一次写入 | 逐个比较，长度随变量数增长 |
| 位掩码 | 一次 `\|=` | **一次 `&`**，与变量数无关 |

换句话说，位掩码把「N 个布尔量」压成「一个字」，让判断的代价与 N 解耦。它还顺带省掉了旧值——判断变化通常要保存上一轮的值来比，而这里只需要「变了没」这一个是非。

**31 与 `-1` 这两个数字都不是随手写的**。JS 的位运算走有符号 32 位，第 32 位是符号位；若一段用满 32 位，全置 1 的那一段值就是 `-1`，与「本轮还没入队」的哨兵撞车。留一位出来，任何组合的结果都恒为非负，哨兵才判得准。`(i / 31) | 0` 取段号、`1 << (i % 31)` 取段内位，也是同一个约束的下游结果。

**5 换了什么**。不是「不用位了」，而是位不再承担编号映射：

| | 位编码什么 | 「哪些脏了」由谁回答 |
|:--|:--|:--|
| Svelte ≤ 4 | 变量编号 → 位（一张成员表） | 一个整数，编译器算好常量掩码 |
| Svelte 5 | 单节点的多个布尔属性（脏/半脏/派生/已销毁） | 依赖图上的标脏传播 + 逐节点状态 |

代价与收益是配套的：4 的方案快，但编号必须构建期固定，依赖关系也只能静态推导；5 换成运行时可建的图，能免疫重构，但「查谁脏了」重新变成一次遍历。
