> 「要不要拆」看三个正当理由，「怎么拆」只看上下文边界——找一块几乎不需要系统其余部分、干完只需回传一个紧凑结果的工作，而不是按业务问题类型切。

**边界**：这条只管怎么拆，不管要不要拆。上下文膨胀导致可测量的性能退化、需要并行且用完即弃的新窗口、单循环选不对工具或指令冲突——三个理由都不成立时，正确答案是一个都不拆。

## 论据/示例

按问题类型切的 agent 之间必须来回传信息，每传一手都掉一层保真度，Anthropic 把这称为传话游戏；按上下文边界切的（独立研究路径、接口干净的组件、黑盒验证）每次只需回一个紧凑结果。一家公司把客服 agent 里十几个按业务域切的专家子代理，收回到「一份 system prompt + 4-5 个薄数据工具 + 硬输出护栏」，品牌一致性与延迟同时改善。
