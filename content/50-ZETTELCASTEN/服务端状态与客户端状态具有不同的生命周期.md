> 区分两类状态的关键不是「存在哪」，而是**权威副本在谁手里**：客户端状态的权威副本就在本地；服务端状态的权威副本在远程，客户端那份只是缓存。

**边界**：这不等于「服务端数据不能放进 Store」，而是「放进 Store 的那份要按缓存对待」——要处理失效、重验证、并发和失败恢复。纯前端生成的交互状态（弹窗开关、草稿、选中项）用不上这套。

## 论据/示例

同一个用户资料页面上两类状态并存：

```tsx
const [isEditing, setIsEditing] = useState(false);   // 客户端：本地说了算
const { data: user } = useQuery({                     // 服务端：只是缓存
  queryKey: ["user", userId],
  queryFn: () => fetchUser(userId),
});
```

`isEditing` 由当前交互控制，组件卸载就没了；`user` 的权威数据在服务端，还可能被别的用户或后台任务改掉，客户端这份随时可能过期。要的不是同一套机制——前者要状态容器，后者要缓存与重验证。
