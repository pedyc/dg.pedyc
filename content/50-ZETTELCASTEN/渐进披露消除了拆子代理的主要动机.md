> 技能与工具能按需加载之后，「怕 system prompt 膨胀、怕上下文过载」就不再是拆子代理的理由——它本来是拆分的头号动机。

**边界**：前提是 harness 真的支持延迟加载，且技能与工具的触发描述写得准。省下来的复杂度会转移到纪律上：一份精心管理的 system prompt、对上下文窗口与记忆的刻意处理。缺这份纪律，单循环会比多代理更差。

## 论据/示例

Claude Code 面向更强的模型把 system prompt 砍掉 80% 以上，砍的正是与渐进披露技能和工具相关的部分——说明这部分膨胀原本是被 harness 的设计不当撑起来的，不是任务的客观需要。
