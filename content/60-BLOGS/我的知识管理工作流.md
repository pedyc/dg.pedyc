> 核心观点：通过 PARA（行动层）+ Zettelkasten（能力层）+ LLM Wiki（维护层）的三层架构，实现知识从收集到内化再到持续维护的完整闭环。

---

## 引言

这篇文章用于记录我对知识管理的思考，还有方法论的迭代。过去几年我尝试过多种笔记方法，从最初的线性记录，到 PARA 行动导向，再到 Zettelkasten 的网状连接，现在结合 LLM 形成了相对完整的知识管理工作流。

---

## 以 PARA 为核心

[[PARA]] 笔记法是一种行动导向型的笔记方法，以 Project 为核心，通过需求推进知识系统。例如我现在想学习 AI，新建一个 "AI 学习项目 "，去收集这个项目需要的资源例如文章、笔记，构建概念系统，规定里程碑。所有的一切都围绕**项目**这个核心。

但 PARA 也有兼顾不到的地方，例如一个项目完成了它的生命周期，那么围绕这个项目的笔记都会被归档，但这并不意味着这些笔记就没用了。

另外，PARA 是围绕项目的结构，当你单独索引一篇笔记时，实际上被困在这个项目结构里。打个比方：我有一个项目 " 找到一份薪水超过 30k 的前端工作 "，为此收集了需要学习的知识、设定了里程、写了许多相关的笔记。此时这些笔记处于这个项目结构里，和这个项目是紧密耦合的，当你在其他的笔记中引用这些笔记大概率并不能直接使用（包含笔记外的噪音），需要进行解耦抽象的工作。对所有项目相关的笔记都进行类似的操作需要花费大量的精力成本。

---

## 结合 Zettelkasten

[[卡片盒笔记法|Zettelkasten]] 的核心是连接，通过笔记间的双向链接构建知识网络。我将 Zettelkasten 作为**能力层**，PARA 作为**应用层**。能力层构建知识资产，应用层只进行引用而不直接参与知识构建。

这解决了 PARA 的一个核心问题：当项目归档后，笔记并没有消失，而是回归能力层，通过 Zettelkasten 的连接继续发挥价值。当新项目需要某个知识点时，可以在能力层检索，通过链接网络找到相关笔记，而不需要重新学习。

```bash
应用层（PARA）：Project → Area → Resources → Archive
       ↓ 引用
能力层（Zettelkasten）：原子笔记 → 概念笔记 → 术语笔记
```

## LLM Wiki 方法论

在 AI 时代，我引入了 [[LLM Wiki]] 的方法来维护知识库。传统 RAG 的问题是 LLM 每次回答都从零发现知识，没有积累。而 LLM Wiki 的核心是**LLM 增量构建和维护一个持久的 wiki**——一个结构化的、互相链接的 markdown 文件集合，介于你和原始资料之间。

当你添加新资料时，LLM 不会只索引它供后续检索，而是会：
- 读取资料，提取关键信息
- 整合到现有 wiki 中
- 更新实体页面、修订主题摘要
- 标注新旧数据矛盾之处
- 加强或挑战已有综合观点

这意味着知识只编译一次，然后**保持最新**，不需要每次查询时重新推导。

### 三层架构

LLM Wiki 有三层结构：

- **Raw Sources（原始资料）**：文章、论文、图片等不可变资料，是知识源
- **The Wiki（知识库）**：LLM 生成的 markdown 文件，包括摘要、实体页、概念页、对比表等
- **The Schema（规范）**：CLAUDE.md 等配置文件，告诉 LLM wiki 的结构和约定

### 操作流程

- **Ingest（摄入）**：将新资料放入原始收藏，LLM 处理后更新 wiki（可能涉及 10-15 个页面）
- **Query（查询）**：向 wiki 提问，LLM 搜索相关页面并综合回答，好的答案可以存回 wiki
- **Lint（检查）**：定期让 LLM 健康检查 wiki，查找矛盾、过时断言、孤儿页面、缺失链接

### 模板驱动 + LLM Wiki

我之前的 " 模板驱动 " 方法让 AI 根据模板严格分类笔记，与 LLM Wiki 结合后形成更完整的工作流：

1. 资料摄入 → LLM 按模板生成标准化笔记
2. 笔记存入 wiki → LLM 维护双向链接和索引
3. 问题查询 → LLM 基于 wiki 回答，好答案再存回 wiki
4. 定期 Lint → LLM 检查 wiki 健康度

---

## 总结

我的知识管理工作流经历了三次迭代：

- **v1**：纯 PARA，优点是行动导向，缺点是项目归档后笔记难以复用
- **v2**：PARA + Zettelkasten，引入能力层解决笔记孤立问题
- **v3**：PARA + Zettelkasten + LLM Wiki，LLM 负责维护工作，让知识库持续生长

当前工作流的核心是：**人负责源资料和提问，AI 负责所有的整理、链接和维护工作**。这样我可以将精力集中在真正重要的部分：思考什么知识值得获取，什么问题值得探索。
