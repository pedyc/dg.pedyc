前端性能优化的核心指标有哪些？分别代表什么含义？	<strong>FCP（First Contentful Paint）</strong><br>首次内容绘制，浏览器首次绘制任何内容（文本、图片、canvas）的时间。<br><br><strong>LCP（Largest Contentful Paint）</strong><br>最大内容绘制，视口中最大元素（图片、视频、文本块）渲染完成的时间。<br>• 优秀标准：≤ 2.5s<br><br><strong>FID（First Input Delay）</strong><br>首次输入延迟，用户首次与页面交互（点击、按键）到浏览器响应的时间。<br>• 优秀标准：≤ 100ms<br><br><strong>CLS（Cumulative Layout Shift）</strong><br>累积布局偏移，页面生命周期中意外布局移动的分数。<br>• 优秀标准：≤ 0.1<br><br><strong>TTI（Time to Interactive）</strong><br>可交互时间，页面完全可交互的时间点。<br><br><strong>TBT（Total Blocking Time）</strong><br>总阻塞时间，FCP 到 TTI 之间长任务的总时长。	性能指标

什么是虚拟滚动（Virtual Scrolling）？如何实现？	<strong>原理</strong><br>只渲染可视区域内的列表项，通过动态计算滚动位置，替换可见数据，实现大量数据的流畅滚动。<br><br><strong>核心实现思路</strong><br>1. 计算可视区域可容纳的列表项数量<br>2. 监听滚动事件，计算当前滚动位置对应的起始索引<br>3. 仅渲染起始索引到结束索引范围内的数据<br>4. 使用占位元素撑开滚动条高度（总高度 = 单项高度 × 总数量）<br><br><strong>代码示例</strong><br>// 简易虚拟滚动核心<br>const startIndex = Math.floor(scrollTop / itemHeight)<br>const endIndex = startIndex + visibleCount<br>const visibleData = data.slice(startIndex, endIndex)<br>// 渲染 visibleData，使用 transform 偏移位置<br><br><strong>现成方案</strong><br>• vue-virtual-scroller<br>• react-window / react-virtualized<br>• 原生虚拟滚动库	渲染优化
如何利用 GPU 加速提升动画性能？	<strong>原理</strong><br>浏览器将元素提升为独立图层（Composite Layer），动画在该图层独立合成，不触发重排重绘，由 GPU 加速渲染。<br><br><strong>触发独立图层的属性</strong><br>• transform: translateZ(0) / translate3d(0,0,0)<br>• will-change: transform / opacity<br>• video、canvas、iframe 元素<br><br><strong>适合 GPU 加速的动画</strong><br>• transform: translate、scale、rotate<br>• opacity 透明度变化<br><br><strong>注意事项</strong><br>• 不要滥用，每个图层占用内存<br>• 动画结束后移除 will-change<br>• 避免对大量元素单独创建图层<br><br><strong>对比</strong><br>• left/top 动画：触发重排，性能差<br>• transform 动画：仅合成，性能好	渲染优化

什么是 Scope Hoisting？有什么作用？	<strong>定义</strong><br>Webpack 的作用域提升，将多个模块合并到一个函数作用域中，减少闭包包装，提升执行效率。<br><br><strong>原理</strong><br>• 传统打包：每个模块被包裹在函数中，存在闭包开销<br>• Scope Hoisting：将模块代码提升到同一个作用域，减少函数调用<br><br><strong>配置</strong><br>optimization: {<br>  concatenateModules: true  // 生产模式默认开启<br>}<br><br><strong>效果</strong><br>• 减少打包体积（约 10-15%）<br>• 提升代码执行速度<br><br><strong>限制</strong><br>• 仅支持 ES Module，不支持 CommonJS<br>• 非直接引入的模块（如通过变量引入）无法提升	打包优化

gzip 和 Brotli 压缩有什么区别？如何配置？	<strong>gzip</strong><br>• 基于 LZ77 算法，压缩率约 70%<br>• 兼容性好，所有浏览器都支持<br>• 压缩速度较快<br><br><strong>Brotli</strong><br>• Google 开发的压缩算法，压缩率比 gzip 高 15-20%<br>• 压缩速度较慢，解压速度与 gzip 相近<br>• 浏览器支持度 97%+（IE 不支持）<br><br><strong>选择策略</strong><br>• 优先使用 Brotli（更高压缩率）<br>• 回退到 gzip（兼容性）<br><br><strong>Nginx 配置</strong><br># Brotli 模块<br>brotli on;<br>brotli_comp_level 6;<br>brotli_types text/plain text/css application/javascript;<br><br># gzip<br>gzip on;<br>gzip_comp_level 6;<br>gzip_types text/plain text/css application/javascript;<br><br><strong>Webpack 配置</strong><br>• CompressionWebpackPlugin 生成 .gz 和 .br 文件<br>• 服务端根据 Accept-Encoding 返回对应格式	网络优化
什么是 HTTP/2 服务端推送？如何配置？	<strong>定义</strong><br>HTTP/2 Server Push，服务器在响应 HTML 时主动推送客户端后续可能需要的资源（如 CSS、JS），无需等待客户端解析 HTML 后发起请求。<br><br><strong>实现方式</strong><br>• 服务器通过 PUSH_PROMISE 帧告知客户端即将推送的资源<br>• 客户端可选择接受或拒绝<br><br><strong>Nginx 配置</strong><br>location / {<br>  http2_push /css/style.css;<br>  http2_push /js/app.js;<br>}<br><br><strong>注意事项</strong><br>• 可能推送已缓存资源，造成带宽浪费<br>• HTTP/2 规范允许客户端拒绝推送（RST_STREAM）<br>• 已被 Cache 的资源不会重复推送<br>• 现代浏览器已支持 preload 替代部分推送场景<br><br><strong>替代方案</strong><br>• preload 预加载 + HTTP/2 多路复用<br>• 合理使用 push 而非滥用	网络优化
