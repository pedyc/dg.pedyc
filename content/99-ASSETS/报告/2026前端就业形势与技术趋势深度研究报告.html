执行摘要：五条核心判断

CORE CONCLUSION

结论先行：前端岗位没有消失，消失的是"只负责把设计稿翻译成代码"这一职能层级。2026 年的市场不是总量崩塌，而是从"金字塔"变为"哑铃 / K 型"——初级执行岗被批量压缩，中高级、全栈化、AI 融合型岗位同时扩张。对一名已具备 TS / React / Vite 能力的工程师而言，风险不在"栈过时"，而在"能力停留在该栈最容易被商品化的那一层"。

因此本报告的最终建议是：不换赛道，沿现有栈向两侧各延伸一层——向下延伸到工具链、渲染原理、类型系统与质量治理；向后延伸到服务端 / BFF / 全链路交付；向前延伸到 AI 应用前端工程化与 Agent 编排；并以垂直业务理解作为不可替代性的落点。

判断一 · 就业：结构性替代，非周期性衰退

国内多个口径同时出现"初级岗 −62%、普通前端岗 −52%"与"前端相关岗位总量 +12.2%"的相反读数，本质是统计口径不同：前者统计"普通前端开发"细类，后者含 AI 融合、全栈与灵活用工。结构性信号在所有来源中高度一致：初级占比从 48% 降至 22%，3 年以上经验要求岗位超七成，中高级 / 全栈可视化岗 +38%。[S8][S20]

判断二 · 机制：AI 切断的是"学徒制"入口

斯坦福数字经济实验室基于 ADP 薪资数据的研究显示，22–25 岁高 AI 暴露职业的就业较趋势低约 19%，资深群体无同类缺口，缺口主要来自少招新人而非裁员。美国劳工统计局同时预测 2025–2035 软件开发者 +10%、纯"程序员"岗位 −7%。AI 替代的是可编码化知识，互补的是实践中积累的隐性知识。[S7]

判断三 · 技术：编译期化 + 原生化 + AI 原生化

React Compiler v1.0 与 RSC 把优化从运行时搬到编译期与服务端；TypeScript 7.0（Go 重写，8–12× 提速）、Vite 8 + Rolldown（Rust，10–30× vs Rollup）完成工具链原生化；AI 从编码辅助升级为应用形态本身（流式 UI、Generative UI、Agent UI、MCP / AG-UI / A2UI）。业务代码写法几乎未变，变的是工程基座与交付对象。[S1][S5][S6][S12]

判断四 · 定位：TS/React/Vite 是资产，不是负债

State of JS 2025 显示 React 仍以 83.6% 使用率居首、Vite 满意度 98%、仅用 TypeScript 的开发者达 40%。三者均有清晰升级路径且治理稳定（React 于 2026-02 移交 Linux 基金会）。真正贬值的不是栈本身，而是"只会调用框架 API 写组件"这一层能力。[S1][S2][S3]

判断五 · 优先级：先补"验证与判断"，再补"生成与广度"

Stack Overflow 2026 调查（30,000+ 样本）：66% 使用编码助手 / Agent，但仅 6.6% 愿意让 AI 做重要决策，78.7% 认为代码来源可追溯重要或非常重要，仅 24% 的企业发布了正式 AI 使用规范。稀缺的不是"会用 AI 生成"，而是"能定义任务、审查产出、约束边界、并对结果负责"。这也是能力建设应最先投入的方向。[S4]

阅读前须知 · 关于数据强度
本报告中，React / Linux Foundation / State of JS / Stack Overflow / The Register / BLS 等属于可核验的一手或权威二手来源；国内招聘平台的 −62%、−52%、+12.2%、127:1 等数字多为媒体与内容聚合站转述，原始报告样本与口径难以直接核验。本报告将其作为方向性信号而非精确值使用，并在第五章给出完整的可信度分级与冲突辨析。个别流传极广的说法（如"高阶 AI 前端薪资差 100 倍""三年淘汰 90% 程序员"）缺乏数据支撑，不予采信。

1.2 结构变化的三个机制

机制一：AI 优先替代"学徒岗"，而非"工程师岗"

被压缩的岗位具有高度一致的特征：需求明确、输出可视化、结果易验证、训练数据充足——基础页面、标准组件、CRUD 接口、测试用例、文档、简单缺陷修复。这些恰是历史上用于培养新人的任务。资深工程师现在用 AI 直接完成，不再向下分派，导致"初级写代码 → 中级管项目 → 高级定架构"的阶梯被抽掉第一级。斯坦福研究者称之为"资历偏向型技术变革"（seniority-biased technological change）。[S7][S20]

需强调一个重要的长期反噬风险：企业个体"砍初级 + 给资深配 AI"是短期理性决策，但行业整体将面临 3–5 年后的资深工程师供给断层。多家来源（Korn Ferry、McKinsey 相关引用）已提出该问题，但招聘市场尚未响应。这意味着当前中级工程师在中期反而可能获得稀缺性溢价。

机制二：前后端职能边界被 AI Coding 抹平

多家媒体报道 2026 年国内大厂出现密集的组织调整：美团 Keemart 前后端团队合并、得物前端部门并入服务端、网易智企前端并入后端、蚂蚁推动测试转研发并过渡为全栈。这类信息的原始出处多为技术自媒体，属三级来源，应作为趋势信号而非确证事实。但更可靠的证据来自招聘 JD 本身——岗位名称与任职要求的变化是可直接观察的：

机制三：供给端过剩放大筛选强度

国内计算机类专业年毕业生规模超 50 万，简历同质化严重（大量"学了 Vue/React + 做了个电商网站"）。需求结构收缩叠加供给放量，把筛选推到极端：初级岗 127:1、1–3 年纯编码岗简历通过率从 2023 年 25% 降至 2026 年 7%。学历与框架熟练度的区分度下降，差异化项目经历、工程深度与业务理解成为主要筛选器。[S8][S20]

常见误读纠正 · FDE 不是"前端岗位"
多篇 2026 年中文爆款文章将 FDE（Forward Deployed Engineer）译作"前端部署工程师"，并以"FDE 暴涨 42 倍 / 1523%"论证前端行情反转。这是概念误用：FDE 中的 "front" 指客户现场的最前线（front line），源自 Palantir 的驻场工程师模式，职责是把模型 / 平台能力部署进客户真实业务，与 frontend 技术栈无直接关系。该岗位确实高薪且增长快，但它不是前端工程师的直接转型岗位，把它算作"前端岗位增长"会显著高估本赛道机会。涉及 FDE 的中文报道自己也已在正文中澄清这一点，但标题与数据表仍造成广泛误读。

1.4 国际交叉印证：这不是中国独有现象

  • 美国 BLS（2026-08 更新）：软件开发者 2025 年 171.78 万个岗位，2025–2035 预计 +10%（约 +17.5 万）；"计算机程序员" −7%。BLS 明确将差异归因于重复性编程任务自动化，以及部分高技能编程工作向开发者岗位转移。[S7]
  • 斯坦福数字经济实验室（ADP 薪资数据，2026-08 修订）：未发现大范围岗位替代，但 22–25 岁高 AI 暴露职业就业较趋势低约 19%，资深群体无同类缺口；作者强调这是描述性早期指标而非因果估计，且部分分化早于生成式 AI。[S7]
  • Dice（2026 Q1）：软件开发职位发布 −22%，而标题含 AI 的职位 +173%。Indeed：软件开发职位自 2025-02 起 +15%，但增量 71% 来自高级职位。[S20][S21]
  • Stack Overflow 2026：仅 22% 开发者对当前工作满意，45% 处于"躺平"状态；自由职业（一人公司）比例从 4% 升至 10%——AI 使单人覆盖全栈更可行，这既是机会也是雇佣关系弱化的信号。[S4]

综合判断："前端岗位减少"与"前端相关需求增长"可以同时成立，它们描述同一 K 型结构的两端。对个人的含义是——不要用行业总量做职业决策，要用自己所处的岗位层级做决策。处于执行层，宏观回暖与你无关；处于判断层，宏观收缩也不必然伤及你。

2.1 主线一 · 编译期化与服务端化：前端正在变成"编译器问题"

过去十余年，框架在运行时解决性能问题（Virtual DOM diff 是典型代表）。2026 年主流框架已收敛到同一判断：运行时工作太贵，应尽可能前移到构建期或服务端。

值得注意的反向信号
State of JS 2025 中，Next.js 使用率 59% 却只有 21% 正面情绪 / 17% 负面情绪，是评论最多的项目，高频抱怨为"复杂度已经高得离谱"与对 Vercel 商业策略的疑虑。Solid.js 连续第五年满意度最高，Astro 在内容型场景持续扩张。这说明"元框架一统江湖"并非无代价：Cache Components、PPR、Server Actions 带来的是认知负担与调试复杂度的显著上升。对工程师而言，理解"何时不该用 RSC"与"何时用"同样有价值。

2.2 主线二 · 工具链原生化：JS 工具用原生语言重写完成

2026 年是前端工具链十余年来最集中的一次替换：VoidZero 系（Vite / Rolldown / Oxc / Oxlint / Oxfmt）+ TypeScript Go 移植 + Node 原生类型擦除共同构成端到端原生链路。关键特征有三：

  • 统一而非叠加：Vite 8 用 Rolldown 同时承担开发与生产打包，消除了"dev 与 prod 行为不一致"这一整类缺陷；Oxc 提供共享 parser，让编辑器、CI、构建工具使用同一基础设施。
  • 破坏性变更集中在配置层：TS 7.0 移除 target: es5、baseUrl、AMD/UMD/SystemJS 模块选项；TS 6.0 已把 strict 设为默认。升级工作主要是清理 tsconfig 与验证插件兼容性，而非重写业务代码。
  • 职责分离：Node.js 24.12 / 25.2 起原生类型擦除稳定（自 22.18 默认开启），但只擦除不检查、不支持需要代码生成的 TS 语法；类型检查交给 TS 7。"能运行类型化文件"与"类型正确"成为两件独立的事。

配套变化：Biome / Oxlint 正在替代 ESLint + Prettier（速度 10–100×）；Vitest / Playwright 是测试层增长最快的两项（State of JS 2025 各 +14% 使用率）；Interop 2026 于 2026-02-12 发布 20 个重点领域，anchor positioning、滚动驱动动画、可定制 select、if() 等原生 CSS 能力逐步替代 JS 定位计算与滚动监听。[S3][S5][S6][S12]

对 TS / Vite 使用者的直接含义
你的工具链经验没有作废，但需要从"会配置"升级到"会诊断"：理解 Rolldown 与 Rollup 插件 API 的兼容边界、能读构建分析 DevTools、能评估 full bundle dev 模式的适用性、能规划 Vite 7 → rolldown-vite → Vite 8 的渐进迁移、能判断 TS 7 对 vue-tsc / typescript-eslint / 代码生成类工具的影响。这类能力无法靠 AI 直接生成，且在大团队里稀缺。

2.3 主线三 · AI 原生化：从"用 AI 写代码"到"为 AI 做前端"

这是与职业前景关联最强的一条主线，需区分两个不同层次：

层次 A：AI 进入研发流程（工具侧）

Stack Overflow 2026：66% 使用编码助手 / Agent、63% 使用通用聊天工具、26.2% 使用自动化 Agent 工作流，仅 17.2% 完全不用；74% 认为 AI 对"实现"有用，66% 对调试/重构有用，但涉及团队沟通（45%）与设计（50%）时 usefulness 显著下降。AI 的价值集中在离代码近的环节。框架也开始把 Agent 当作一等用户：Next.js 通过 DevTools MCP 与 AGENTS.md 向编码 Agent 暴露运行时错误、路由信息与版本匹配文档。[S4][S12][S18]

层次 B：AI 成为前端的交付对象（产品侧）

这一层是 2026 年前端新增的技术面，也是 TS/React 工程师最自然的扩展方向：

前端工程师在这一层具备结构性优势：async/await、SSE、API 集成、状态机、组件化、错误边界这些日常技能可直接迁移到 LLM 流式输出、工具调用与 Agent 状态管理；而多数 AI 后端工程师做不出可用的交互界面。这是本报告建议优先投入"AI 应用前端"而非"转算法 / 转纯后端"的核心依据。

2.4 横切变量一 · 安全与供应链成为新的能力壁垒

2025-12 至 2026 年，RSC 协议连续出现多个高危漏洞：CVE-2025-55182（CVSS 10.0，"React2Shell" 未认证 RCE）、源码泄露与多个 DoS 类 CVE、2026-05 单批 13 个 Next.js 公告、2026-10 一份 CVSS 9.5 的 RSC RCE 公告。同期还出现 axios npm 包供应链投毒（2026-03-31）。AI 生成代码的常见缺陷被反复记录为：IDOR、无鉴权管理后台、密钥硬编码进前端 bundle。[S14]

三个实践结论：（1）"升级 react 包"不等于修复——Next.js 内置自己的 RSC 运行时副本，必须同时升级框架并重新部署所有 preview / branch 环境；（2）采用 BFF 模式隐藏密钥、集中鉴权，是 AI 应用的标准安全边界；（3）把 AI 输出一律视为不可信输入，渲染前净化，工具调用按副作用严重度分级审批。这类"对结果负责"的能力，正是 AI 最难替代、企业最愿意付费的部分。

2.5 横切变量二 · 跨端与端侧算力（中国市场特有增量）

HarmonyOS NEXT 采用 ArkTS / ArkUI，不再兼容传统 Android 思路，带来一批明确要求"React / TypeScript 背景 + 鸿蒙转化"的岗位。真实 JD 中出现这样的表述："若具备前端 React 背景：利用 React / TypeScript / JSX 思维优势，承接 Web 或跨端业务向 ArkUI 的转化，处理前端工程化（Webpack / Vite）、状态管理（Redux / Zustand）与鸿蒙原生状态的映射"，以及 "React Native 与鸿蒙原生模块之间的通信及混合开发"。[S15]

同时，WebGPU 成熟使 3D / 可视化 / 端侧推理成为可持续增长的细分方向（Three.js、Babylon.js、点云与三维编辑器岗位在招）。判断：这两条属于"有明确业务场景才值得投入"的差异化方向，不建议作为通用前置技能；但若你所在行业是移动端、车机、IoT、工业软件或数据密集型产品，它们的稀缺度显著高于通用 Web 前端。

3.2 护城河从"会写"迁移到"会判"

高替代风险的能力画像

按设计稿 1:1 还原页面；模板化 CRUD 与基础组件；靠记忆调用框架 API；缺乏系统调试与线上问题定位能力；无法判断 AI 生成代码是否合理；把"熟练使用某框架"当作主要资历；工作内容高度标准化且产出可立即目视验证。

高溢价的能力画像

需求拆解与技术方案权衡（"为什么这样而不是那样"）；架构设计与边界划分；对 AI 产出的审查、纠错与安全把关；性能 / 稳定性 / 成本的系统性治理；垂直行业 know-how；把模糊业务目标翻译成可执行技术指标；端到端交付并对结果负责。

04

能力增强方向：分层路线与锚点项目

STRATEGY

总策略：不换赛道，沿现有栈向外延伸一层。TS / React / Vite 是当前最主流、升级路径最清晰、且与 AI 工具配合最好的组合；放弃它去从零学 Java 或 Rust 全栈，会同时损失既有资产与迁移速度。真正需要做的是三个延伸：向下（工具链、渲染原理、类型系统、质量治理）、向后（Node / BFF / 数据 / 部署 / 全链路交付）、向前（AI 应用前端与 Agent 编排），再以垂直业务理解作为差异化落点。

4.2 分层路线：P0 / P1 / P2

P0 · 立即把现有栈从"会用"升级到"能诊断、能审查"0 – 3 个月
  • AI 编码工程化（第一优先）：在仓库落地 AGENTS.md 项目规则、把重复任务沉淀为可复用 Skill、建立"外部验证"闭环（类型检查 + 测试 + 浏览器验证 + diff 边界），而不是靠 Agent 自称完成。学会写精确的任务说明、审查大体积 diff、识别"几乎对但差一点"的产出。同步建立团队级 AI 使用规范（哪些代码 / 数据可外发、生成代码的来源与许可、评审要求）——Stack Overflow 数据显示 76% 的组织尚未做这件事，这本身就是可陈述的差异化贡献。
  • TypeScript 深度：strict 全开并补 noUncheckedIndexedAccess / exactOptionalPropertyTypes；掌握泛型、判别联合、模板字面量类型、satisfies、never 穷尽检查；用 Zod（或 Valibot）把运行时校验与静态类型统一到单一 schema；理解 TS 7 的破坏性变更并清理 tsconfig（移除 target: es5、baseUrl、AMD/UMD/SystemJS），评估依赖 Compiler API 的工具链兼容性。
  • React 19 现代模型：理解 Compiler 之后"无需手写 memo"的心智模型；掌握 RSC 服务端/客户端边界、序列化约束、use()、Server Actions、Suspense 流式与 View Transitions；理解 Next 16 Cache Components 的 opt-in 缓存与 PPR 静态壳；同时明确"何时不该用 RSC"。
  • Vite 8 / 构建诊断：走通 Vite 7 → rolldown-vite → Vite 8 的渐进迁移；能读构建分析 DevTools、定位大模块图瓶颈、评估插件兼容；用 Oxlint / Biome 替换 ESLint + Prettier 的可行性与代价。
  • 性能与质量基线：接入 web-vitals RUM，看 LCP / INP / CLS 的 P75 而非平均值；把性能预算写进 CI（bundle 体积、LCP 2500ms、INP 200ms）；用 Vitest + Playwright 建立可回归的测试层。
可验证产出：一份仓库级 AGENTS.md + AI 使用规范；一次现有项目 Vite/TS 升级的迁移记录（含前后构建与 CI 时长数据）；一个带 RUM 看板与性能预算的性能基线报告；一段"AI 生成代码被发现并修正"的具体案例复盘。
P1 · 半年内补齐全链路交付与 AI 应用前端3 – 6 个月
  • 全栈 / BFF（按 TS 优先顺序）：Next.js App Router + Server Actions 或 Hono / NestJS；PostgreSQL + Drizzle / Prisma；Zod 契约 + tRPC 端到端类型推理（内部系统）或 OpenAPI 生成类型化客户端（对外 API）；认证与会话（JWT / OAuth / HttpOnly Cookie）、缓存、幂等、限流、结构化日志；Docker + CI/CD + 部署与回滚。关键不是"会写接口"，而是能独立完成"数据库设计 → 接口 → 页面 → 上线"的一条需求。
  • AI 应用前端：用 Vercel AI SDK 走通 SSE 流式输出、message.parts 工具调用状态渲染、Generative UI 受控组件目录；理解 AI State / UI State 双轨与消息持久化回放；处理断流重连、取消、占位降级、错误态；了解 AG-UI（事件流）、A2UI（声明式 UI）、MCP Apps（第三方 UI 沙箱）的分工与选型。
  • BFF 作为安全边界：隐藏 LLM API Key、集中鉴权与权限校验、输入脱敏、AI 输出净化（DOMPurify 类）、按副作用严重度对工具调用分级审批。这既是安全实践，也是 JD 里高频出现的职责。
  • 可观测与评测：前端监控（白屏、脚本错误、API 失败、长任务）；AI 侧 tracing 与 Token / 成本审计；用固定评测集做离线回归门禁。
锚点项目 A · 生产级 AI 知识库问答工作台：文档上传 → 切块与 Embedding → 混合检索（向量 + BM25，检索前做权限过滤）→ LLM 流式回答带引用高亮 → 人机协同审核节点 → tracing 与评测集 → 部署上线。要求有架构文档、失败 case 复盘、成本与延迟数据。这个项目同时覆盖 P0 与 P1 的绝大多数能力点，比"再做一个聊天页面"高一个量级。
P2 · 1–2 年形成架构判断力与不可替代的纵深6 – 24 个月
  • 架构与取舍：设计系统与组件治理、微前端 / Module Federation 的适用边界与代价、渲染策略选型（CSR / SSR / SSG / ISR / PPR / 岛屿）、多端一致性与渐进迁移、技术债与成本建模。核心训练是"能写出为什么不这样"的文档，而不是画出更多框。
  • Agent 编排纵深：Function Calling / Tool 暴露三种模式（进程内 / CLI / MCP）、分层记忆、RAG 作为持续数据管道、LangGraph 状态机、多 Agent 的引入条件（单 Agent 稳定且任务边界清晰之后再上）、Prompt 版本化与评测。
  • 按需选择的差异化纵深：① 可视化 / 3D / WebGPU / Wasm（数据密集型、工业、电商）；② 端侧推理（金融、医疗等隐私敏感场景）；③ 跨端与鸿蒙 ArkTS / RN 新架构（移动端与车机行业）；④ 平台工程 / DX / 低代码平台建设（大厂中台与 ToB）；⑤ 一个垂直行业（金融、医疗、跨境 SaaS、工业软件）的业务建模能力。
  • 影响力外化：开源贡献、技术文章、内部工具沉淀、可公开的架构复盘。在简历同质化（80% 是"学了框架做了电商网站"）与初级岗 127:1 的筛选环境下，可验证的公开产出比证书与培训经历有效得多。
锚点项目 B · 团队级 AI 研发效能平台：把 AGENTS.md 规则、Skill 库、AI 生成代码审查门禁、评测与成本看板整合为内部平台，并用"需求交付周期 / 缺陷逃逸率 / 人均产出"前后对比量化收益。锚点项目 C · 复杂体验专项：一个高性能可视化或跨端项目，附 RUM P75 数据、长任务拆解记录与低端设备实测。

4.4 明确不建议的方向（及理由）

不建议理由与替代方案
放弃 TS 栈从零转 Java / Rust 后端学习曲线陡、与既有资产协同弱，且目标是"全链路交付"而非"换一门语言"。先用 Node / Hono / Next.js 打通链路，仅在遇到明确的性能或团队栈约束时再考虑 Go 旁路。Go 的价值在于国内后端基建，不在于替代 TS。
横向追第三个 / 第四个 UI 框架State of JS 2025 显示框架格局异常稳定（React 83.6%），框架知识已非护城河。Svelte / Solid / Vue Vapor 值得理解其编译期与 Signals 思路，但不必作为求职主技能投入。
只学 Prompt 技巧、跳过工程基础Stack Overflow 2026 显示 AI 在设计、沟通、重要决策上可信度低；生产级 AI 系统的瓶颈是状态一致性、权限、评测、可观测与成本，不是提示词措辞。
把 FDE 当作前端转型目标见 1.3 节纠错。FDE 是客户现场部署工程，核心是业务与模型落地，不是 frontend 技术栈的直接延伸。
以证书、培训班、Demo 数量作为能力证明当前筛选环境下，简历同质化是初级岗机会枯竭的直接原因。可核验的公开项目、架构文档、性能数据与失败复盘，区分度显著更高。
因"前端已死"叙事而彻底转行BLS 预测软件开发者 2025–2035 仍 +10%；岗位结构变化是职能升级而非职业消失。现有栈的迁移成本远低于彻底转行，且 AI 应用前端恰好放大了前端背景的优势。

5.2 需要明确标注的不确定性

  • 国内招聘数据口径不可直接核验：−62%、−52%、+12.2%、127:1、85% 替代率等数字广泛流传但多来自媒体转述，原始报告的样本量、统计周期与岗位分类定义未公开。本报告已按统计对象拆分，仍建议将其理解为"方向一致、幅度存疑"。
  • 组织变革信息为三级来源：美团 / 京东 / 蚂蚁 / 得物的前后端合并报道多出自技术自媒体，缺乏公司正式公告。JD 层面的变化（BFF 进 JD、岗位改名）证据强度更高，应以此为准。
  • AI 领域协议与版本迭代极快：AG-UI、A2UI、MCP Apps、Vercel AI SDK 的版本与能力在数月内可能变化，采用前须以官方文档复核。
  • 本研究的时间截点为 2026-11-24：Q4 后续发布、年末招聘数据与政策变化未纳入。
  • 判断可能出错的地方：若 AI 编码 Agent 在 2027 年显著攻克长上下文架构推理与线上问题定位，第 Ⅱ 象限（工程深度型）的稀缺度会下降得比预期快；反之若企业因人才断层重启校招与培养体系，初级岗收缩可能部分回补。建议每 6 个月用同样的指标复核一次，而不是把本报告当作一次性结论。
关于"数据打架"的方法论提醒
当同一时期出现"岗位 +12.2%"与"岗位 −52%"时，正确做法不是选一个相信，而是追问统计对象：是"前端相关岗位"还是"普通前端开发岗"？是同比还是对比两年前？是否含外包与灵活用工？是否含 AI 融合岗？本报告的 K 型结论之所以稳健，恰恰因为它在所有口径下都成立——无论总量增或减，初级收缩与高端扩张都同时被观测到。

5.3 30 天行动清单

第 1 周 · 建立基线

① 用当前项目的下一个真实需求，完整走一遍 AI 辅助开发，并记录：任务如何拆解、AI 出错在哪、你如何发现、验证用了什么手段。② 检查项目实际解析的 React / Next / Vite / TypeScript 版本（npm ls），核对 RSC 相关 CVE 修复状态与所有 preview 部署。③ 接入 web-vitals，拿到 LCP / INP / CLS 的 P75。

第 2 周 · 固化规范

① 写仓库级 AGENTS.md：项目结构、技术约束、禁止模式、验证命令。② 把 2–3 个高频重复任务沉淀为 Skill。③ 起草团队 AI 使用规范（可外发的代码/数据边界、生成代码评审与来源要求）。④ 清理 tsconfig 中 TS 7 已移除的配置项。

第 3 周 · 打通链路

① 用 Next.js App Router 或 Hono + Zod + tRPC 做一个最小全栈模块（数据库 → 接口 → 页面 → 部署）。② 用 Vercel AI SDK 跑通一次 SSE 流式输出与工具调用状态渲染。③ 把 BFF 作为密钥与鉴权边界落进去。

第 4 周 · 选定纵深

① 依据所在行业，从可视化 / 端侧推理 / 跨端鸿蒙 / 平台工程 / 垂直业务中只选一个作为 6–12 个月的主纵深。② 写出锚点项目 A 的架构文档与验收标准。③ 把前 3 周的产出整理成可公开的项目与复盘，作为作品集第一版。

FINAL TAKEAWAY

2026 年前端就业的核心矛盾，不是"人 vs AI"，而是"标准化实现"与"非标准化判断"之间的价值重估。对 TS / React / Vite 工程师，最理性的策略是保留既有栈、拒绝赛道切换，用 3–6 个月补齐全链路交付与 AI 应用前端，用 1–2 年建立架构判断力与一个垂直纵深。先成为能审查 AI、并为结果负责的人，再谈其他方向。
