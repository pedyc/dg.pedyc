# AGENTS.md

本文件是这个知识库的 **agent 约定总入口**：任何 agent（Claude Code、Codex、Cursor、WorkBuddy……）在本目录工作时都以它为准。约定只有这一份，别处只放指针。

## 零、读文件的顺序

1. **先读当前目录及其最近祖先的 `AGENTS.md`**。若某个目录下有它自己的，那份优先于本文件——就近优先，冲突时子级覆盖根级，不冲突则叠加。
2. **不要凭印象写规范**。定义、枚举、字段、命名规则都在 `01-META/Truth/`，按下表路由，不要 rglob 全扫。
3. 动手前扫一眼第一节（禁令）与第三节（写作约定）；涉及命令、编码、配置、发布的动作，再看 `Guide/本库踩坑手册` 里对应的那一节。

## 一、一定不能做

> 本库不设 pre-commit 钩子与额外校验链：笔记库的判据是「最常用的即最重要的」，改坏了你会看见，加链条只是增加维护成本。
> 这八条针对的恰恰不是那些——而是**改坏了不会当场显形**的部分：删掉一篇冷门笔记、污染一段对话存档、把字段写成数组让视图空白、多留一份定义让副本悄悄过期。它们没有「察觉」这个出口，所以只能靠纪律。

1. **不删内容，只移动**。笔记与你的原话是唯一不可再生的东西；同卷 rename 成本为零（`pathlib.replace()` / `robocopy /MOVE`）。覆盖已有文件前先看 `git status`。
2. **不碰只读区**：`99-ASSETS/copilot/`（对话存档）、`.claude/`（配置与示例）、`01-META/Log/`（流水日志）、`40-ARCHIVE`（免维护区）、规范文档里的反例示例。改这里等于篡改历史。
3. **不凭印象写字段**。`content-type` / `up` / `uid` / 链接写法这四样，写错的后果统一是「视图空白、不报错」。一律去 `Truth/` 查。
4. **不把派生值写进 frontmatter**。一旦落库，不一致是必然的，而且不会显形。
5. **不恢复已废除的字段**（`status`、`related`），不手写 `uid`，不用 12 位。
6. **不用别名建链接**。别名的存在性靠人记、文件名的存在性由文件系统保证；而断链只在点击那一刻暴露。
7. **批量改写必须逐项列出要排除的目录**，不能只写「排除归档区」一类——漏一处就是无声篡改。
8. **不新增第二真值源**。Specification / Guide 只引用、不复制定义。同一份规则出现两处，其中一处迟早过期，且没人会发现。

## 三、输出与写作约定

- **正文排版（一切输出都适用）**：中文不用斜体；加粗只留给真正的判断，「标签：内容」式加粗降为纯文本（全篇 20 处加粗等于没有）；引号用「」且内外不留空格；不写 LaTeX 箭头，直接 →；中英混排括号用全角。
- **写或改 atomic 前，先读 `Truth/笔记类型规范`「atomic 的正文结构」**。要点：观点 + 边界 + 至多一个论据；判据是「这句在支撑观点，还是在给观点划范围」。`## 论据/示例` 下出现 `### 论据`，就是该瘦身的信号。
- **写作习惯**：10-PROJECTS 项目制，相关文件全丢 `P-XXX/`，结束再消化归档。
- **`.base` 用独立文件**，不写 md 内联代码块：能图形调视图、能被 `![[x.base]]` 嵌入；内联块在笔记被嵌入时不渲染，且不报错。

## 四、动手前后

- **改完必跑**：`python _scripts/validate_meta.py --all`（字段脏值）；动了链接或 `up` 再跑 `--links`。
- **覆盖已存在文件前先看 `git status`**（用户可能同时在 Obsidian 里改）。
- **只在被要求的范围内动手**：顺手发现的问题先说出来，不要自己扩大范围（P0 变 P0+P1 就是范围蔓延）。
- **补 `up` 前先跑 `check_targets.py`**：凭印象写的父级名很可能不存在，不校验就是用一个新断链换掉一个空字段。
- **任何清单里的篇数都会过期**（包括本文件里的），动手前先重扫。
- **记事**：工作记录走本项目的记忆目录（WorkBuddy 为 `.workbuddy/memory/YYYY-MM-DD.md`，append-only）；跨 agent 通用的约定才进本文件，一次性数字与过程叙事不进。
