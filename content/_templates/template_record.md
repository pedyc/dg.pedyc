<!--
	记录笔记 (Record) 设计原则：

	1. 定义：record 是**外部事实的落地页**——一次发生、一篇读过的东西、一个持续消费的源，
	   凡「不是我原创、有客观事实基础、有边界」的，都用它。
	   与 atomic / concept 的分界不是题材，是归属：record 承载「发生过什么」，
	   atomic 承载「我怎么判断」，concept 承载「它怎么运作」。

	2. 三种形态共用本模板，按形态取用中段，用不上的标题删掉、不要留空：

	   事件  → 时间线 / 背景 / 影响          例：俄乌冲突、项目里程碑
	   素材  → 核心命题 / 关键论点 / 摘录    例：一篇论文、一期播客、一本书
	   信源  → 不套本模板，用 template_source.md

	   信源卡是 record 的独立子类型，走自己的模板与五维评分。

	3. **「来源」与「产出」是本模板的两个挂载位，比正文更重要。**
	   它们不是装饰，是信源产出率的数据链：
	    - 「来源」段向上挂信源卡 → 该源多一条素材
	    - 「产出」段向下挂知识资产 → 该源多几条 ingest
	   统计脚本只数这两段，口径见 [[信源质量审计标准]]。
	   缺了这两段，笔记就只是一份孤立存档。

	4. `up` 指向**知识归属**（这个概念属于哪个主题），不是信源。
	   信源走「来源」段。两者混用会让 `up` 的语义失效，也会把知识网络与出处网络搅在一起。

	字段说明：
	- url：原文链接（素材形态必填，事件形态可空）
	- date：这件事发生的日期——事件的发生日、素材的发布日
	- location / participants：仅事件形态填
	- aliases 的 R- 前缀是本类型的命名约定，见 [[文件名与别名规范]]

	本模板真值来源：[[笔记类型规范]]、[[元数据规范]]
