## 二、面板之外的证据

> 面板已列出本周新增的笔记清单（按 `date-created` 归周）。**这里不复述它列过的东西**——抄一遍清单不是复盘；而且哪天某篇改名或被推翻，周记就成了第二个真值源，必然与面板打架。
>
> 本段只写三类面板给不了的：**它不统计的工作**（工程、配置、决策落地）· **它数字准不准** · **阻碍**。

- **📐 面板数字是否可信**：（正常写「可信」；失准则写明原因与真实值，例如字段被批量重置）
- **🎯 面板之外的产出**：
- **⚠️ 阻碍**：（从「一、上周目标核对」里**没留痕迹**的那几条推——「想做 A、实际做了 B」，差值就是阻碍，不必等日记里有人记过）

> 阻碍若是**两条以上同型**，就是系统问题（改 SOP 或调小目标粒度），不是「这周太忙」。

## 三、强制收敛：产出一件可复用件

- [ ] 一条 `atomic`：______（必须能写出边界）
- [ ] 一次 SOP 修订：______
- [ ] 一个项目状态变更（`10-PROJECTS/`）：______
- [ ] 一条旧 atomic 的边界修正：______

> 一件都产不出，就写「本周空转」。空转是有效记录，不要编。

## 四、下周 Top 3

| # | 目标（可验收的结果，不是方向） | 类型 | 落点（`- [ ]` 写到哪个文件） |
|:---:|:---|:---|:---|
| 1 |  | 推进 |  |
| 2 |  | 推进 |  |
| 3 |  | 维持 | —（节律，不落 checkbox） |

> **落点三选一**：① `10-PROJECTS/` 有终点的事 → 在该 project 加 `- [ ]`；② `20-AREAS/` 持续负责的事（维护系统、积累能力）→ 在该 area 加 `- [ ]`；③ 维持型节律 → 不落，只留在本表。
> 三条都指认不出落点，说明它不是目标而是愿望，重写。
>
> **为什么必须落**：`任务总览` 的两组查询就是抽 `- [ ]`。写进周记只是三行字；写进 checkbox 才会在打开项目时看见、勾掉时有反馈。**周记是决定，checkbox 是执行。**
>
> **落锚点**：每天早上从这 3 条里切一块，写进当天日记的「🔭 明日聚焦」。不做这步，下周的核对就没有对照物。
